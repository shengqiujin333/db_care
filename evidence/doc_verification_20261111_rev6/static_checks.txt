B1. D-31 docs/04 §4.3 “关闭守护则停止读取与上传” 与实现不符
文档：docs/04_安卓App安装与使用.md:178
“守护按钮启动后 App 每 **180 s** 读取一次网关；关闭守护则停止读取与上传。”

源码事实：
- MqtttService.kt:259 READ_INTERVAL_MS = SensorCadence.SAMPLE_PERIOD_MS（180000 ms）
- MqtttService.kt:383-405 startBluetoothTask(): while (isActive) { onTimeout(READ_INTERVAL_MS) ...;
  uploadRepository.triggerUpload(); connectToBluetoothDevice() } —— 该循环不读取守护状态。
- MqtttService.kt:372-376 只要 macAddr 非空（且不以 "1010" 开头）即启动上述循环。
- 守护状态仅门控：
  * 入库/上传：MqtttService.kt:1170-1185（startData 值传给 storeTemperatureReading，非 1 时
    TemperatureDatabaseHelper.kt:214-221 直接返回 -1，且不入队）
  * 报警：MqtttService.kt:1205 if (homeViewModel.startData.value == 1)
  * 关闭守护的按钮动作：HomeFragment.kt:168-173 只发送 START_STOP_GUARD 并写 measure_state，
    不停止 MqtttService，也不停止 BLE 循环。
结论：关闭守护后，BLE 读取轮询仍每 180 s 执行（只是不写库、不报警、不上传）。
文档“停止读取”不成立；参数/行为说明需修正或由 Android 实现改为真正停止读取。
产品归属：Android 实现（P-11）。

B2. D-32 用户手册 §6.3 “剩余倒计时”恢复与实现不符
文档：dengbei_care/用户使用说明书.md:163
“应用被杀进程重启后,会自动恢复到之前的守护状态(启动/停止)和剩余倒计时。”

源码事实：
- HomeFragment.kt:59 restoreGuardState() 在首页创建时调用。
- HomeFragment.kt:121-147 measure_state=="stopping" 时读取 finish_guard_time，
  HomeFragment.kt:137:
  val minutesDifference = calculateMinutesDifference(timed, timec) * 3600000L
- HomeFragment.kt:230-236 calculateMinutesDifference 返回 diff / (60 * 1000)，单位是分钟。
- HomeFragment.kt:238-245 startCountDown(timeInMillis) 直接使用该值。
换算：剩余 N 分钟 → N × 3,600,000 ms = N 小时（多 60 倍）。例如剩余 120 分钟会按 120 小时倒计时，
到时自动停止不会在预期剩余时间发生。
结论：守护状态恢复成立，但“剩余倒计时”不成立。文档需按当前缺陷披露，或由 Android 实现修复后
（应为 × 60_000L）再声明。产品归属：Android 实现（P-09）。

B3. D-33 用户手册 §8 “震动最长 5 分钟”与实现不符
文档：dengbei_care/用户使用说明书.md:223
“1. **手机震动**(最长 5 分钟,可循环)”

源码事实：
- MqtttService.kt:1132 / :1212 调用 VibrationPlayer.vibratePhone(this, 300 * 1000, true)
- VibrationPlayer.kt:38-44 API 26+ 分支：pattern longArrayOf(0, 500, 1000)，repeatIndex=0（无限循环）；
  该分支未使用 duration 参数。
- VibrationPlayer.kt:45-50 API <26 且 repeat=true 分支同样使用无限循环 pattern，未使用 duration。
- stopVibration 只在 BaseActivity.kt:15-22 的 onTouchEvent 中调用；没有 5 分钟的定时停止路径。
结论：当前支持版本（minSdk 26）上震动会持续循环，直到用户触屏/进程结束；“最长 5 分钟”不成立。
文档需改为实际行为或由 Android 实现增加时限。产品归属：Android 实现（P-10）。

B4. D-34 用户手册 §7.1 “报警间隔”字段未参与本地报警节流
文档：dengbei_care/用户使用说明书.md:177 “**报警间隔**（秒）”；
同一手册 :216 “普通报警(下降/超限)有 15 分钟节流:15 分钟内只触发一次报警”。

源码事实：
- MqtttService.kt:176 DeviceParams.delayAlarm；:197 从 delayalarm 读取并赋默认 "8"；
  :244 _delayAlarm；:326-327 读入并打印日志。
- 之后未再使用 _delayAlarm：报警判定 AlarmEvaluator.Parameters（MqtttService.kt:1101-1110）不含该字段；
  普通报警节流 MqtttService.kt:1208 固定 (900 * 1000) ms。
- delayalarm 仅出现在 PUBLISH_DATA 负载字符串（MqtttService.kt:1290-1292），未参与 App 本地节流。
结论：用户在「设定」页填写的“报警间隔”不会改变当前 App 的 15 分钟固定节流。手册把它列为可设置参数
但未说明实际作用，读者会误以为可改变报警间隔。文档需注明“当前版本仅保存/随配置发布，实际节流固定
15 分钟”，或由 Android 实现接入该值。产品归属：Android 实现（P-08）。
