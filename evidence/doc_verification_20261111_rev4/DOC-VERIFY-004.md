## 4. 文档缺陷（本轮新发现，需技术文档修正）

### D-19（高）用户手册安装对象错误：指向 1.0 历史包

- 位置：`dengbei_care/用户使用说明书.md:23`
- 原文：“直接安装 `爱守护.apk` 即可。”
- 实测：`dengbei_care/爱守护.apk` 为 **versionCode 1 / versionName 1.0**（8,144,628 B，文件时间 2024-11-06）；本次候选是 `dengbei_care/app/build/outputs/apk/debug/app-debug.apk`（versionCode 10 / 1.9，10,365,460 B，SHA-256 `d2054221…`）。
- 影响：用户按手册安装会得到旧版 1.0，缺少本轮 BLE/网关身份/上传分类/规则文案等全部 Android 改动；且未说明 debug 候选仅内部测试。
- 修正建议：改为当前候选路径与身份（versionCode 10 / versionName 1.9 / SHA-256），并注明 `爱守护.apk` 为历史包、不得作为 1.9 安装源；补充“debug 候选不用于对外分发”。

### D-20（中）用户手册把 BLE 连接对象写成“温湿度传感器”

- 位置：`dengbei_care/用户使用说明书.md:29`
- 原文：“附近设备/蓝牙权限(必须):连接 BLE 温湿度传感器”。
- 实现：手机 BLE 连接的是**中继器（网关 CH592）**（`gateway_ble_addr` / `GATEWAY_CONNECT`）；传感器与网关之间是 433 MHz，传感器不与手机建立 BLE 链路（01 §1、04 §4.2）。
- 影响：现场人员可能去搜索/配对传感器，而实际应发现并保存网关 BLE 地址。
- 修正建议：改为“连接中继器（网关）的 BLE GATT；传感器数据先经 433 MHz 到网关”，并与 04 §4.2 用语统一。

### D-21（中）用户手册默认报警参数与首次安装实际值不符

- 位置：`dengbei_care/用户使用说明书.md:172`
- 原文：“点「取消」恢复默认值(温度下降 1°C、湿度下降 4%、温度 29-35°C、湿度 40-70%、守护 8 小时、延时 5 秒…)；**这些是「默认值」，所有新设备会自动使用这套参数**。”
- 实现：
  - 首次安装写入 `MyPrefs`（`MainActivity.kt:139-166`）：`tempdrop=2`、`humdrop=0.1`、`tempmax=35`、`tempmin=29`、`hummax=75`、`hummin=40`、`guardtime=8`、`delayalarm=10`。
  - 真机「设定」页当前值（`ui_after_report_click_rev4.xml`）：`2 / 0.1 / 35 / 29 / 75 / 40`。
  - 「取消」按钮只是把输入框填成 `1 / 4 / 35 / 29 / 70 / 40 / 8 / 5`（`DashboardFragment.kt:90-104`），不落盘；与首次安装默认值不同。
- 影响：用户按手册预期 1/4/70/5，实际得到 2/0.1/75/10，报警阈值与行为不同。
- 修正建议：分别写清“首次安装生效值”和“取消按钮填充值”，或在产品侧统一两组值；文档必须给出真机可核对的实际值。产品侧统一问题另见 P-07。

### D-22（高）用户手册的“该设备参数”入口不存在

- 位置：`dengbei_care/用户使用说明书.md:133`、`:177`
- 原文：“点击任意卡片…右上角有「该设备参数」菜单”；“在首页点开某个设备卡片进入详情页,点右上角「该设备参数」菜单”。
- 实现：`DeviceDetailFragment.kt:58-80` 只设置 toolbar 标题与返回监听，没有菜单；`res/menu` 仅有 `bottom_nav_menu.xml`；详情页布局无 `app:menu`。每设备参数的真实入口是**「设定」页顶部「选择设备」下拉**（`DashboardFragment.kt:120-162`，含“全局默认值(所有设备)”与各设备项），编辑后点「确定」保存。
- 影响：用户按手册在详情页找不到入口，无法完成每设备参数设置。
- 修正建议：删除“该设备参数菜单”，改为“设定 → 选择设备 → 选择目标设备 → 修改参数 → 确定”；§5.1 的详情页描述只保留实际存在的条目（曲线、时间范围、报警记录）。

### D-23（高）用户手册的报告时间修改命令会破坏 SharedPreferences

- 位置：`dengbei_care/用户使用说明书.md:239-243`
- 原文：`adb shell run-as com.jinyuni.dengbei_care sh -c "echo 'report_time=08:00' >> shared_prefs/MyPrefs.xml"`
- 事实：SharedPreferences XML 需要 `<string name="report_time">08:00</string>` 元素；直接追加 `report_time=08:00` 文本会写出非法 XML，应用下次加载可能解析失败或丢失设置。当前应用只有读取逻辑（`MainActivity.kt:75`），没有 `report_time` 的 UI 入口。
- 影响：按手册操作可能损坏 `MyPrefs`，影响守护/报警参数等本地设置。
- 修正建议：删除该追加命令；明确“当前版本无受支持的报告时间修改入口”。若确需提供运维方法，应给出“先停止应用、备份 XML、重写合法元素、重启核对”的完整步骤，并标注风险。

### D-24（中）用户手册把未验证的服务端幂等写成事实

- 位置：`dengbei_care/用户使用说明书.md:304`
- 原文：“重复上传由服务端 (设备 ID, 时间) 唯一键与本地待发箱双重去重，**不会产生重复记录**。”
- 事实：服务端 `(dev_id,time)` 唯一键与 `INSERT IGNORE` 仅来自部署资料声明；05 §5 D4 与 06 #7 明确“本轮未验证真实写入与幂等”，且无写授权、未连数据库。
- 影响：用户/验收方会把未验证的服务端行为当成已保证，掩盖重复上传风险。
- 修正建议：改为“本地待发箱按 (devId,time) 去重；服务端唯一键为部署资料声明，尚未验证，不能承诺不产生重复记录”，与 04 §5、05 §5 保持一致。

### D-25（中）时间字段语义在包内冲突且均不准确

- 位置：`docs/01_产品说明与版本变更.md:75` 与 `dengbei_care/用户使用说明书.md:295`
- 原文：01 写“App 的 `time` 字段是 **BLE/MQTT 接收秒**，不是传感器物理采样时刻”；用户手册写“写入时间是该读数的**真实采样时间**”。
- 实现：BLE 路径使用手机接收时刻（`MqtttService.kt:978-999`）；MQTT 路径使用 payload 首段网关时间（`UploadPayload.kt:27`；`MqtttService.kt:1669-1677`）。两者都不等同于传感器物理采样时刻。
- 影响：对“最近上报时间”、下降报警时间窗、云端时间字段的解读都会偏差。
- 修正建议：docs/01 与用户手册统一为“BLE=手机接收时刻；MQTT=网关 payload 时间；均非传感器物理采样时刻”，删除“接收秒/真实采样时间”的绝对表述。

### D-26（中）用户手册未披露交付固件“无光”分支不触发

- 位置：`dengbei_care/用户使用说明书.md:134`、`:265`（以及 Q2 相关段落）
- 原文：把“温度较上次升高超过 0.9℃ **且无光**”写成当前可生效规则，未注明限制。
- 事实：交付固件 `LIGHT_DARK_THRESHOLD_CODE=0`，`S` 行 `V=0 D=0`，升温+无光分支不触发；板上只有严格 `>35.0℃` 分支可用。`FW-LIGHT-DEF2-ENABLE` 已人工确认 **NOT EXECUTED**（docs/06 §4）。
- 影响：用户会等待一个当前固件不可能触发的上报分支。
- 修正建议：在用户手册相关段落加显著限制说明，并引用 docs/01 §3 / docs/06 §3 #1；可同时建议产品 UI 规则文案补充同一限制。

### D-27（低）界面文字引用不精确

- 位置：`dengbei_care/用户使用说明书.md:125`、`:143`；`docs/04_安卓App安装与使用.md:179`
- 原文：“最近上报 12 分钟前…可能长时间无上报”；“「启动守护」”；“只显示'最近上报时间'”。
- 实际：卡片文案为“最近读取 … · 按条件上报，可能长时间无数据”（`DeviceCardAdapter.kt:74`）；首页按钮初始为“启动”、运行后为“停止”（`HomeFragment.kt:127-189`，`strings.xml:80`）。
- 影响：用户按文字找不到按钮/卡片字段；属可读性与可操作性缺陷。
- 修正建议：按实际文案改写，或不依赖精确按钮/卡片文字进行步骤描述。
