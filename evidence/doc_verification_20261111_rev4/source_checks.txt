D-19（高）用户使用说明书 §2.1 安装对象错误
  文档（dengbei_care/用户使用说明书.md:23）：“直接安装 `爱守护.apk` 即可。”
  事实：仓库内 dengbei_care/爱守护.apk 为 versionCode=1 / versionName=1.0（2024-11-06，8144628 B），
        不是本次交付的 1.9 候选；当前候选为
        dengbei_care/app/build/outputs/apk/debug/app-debug.apk（versionCode 10/1.9，
        SHA-256 d2054221…，10365460 B）。
  影响：按用户手册安装会得到旧版 1.0，缺少本轮全部 Android 改动。
  修正：改为当前候选路径与身份，并注明 debug 候选仅内部测试；明确 爱守护.apk 为历史包、不得作为 1.9 安装源。

D-20（中）用户使用说明书 §2.2 BLE 连接对象错误
  文档（:29）：“附近设备/蓝牙权限(必须):连接 BLE 温湿度传感器”。
  事实：手机 BLE 连接对象是网关（CH592，GATEWAY BLE 地址/`gateway_ble_addr`），
        传感器与网关之间是 433 MHz；传感器不与手机建立 BLE 链路。
  修正：改为“连接中继器（网关）的 BLE GATT；传感器数据经 433 MHz 先到网关”。

D-21（中）用户使用说明书 §7.1 默认参数数值错误
  文档（:172）：“取消恢复默认值(温度下降 1°C、湿度下降 4%、温度 29-35°C、湿度 40-70%、
        守护 8 小时、延时 5 秒…)；这些是「默认值」，所有新设备会自动使用这套参数。”
  事实：首次安装实际写入 MyPrefs（MainActivity.kt:139-166）：
        tempdrop=2、humdrop=0.1、tempmax=35、tempmin=29、hummax=75、hummin=40、
        guardtime=8、delayalarm=10；
        真机“设定”页当前值（ui_after_report_click_rev4.xml）为 2 / 0.1 / 35 / 29 / 75 / 40。
        “取消”按钮只是把输入框填为 1 / 4 / 35 / 29 / 70 / 40 / 8 / 5（DashboardFragment.kt:90-104），
        不落盘；与首次安装默认值不同。
  修正：分别写清“首次安装生效值”和“取消按钮填充值”；或统一两组值并同步实现，
        在文档中给出真机可核对的实际值。

D-22（高）用户使用说明书 §5.1/§7.2 每设备参数入口不存在
  文档（:133、:177）：“点击任意卡片…右上角有「该设备参数」菜单”；“点右上角「该设备参数」菜单”。
  事实：DeviceDetailFragment.kt:58-80 只设置 toolbar 标题与返回监听，无菜单；
        res/menu 仅有 bottom_nav_menu.xml；详情页布局无 app:menu。
        每设备参数实际入口是「设定」页顶部「选择设备」下拉（DashboardFragment.kt:120-162，
        含“全局默认值(所有设备)”与各设备项），编辑后点「确定」保存。
  修正：删除“该设备参数菜单”表述，改为“设定 → 选择设备 → 选择目标设备 → 修改参数 → 确定”。

D-23（高）用户使用说明书 §9.1 adb 修改报告时间命令会破坏 SharedPreferences
  文档（:241-243）：`adb shell run-as com.jinyuni.dengbei_care \
    sh -c "echo 'report_time=08:00' >> shared_prefs/MyPrefs.xml"`
  事实：SharedPreferences XML 需要形如 `<string name="report_time">08:00</string>` 的元素；
        直接追加 `report_time=08:00` 文本会写出非法 XML，应用下次加载可能解析失败/设置丢失。
        当前应用也没有 `report_time` 的 UI 入口（MainActivity.kt:75 读取）。
  修正：不要提供该追加命令；若确需支持，应给出“停应用、备份、重写合法 XML、重启”的完整安全步骤，
        或明确说明当前无受支持修改方式。

D-24（中）用户使用说明书 §11.2 服务端幂等被写成已验证事实
  文档（:304）：“重复上传由服务端 (设备 ID, 时间) 唯一键与本地待发箱双重去重，不会产生重复记录”。
  事实：服务端 `(dev_id,time)` 唯一键与 `INSERT IGNORE` 仅来自部署资料声明；
        docs/05 §5 D4 与本轮授权均未执行真实写入/幂等验证（无写授权、未连库）。
  修正：改为“本地待发箱按 (devId,time) 去重；服务端唯一键为部署资料声明，尚未验证，
        不能承诺不产生重复记录”，与 docs/04 §5、05 §5 保持一致。

D-25（中）时间字段语义在包内不一致
  文档：docs/01:75 “App 的 time 字段是 BLE/MQTT 接收秒，不是传感器物理采样时刻”；
        用户使用说明书:295 “写入时间是该读数的真实采样时间”。
  事实：BLE 路径用手机接收时刻（MqtttService.kt:978-999）；
        MQTT 路径用 payload 首段网关时间（UploadPayload.kt:27；MqtttService.kt:1669-1677）；
        两者都不等同于传感器物理采样时刻。
  修正：docs/01 与用户使用说明书统一为“BLE=接收时刻、MQTT=网关 payload 时间；
        均非传感器物理采样时刻”，删除“真实采样时间”表述。

D-26（中）用户使用说明书未披露交付固件“无光”分支禁用
  文档：:134、:265 将“温度较上次升高超过 0.9℃ 且无光”写成当前可生效规则，未注明限制。
  事实：交付固件 LIGHT_DARK_THRESHOLD_CODE=0，`V`/`D` 恒 0，升温+无光分支不触发；
        板上只有严格 >35.0℃ 分支可用（docs/01 §3、docs/06 #1、FW-LIGHT-DEF2-ENABLE SKIP_CONFIRMED）。
  修正：在用户手册相关段落加“当前交付固件无光判据未启用，升温+无光分支不触发，
        仅 >35.0℃ 可用”的显著说明，并链接 docs/01 §3 / docs/06 §3 #1。

D-27（低）界面文字引用不精确
  文档：用户使用说明书:125 “最近上报 12 分钟前…可能长时间无上报”；:143 “「启动守护」”；
