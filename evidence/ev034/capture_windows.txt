Interpretation of the 0-byte windows:
- The resets are real: the later cadence restarts (e.g. k=0 after the 03:10:40 reset,
  then k=3/6/9/12), and pyocd reports DP/core discovery + reset Done.
- The MCP serial_capture receive path was not ready when the reset happened in
  windows 2/3/4/6, so the one-shot boot lines were missed.  The port-first script
  (pyserial open confirmed, then HW reset 2 s later) captured the complete boot
  sequence.  This is a capture-orchestration result, not a firmware defect.
- Windows 5/7/8/9 show that periodic S rows are received normally by the MCP tool.
- No `G` and no `P` rows appeared in any window.
- k=0,3,6,9,12 are consecutive sampling opportunities (k difference 3).
- liveness after reset: k=0 at 03:10:41, k=3/6/9/12 in the following windows,
  k=15 by the bit-level I2C capture, k=18 in window 9.
- Wall-clock tick spacing is about 57 s per minute tick (k wall-clock interval
  about 171 s); readme gives no LSI tolerance, so no 180.0 s precision is claimed.
