## 4. 本轮新发现的文档缺陷

### D-35（中）“关闭守护后全部停止”的边界与实现不符

- 位置：
  - `docs/04_安卓App安装与使用.md:178`：“关闭守护只停止入库、报警与云端上传。”
  - `docs/04:179`：“不会新增本地记录、不报警、不上传。”
  - `docs/04:191`：“守护关闭 或 未注册手机号 | **不入队、不上传**（数据只在本机 SQLite）”
  - `docs/06_维护排障与已知限制.md:94`（#21）：“守护只门控入库/报警/上传”
  - `dengbei_care/用户使用说明书.md:314`：“守护关闭或本机未注册手机号时，**不上传**（也不入待发箱）”
- 实际（源码静态）：
  - 温度读数入库确受门控：`MqtttService.kt:1170-1183`、`TemperatureDatabaseHelper.kt:221`。
  - `/upload_data` 确受门控：`CloudUploadRepository.kt:117、129-132、153-154`。
  - 下降/超限（普通）报警的震动/铃声/通知受门控：`MqtttService.kt:1204-1223`。
  - **仍继续执行**：
    1. >65 ℃ 紧急报警的震动/铃声/通知：`MqtttService.kt:1129-1139`（位于守护门控 `:1205` 之前）；
    2. 报警事件写入 `alarm_events`：`MqtttService.kt:1148-1166` → `TemperatureDatabaseHelper.kt:246-267`（无守护门控）；
    3. 卡片报警/读数 UI 更新：`MqtttService.kt:1141-1146、1194-1200`；
    4. BLE 批次 MQTT 转发：`MqtttService.kt:1019` → `:1030-1049`，仅受 `shouldPublishBle()`（平台身份非空且非 `1010`，`:1022-1024`）与连接状态约束，不读守护状态。
- 影响：用户/运维会误以为关闭守护后手机不再向平台发送任何数据、不再产生任何本地记录或提醒；实际 >65 ℃ 仍会震动/响铃/通知、`alarm_events` 仍增行、MQTT 转发仍可能发送。
- 修正建议（文档侧，任选其一）：
  1. 将上述句子限定为“停止**温度读数入库**、`/upload_data` 上传与**下降/超限**报警的震动/铃声/通知”；并明确“BLE 读取、MQTT 批次转发、>65 ℃ 紧急提醒与报警事件记录仍继续”。
  2. 若产品意图是“关闭守护后一律不上传/不报警”，则由 Android 实现补齐门控后再声明；文档在修复前不得写成已全部停止。
- 产品归属：P-12（见 §5）。

### D-36（低—中）用户手册未披露关闭守护后 BLE 读取仍继续（跨文档不一致）

- 位置：`dengbei_care/用户使用说明书.md:158-160`（§6.2 停止）仅写“点停止/到时自动停止”，全文未说明 BLE 读取继续；而 `docs/04:178-179`、`docs/06:94` 已披露 P-11。
- 实际：同 D-31（`MqtttService.kt:383-405`）。
- 影响：用户关闭守护后若看到“最近读取”继续更新，会误判守护未停止或设备异常；同一文档包对同一版本的行为描述不一致。
- 修正建议：在用户手册 §6.2 补充：“关闭守护只停止温度读数入库、下降/超限报警与 `/upload_data` 上传；手机仍每 180 s 读取网关，‘最近读取’时间可能更新。”并在 §5 卡片说明处交叉引用。

### D-37（低—中）紧急（>65 ℃）报警忽略“震动/响铃”开关，文档未披露

- 位置：
  - 用户手册 `:175`：“报警方式：`震动`、`响铃`”；
  - 用户手册 `:240`：“是否在‘设定’页关闭了震动/响铃（关闭后只通知不响铃）”；
  - `docs/04:208`：“报警方式可配震动/响铃”。
- 实际：`MqtttService.kt:1117-1125` 仅对 DROP/THRESHOLD 设置 `vibrationAlarmFlag/voiceAlarmFlag`；`:1129-1133` 紧急报警直接 `VibrationPlayer.vibratePhone` + `RingtonePlayer.startAlarm`，不检查两项开关。
- 影响：用户按手册关闭震动/响铃后，>65 ℃ 紧急报警仍会震动并响铃；排障清单第 3 项的结论不成立。
- 修正建议：明确“紧急（>65 ℃）报警始终震动+响铃，不受‘报警方式’开关影响”；或由 Android 实现接入开关后再维持原表述。产品归属：P-13。

### D-38（低）“设备是否在线请看最近读取”与时间语义冲突

- 位置：用户手册 `:134`：“设备是否在线请看‘最近读取’以及网关/蓝牙连接状态。”
- 对照：`docs/01:75` 与 `docs/04:181`：“最近读取不是传感器物理采样时刻……不得据此推断采样精度或设备离线。”
- 事实：最近读取是手机从网关读取的时刻；网关缓存复读时，传感器离线也可能继续更新（`docs/01:76`）。
- 影响：用户可能把“最近读取在走”当作传感器在线证据，与包内时间语义相矛盾。
- 修正建议：改为“最近读取只表示手机最近一次成功读取网关的时刻，不能证明传感器在线或离线；请结合网关供电/蓝牙链路状态判断”。
