## 4. 签发规范与命令（供受权执行者使用）

模板：`evidence/e2e_p0/emqx_8883_san.cnf`（已本地演练，见 §9）

- `subject`：`C=US, ST=State, L=City, O=Organization, OU=Organizational Unit, CN=8.140.23.253`（CN 仅沿用既有证书风格，**判据是 SAN**）
- `SAN`：`IP:8.140.23.253`（必须）+ `IP:117.72.84.210`（保留旧地址条目，仅用于资料兼容与回退比较，不作连接目标）
- 扩展：`basicConstraints=CA:FALSE`、`keyUsage=critical,digitalSignature,keyEncipherment`、`extendedKeyUsage=serverAuth`
- 私钥：新建 RSA 2048/3072 或沿用服务器上现有的叶子私钥（后者可减少分发面）；私钥权限 `600`、属主与现有部署一致
- 有效期：`-days 730`（到期日必须早于 CA `notAfter=2034-10-10`）

```bash
# 1) 生成新私钥与 CSR（服务器受控目录，勿落仓库）
openssl req -new -newkey rsa:2048 -nodes \
  -keyout emqx_8883.key -out emqx_8883.csr \
  -config emqx_8883_san.cnf

# 2) 由 App 信任的 CA 签发（CA 私钥仅在本命令期间于服务器本地可见）
openssl x509 -req -in emqx_8883.csr \
  -CA jd-ca.crt -CAkey tiktok_root_ca.key -CAcreateserial \
  -days 730 -sha256 \
  -extfile emqx_8883_san.cnf -extensions v3_server \
  -out emqx_8883.pem

# 3) 签发后即时自检（任一不满足即停止，不部署）
openssl x509 -in emqx_8883.pem -noout -subject -issuer -serial -fingerprint -sha256 -dates \
  -ext subjectAltName,extendedKeyUsage
openssl verify -CAfile jd-ca.crt -verify_ip 8.140.23.253 emqx_8883.pem      # 期望 OK
openssl verify -CAfile jd-ca.crt -verify_ip 8.140.23.254 emqx_8883.pem      # 期望失败（反例，可选）
```

签发记录需包含：新证书 serial、SHA-256 指纹、`notBefore/notAfter`、SAN 原文、签发时间、执行者、CA 文件指纹（`jd-ca.crt` 仍为 `75:33:09:B3:…:15:2B`，若变化说明信任锚被动过，必须停止）。

**回退步骤**：

1. 恢复变更前的证书/私钥文件（备份副本），配置文件如被修改则一并恢复。
2. 按同一方式重载 listener。
