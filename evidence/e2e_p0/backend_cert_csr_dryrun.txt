## 8) 复验命令判别力核对：-verify_hostname 会回退 CN，必须用 -verify_ip 判 IP SAN
时间(UTC): 2026-11-24T05:48:08Z
ca_exit=0
csr_exit=0
sign_exit=0

构造：CN=other.example，SAN=IP:8.140.23.253（故意让 CN 与目标地址不一致）
subject=CN = other.example
X509v3 Subject Alternative Name: 
    IP Address:8.140.23.253

a) openssl verify -verify_hostname 8.140.23.253（只比对 DNS/CN，不判 IP SAN）
CN = other.example error 62 at 0 depth lookup: hostname mismatch error .tmp_cert_dryrun3/l.pem: verification failed 
b) openssl verify -verify_ip 8.140.23.253（严格比对 IP SAN）
.tmp_cert_dryrun3/l.pem: OK 
c) openssl verify -verify_ip 8.140.23.254（反例，应失败）
CN = other.example error 64 at 0 depth lookup: IP address mismatch error .tmp_cert_dryrun3/l.pem: verification failed 

对照上一步 §7：新证书 CN=8.140.23.253 时 -verify_hostname 8.140.23.253 返回 OK，但该 OK 可由 CN 命中产生，不能证明 IP SAN 正确。
因此服务器侧与复验判据必须同时满足：SAN 含 IP:8.140.23.253（文本核对）+ openssl verify -verify_ip 8.140.23.253 返回 OK。
说明：Android/Conscrypt 对 IP 形式主机按 IP SAN 校验（CN 不参与该分支），故 SAN 是本缺陷的实质修复点。
