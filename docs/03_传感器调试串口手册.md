# 03 传感器调试串口手册（UART1）

适用版本：传感器固件 FD-002 rev 8（发布包 `fw_sensor_FD-002r8.zip`）
文档包：DOC-PKG-001 rev 13（2026-11-13）
依据：`USER/inc/debug_trace.h`、`USER/src/debug_trace.c`、`USER/inc/sensor_config.h`、`evidence/test.md`（EV-040/EV-038 原始捕获；EV-036 历史样本 `evidence/ev036/`）

> 本手册只描述当前固件**实际实现**的串口行为。串口输出是观测手段，不是产品功能；串口"看起来正常"不等于上报链路或整机功能通过。

---

## 1. 用途与前提

- 用途：观察上电自检、采样是否成功、光照 ADC 原始值、判定与发送结果，用于现场排障与测试取证。
- 前提：固件为**目标编译器构建**（`SENSOR_DEBUG_UART` 在 ARM 目标下默认 =1）；宿主机 harness 构建默认关闭串口，不输出任何字节。
- 串口是只读观测通道：打印不改变判定、前值、冻结快照或发送结果。

---

## 2. 电气连接与参数

| 项 | 值 |
|---|---|
| MCU 外设 | UART1（轮询发送，不使用 UART 中断） |
| 引脚 | PA06 = UART1_TXD → J3.1；PA05 = UART1_RXD → J3.2；J3.3 = GND |
| 参数 | **9600 bps，8 数据位，无校验，1 停止位（8N1）** |
| 时钟 | PCLK = 8 MHz（HSI DIV6） |
| 主机端口（本机） | `COM43`（Prolific `067B:2303`） |
| 非本用途端口 | `COM26` 是调试器 CDC 串口，**不是**传感器调试串口 |

接线要点：

1. 传感器的 **TXD（PA06，J3.1）接 USB-TTL 的 RXD**；传感器的 RXD（J3.2）可不接（本固件不解析上位机命令）。
2. USB-TTL 的 GND 必须与 J3.3 共地。
3. 使用 3.3 V 电平的 USB-TTL；不要向目标板回灌电源。

---

## 3. 输出节律与行长

| 时机 | 输出 |
|---|---|
| 上电/复位 | 依次 `BOOT` → `VDD` → `IOTEST` → `IOSIG` → `BUS`，各一次 |
| 每次采样（每 3 分钟） | 一条 `S` 行 |
| 采样失败（`q=0`） | `S` 行之后紧跟一条 `G` 行 |
| 本周期产生上报判定或发生过发送尝试 | `S`/`G` 之后追加一条 `P` 行 |
| 采样间期 | **无任何字节输出**（UART1 在打印完成后关闭以省电） |

- 每行 ≤ 96 字节（含 `\r\n`）：按最坏字段宽度核算并由实现/宿主测试保证，不输出超长行或半行。
- 时间基准：`k` 为 RTC 累计分钟节拍；每 3 拍采样一次，因此正常连续采样时 `k` 递增 **3**。
- 固件未给出 LSI 容差，因此**不能**用 `k` 精确反推 180.0 s 精度。

---

## 4. 上电五行字段

真实样本（EV-036，2026-11-11，复位后同窗口采集）：

```
BOOT fw=FD-002r4 uid=6A002C00 rst=0040 uart=9600
VDD ok=1 code=1480 bgrmv=1189 mv=3289
IOTEST sda_lo=0 scl_lo=0 idle=3 swap=none gc=0
IOSIG scl=95555 sda=30300
BUS idle=3 scl=1 sda=1 ack=44
```

| 行 | 字段 | 含义 |
|---|---|---|
| `BOOT` | `fw` | 字节冻结的固件横幅（`FD-002r4`），**不代表版本号** |
| | `uid` | 芯片 UID 前 4 字节（同板稳定，可用于识别板件） |
| | `rst` | 复位来源寄存器值（按芯片手册解读；EV-036 样本为 `0040`） |
| | `uart` | 串口波特率（9600） |
| `VDD` | `ok` | 1=测量有效；0=超时/无效（此时 `mv=0`，不得当作真实电压） |
| | `code` | 内部 1.2 V 基准通道 ADC 原始码 |
| | `bgrmv` | 出厂修调的内部基准电压（mV） |
| | `mv` | 反推的供电电压，恒满足 `mv = 4095 × bgrmv ÷ code`（整数除法） |
| `IOTEST` | `sda_lo` / `scl_lo` | 主机主动拉低该线后回读的电平（0=拉低成功） |
| | `idle` | 释放两线后的电平位掩码（bit0=SCL，bit1=SDA，1=高） |
| | `swap` | 引脚角色对调后收到 ACK 的候选地址（`none`=无；用于识别板级接反） |
| | `gc` | 上电一次性 general-call 复位尝试结果：`0`=未尝试（0x44/0x45 已应答）、`1`=0x00 收到 ACK 但 0x06 未 ACK、`2`=0x06 已被接受（复位命令生效）、`3`=0x00 也不应答（器件对任何 I²C 地址均无响应） |
| `IOSIG` | `scl` / `sda` | 一次地址字节事务（START+8 位+ACK）逐半位回读签名（20 bit，5 位大写 hex） |
| `BUS` | `idle` / `scl` / `sda` | 上电总线诊断的空闲电平与展开位 |
| | `ack` | 0x08..0x77 地址扫描中收到 ACK 的 7 bit 地址集合（最多 8 个，超出以 `+` 结尾；无应答为 `none`） |

判读要点：

- `BUS ack=44` 表示 GXHT40 在 `0x44` 上应答，与随后 `S` 行 `q=1` 自洽。
- `IOSIG` 的 `scl`/`sda` 是**软件逐半位回读**，只说明逻辑电平，不构成模拟电气/时序结论。
- `VDD` 是供电轨测量；EV-035/EV-036 期间读数为 3287–3289 mV。

---

## 5. `S` 行字段（每 3 分钟一条）

格式（字段顺序冻结，单字符键名以守住 ≤96 B 预算）：

```
S k=<tick> p=<prev> H=<have> V=<lvalid> o=<ok> n=<min> x=<max> a=<mean> D=<dark> t=<temp> h=<hum> q=<sample_ok> r=<report> s=<send> y=<retry>
```

真实样本（EV-036 首样本）：`S k=0 p=0 H=0 V=0 o=8 n=2856 x=2864 a=2860 D=0 t=273 h=349 q=1 r=0 s=0 y=0`

| 字段 | 取值 | 含义 |
|---|---|---|
| `k` | 无符号整数 | RTC 累计分钟节拍；正常连续采样步长 3 |
| `p` | 有符号，0.1 ℃ | **判定所用**的前一有效温度（无前值时为 0） |
| `H` | 0/1 | 是否存在前一有效样本 |
| `V` | 0/1 | 光照分类依据是否有效（`valid = adc_ok && 阈值已启用`；交付默认恒 0） |
| `o` | 0..8 | 成功转换的 ADC 样本数 |
| `n` / `x` | 0..4095 | 成功样本的最小/最大 ADC 码 |
| `a` | 0..4095 | 成功样本算术均值（`o=0` 时为 0，**不得**当作暗态） |
| `D` | 0/1 | 无光判定结果（LIGHT-DEF-2：`V && a >= T`；交付默认恒 0） |
| `t` | 有符号，0.1 ℃ | 本周期温度；采样失败周期为最近有效值（由 `q=0` 区分） |
| `h` | 0..1000，0.1 %RH | 本周期湿度；同上 |
| `q` | 0/1 | 本周期温湿度采样是否有效 |
| `r` | 0/1 | 本周期条件上报判定结果 |
| `s` | 0/1/2 | 433 发送结果：0=未发送，1=成功，2=失败 |
| `y` | 0..3 | 待上报重试计数 |

### 5.1 判读矩阵

| `q` | `r` | `s` | 含义 |
|---|---|---|---|
| 1 | 0 | 0 | 采样成功、未达上报条件（最常见） |
| 1 | 1 | 1 | 采样成功、满足条件且 433 发送成功 |
| 1 | 1 | 2 | 满足条件但发送失败；后续周期继续重试（`y` 递增） |
| 0 | 0 | 0 | 采样失败；不推进前值、不上报；随后应有 `G` 行 |
| 任意 | 1 | — | 必有 `P` 行（冻结快照） |

### 5.2 交付默认状态（`LIGHT_DARK_THRESHOLD_CODE = 0`）

- 所有周期 `V=0`、`D=0`；`a` 仅作**事实记录**，不据此判断"有光"或光路好坏。
- 升温+无光分支**不会触发**；`r=1` 只可能来自严格 `t > 350`（35.0 ℃ 以上）。
- 因此看到长期 `r=0` 是默认判据未启用的正常表现，不能据此判定"光路故障"或"判定失效"。

## 6. `G` 行（采样失败诊断）

格式：

```
G s=<1..5> a44=<0|1> a45=<0|1> rd=<0..5> at=<1..3> raw=<12 位大写 hex 或 12 个 '-'>
```

| 字段 | 含义 |
|---|---|
| `s` | 驱动结果码：1=入参错误，2=无器件，3=读失败，4=CRC 错，5=量程无效 |
| `a44` / `a45` | 本轮 `0x44` / `0x45` 是否收到地址 ACK |
| `rd` | 最近一次读事务消耗的失败重读次数（0..5） |
| `at` | 本轮整帧重测次数（1..3） |
| `raw` | 最近一次成功读回的 6 字节（12 位 hex；未成功则 12 个 `-`） |

用途：区分"器件不在线（`a44=a45=0`）"、"读失败"、"CRC 错"与"量程无效"；`raw` 可用独立 CRC-8（poly `0x31`、init `0xFF`）复算。`G` 行不改变业务状态。

---

## 7. `P` 行（待上报冻结快照观测）

格式：

```
P rq=<0|1> s=<0|1|2> y=<0..3> t=<frozen x10> h=<frozen x10>
```

| 字段 | 含义 |
|---|---|
| `rq` | 打印时"仍待上报"标志（1=本轮未结束） |
| `s` | 打印时发送状态（0/1/2，同上） |
| `y` | 重试计数 |
| `t` / `h` | **组帧实际使用**的冻结温度/湿度（0.1 ℃ / 0.1 %RH） |

注意：首次发送失败时 `rq=1 s=2` 只表示本轮未结束，不代表最终失败；同一次唤醒内的后续重试不会再打印 `P`。最终是否成功以 `report_req` 清除与后续周期行为判断，手机侧实收属跨链路联调范围。

## 8. 采集操作步骤

1. 接线（§2），确认 USB-TTL 枚举为 `COM43`；关闭其它占用该端口的程序（PulseView/USBee 等会独占设备）。
2. 以 **9600 8N1** 打开串口，先开始采集。
3. **在串口已打开后**再触发复位：
   - 方式 A：调试器 HW reset（如 `pyocd reset -t cortex_m -M attach -m hw`，需本机已安装且探针可用）；
   - 方式 B：整板断电再上电（CR2032 焊接，实际为断开外部供电/复位引脚操作，按现场条件执行）。
4. 同一窗口内应取得五行上电行与首条 `S k=0`；此后持续采集 ≥3 个采样机会（约 ≥10 分钟）以覆盖节律。
5. 保存**原始字节**（不要只保存截图/文本转录），记录：时间、端口、波特率、复位方式、探针序列号、固件包 md5。

**顺序很重要（实测）**：先复位再打开串口，会错过一次性上电输出（EV-034 记录 4 个窗口 0 字节，但 `k` 从 0 重新计数证明复位已生效）。这是采集编排问题，不是固件缺陷。

**已知编排限制**：`pyocd` 可用但未登记在项目环境入口清单中；若当前权限或工具不允许在采集期间复位，按项目要求记录"上电日志未执行及原因"，不得为取得日志反复修改固件。

## 9. 常见问题与处理

| 现象 | 排查 |
|---|---|
| 完全无输出 | 端口是否 `COM43`；波特率是否 9600 8N1；TXD/RXD 是否交叉；GND 是否共地；端口是否被其它程序占用 |
| 有乱码 | 波特率/校验位不符；USB-TTL 电平不匹配 |
| 只有上电五行、无 `S` | 正常：采样间期静默，需等待 ≥3 分钟；或采集窗口过短 |
| `k` 不按 3 递增 | 中间有复位/断电，或窗口跨越了未采集区间；按实际 `k` 记录，不推断 |
| `VDD ok=0` | 转换超时/无效；`mv=0` 不代表 0 V，需重新测量供电并记录 |
| `BUS ack=none` | 器件未应答：检查 GXHT40 焊接/供电；随后 `S q=0` 与 `G a44=0 a45=0` 可交叉验证 |
| 出现 `G s=4` 且 `raw[2]` 等于温度 MSB | 已知历史失败形态；保留原始行交固件角色分析，不放宽 CRC 或伪造数据 |
| 串口偶尔漏行 | 9600 下每行约 100 ms；确认采集工具未做超时截断；以原始字节核对 |

## 10. 限制

1. 串口为**目标固件调试通道**，不是产品数据接口；不解析上位机命令。
2. 每次打印后关闭 UART1（省电），因此不可能连续流式输出。
3. `IOSIG` 与位级 I²C 采集只证明逻辑电平与采样分辨率内的时序，不证明模拟幅度/上升沿/上拉质量。
4. 交付固件判据未启用（`T=0`），`V`/`D` 恒 0；**不具备**在板上验证"无光判定"的能力。
5. 本文档中的样本值来自同板同构建的一次捕获，不构成长期稳定性或电池寿命结论。
