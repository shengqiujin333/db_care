## 1. 例行维护

| 周期 | 检查项 | 方法与判据 |
|---|---|---|
| 每次交付/升级 | 固件身份 | 解压发布包核对 axf/hex md5；下载日志 `Verify OK`；上电 `BOOT` 行与首条 `S` 行原文 |
| 每次交付/升级 | App 身份 | `dumpsys package com.jinyuni.dengbei_care` 的 versionCode/versionName；APK SHA-256 |
| 每周（现场） | 传感器采样健康 | COM43 采 ≥3 个周期：`q=1` 占比、是否出现 `G`、`k` 步长是否为 3、行长 ≤96 B |
| 每周（现场） | 供电趋势 | `VDD ... mv=`（`mv = 4095*bgrmv/code`）；明显低于 ~2.7 V 时按硬件维护流程处理（CR2032 焊接在板上，不能直接换电池） |
| 每日/每轮守护 | App 待发与阻塞 | 「我的 → 网关与上传设置」中的待发条数、HTTP 状态、是否"被拒绝" |
| 每周 | 平台可用性 | EMQX/HTTP 端口可达、`user_script` 运行、无异常重启；只做只读检查 |
| 变更前 | 回退准备 | 确认上一固件包与上一 APK 可用；服务器变更需备份与维护窗口 |

维护记录至少包含：时间、设备/板件标识（`uid`）、版本（源码提交 + 产物摘要）、操作人、原始关键行、结论（"已观测"≠"已通过"）。

## 2. 排障路径（按现象）

### 2.1 手机端无数据

```text
1) App 守护是否启动？            → 未启动则先启动（首页按钮显示“停止”为运行中）
2) 网关 BLE 地址是否已保存？      → 「我的 → 网关与上传设置」；停留在“默认未确认”时先搜索并保存
3) 蓝牙/权限/定位是否满足？       → 按首页链路状态文本跳转系统设置
4) App 日志是否有链路状态？       → logcat 关键字：GATEWAY_UNSET / READ_INCOMPLETE / MTU / NO_DEVICE
5) 网关是否在线、绑定是否 ≤9 台？ → 仅核对数量；当前构建无 UI 查看/删除路径（§3 #20），超限时不要反复尝试，按 #20 登记并等 Android 修复；确认网关供电与蓝牙可发现
   （清除应用数据会删除全部本机绑定与未上传记录，仅在确认可丢弃时由运维执行，不是常规排障步骤）
6) 仍无数据 → 转 2.2（传感器侧）
```

### 2.2 传感器侧怀疑异常

```text
1) COM43/9600 8N1 采集，复位后应见五行 + S k=0     → 无输出见 03 文档 §9
2) S 行 q=1 且 k 步长 3？                          → q=0 见紧随 G 行的 s/a44/a45/rd/at/raw
3) VDD mv 是否正常？                              → ok=0 或明显偏低先查供电
4) 长期 r=0 且无 P 行                              → 默认 T=0 的正常表现，不是故障（见 §3 限制 1）
5) 出现 P 行但 App 无对应数据                       → 433/网关/App 链路，按 05 联调前提处理
```

### 2.3 上传异常

| 状态 | 处理 |
|---|---|
| 待发条数持续增长、显示"重试中" | 网络/服务端 5xx 或 **408/429**（超时/限流）：在 **20 次**自动重试上限内按退避重试（退避上限 30 分钟），无需手动干预；**累计 20 次失败后该行停止自动重试但数据保留**，网络恢复也不会自行补传，必须手动「重试上传」恢复 |
| 显示"被拒绝（HTTP 401/403）" | 全局暂停；保留数据。属平台鉴权/受理条件问题，按 05 文档 D1 交平台侧；不要改客户端鉴权或伪造成功 |
| 显示"请求被拒绝（HTTP 4xx）"（除 401/403/408/429） | 核对请求体字段/单位/时间；保留原始响应 |
| 上传 2xx 但平台查不到 | 2xx 仅表示受理；按 05 文档 D4/D5 验证持久化与回读 |

### 2.4 固件升级失败

按 02 文档 §7 表处理；连续失败两次后停止重试并保留日志（`Erase/Program/Verify` 原文、调试器序列号、供电实测值）。

### 2.5 「查看今日报告」点不开

当前布局下该按钮位于底部导航之下，点击会被导航拦截并切到「设定」（O-PKG-2，见 §3 #18）。报告内容仍可通过**早报通知**打开；盘点/验收时不要把“按钮可见”当作可点击。

## 6. 文档与缺陷反馈

1. **文档缺陷**（步骤、命令、路径、字段错误）：在本包内修正并提升文档版本号；修正后需重新按步骤核对关键操作。
2. **产品缺陷**（实现与需求不符、实板可复现异常）：保留原始证据（串口字节、日志、APK/固件摘要），反馈对应实现角色；不得通过改写手册降低要求。
3. **未执行项**：写明缺项、所需条件与责任方，不写成通过，也不据此判定其它能力无法完成。
4. 本文档包不声称独立验证；独立校核与总测按当前文档复核安装/操作关键步骤。
