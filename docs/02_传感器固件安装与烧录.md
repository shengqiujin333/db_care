# 02 传感器固件安装与烧录

适用对象：传感器板（CW32L010 + GXHT40 + 光敏分压 + UM2005C 433 发射）
适用版本：FD-002 rev 8 发布包 `fw_release/fw_sensor_FD-002r8.zip`
文档包：DOC-PKG-001 rev 10（2026-11-11）
依据：`artifacts/firmware_release.md`（FW-REL-001 rev 2，包字节未变）、`fw_release/PACKAGE.txt`、`evidence/test.md`（EV-038/EV-037/EV-036）、`CW32L010_StandardPeripheralLib_V1.0.5/Examples/sensor/gpio_input_output/MDK/Project.uvprojx`

> 本文档描述**真实可执行的安装步骤**。发布包是构建候选：`Verify OK` 只证明写入内容回读一致，不证明功能合格。烧录本身不属发布角色的职责，执行者需具备本项目的烧录授权与设备入口。

## 1. 前置条件

| 项 | 要求 | 说明 |
|---|---|---|
| 硬件 | 传感器板（CR2032 已焊接供电）；CW-DAPLink 调试器；USB 线 | 电池不可拆换，整板断电即视为断电 |
| 软件 | Keil MDK（含 ARMCLANG V6.24）；工程 `MDK/Project.uvprojx` 保存的 Device/调试器/Flash 算法 | 不得另选芯片、调试器或算法 |
| 串口 | 3.3 V/5 V USB-TTL（Prolific `067B:2303` 已在本机枚举为 `COM43`）；杜邦线接 J3 | 9600 8N1 |
| 权限 | 具备烧录入口（`mdk_flash`）与调试器复位入口（如 `pyocd`） | 缺少时按 §7 记录，不得用其它通道替代或猜测 |
| 产物 | `fw_release/fw_sensor_FD-002r8.zip`（134,791 B，md5 `5df0c6d45ecddc8aae8bddbbcfc9cfdf`） | 从项目仓库取得，不要使用散落的旧 `MDK/output` 产物 |

## 2. 步骤 1：校验发布包

1. 计算包摘要并与声明比较：

   ```
   md5sum fw_release/fw_sensor_FD-002r8.zip
   # 期望：5df0c6d45ecddc8aae8bddbbcfc9cfdf
   ```

2. 解压并核对三个成员与 `PACKAGE.txt` 内的 MD5：

   | 成员 | 大小 | MD5 |
   |---|---|---|
   | `fw_sensor_FD-002r8_b6a15fed.axf` | 297,380 B | `b6a15fed2ed5e3d0c4adc51ac87a4830` |
   | `fw_sensor_FD-002r8_4d728dec.hex` | 75,275 B | `4d728dec9b0d28a352c46436b7586c72` |
   | `PACKAGE.txt` | 3,202 B | `a58f67fcf5b760767ff5b65888c73dfb` |

3. 预期结果：zip CRC 校验无坏成员；三成员 MD5 与上表一致（可复跑 `evidence/fw_release_20261111/verify_release_package.py`）。
   若不一致：**停止烧录**，重新取得发布包；不要用摘要不符的文件烧录。

---

## 3. 步骤 2：连接并确认烧录链路

1. 将 CW-DAPLink 接到传感器板的 SWD（PA07/PA08）与 GND，插入 USB。
2. 确认调试器被主机识别（设备管理器或工具枚举中可见 CW-DAPLINK，历史序列号 `87094109484987710672FF50`）。
3. 确认目标板供电正常：`VDD` 由 CR2032 提供，EV-036/EV-038 期间实测约 3.28–3.29 V；若 `VDD ok=1` 但明显低于约 2.7 V，先确认供电（`artifacts/firmware_implementation.md` 的 VDD 判读表将 `mv≈2700–3100` 视为新鲜 CR2032 范围）后再烧录，并记录实测值。
4. 不做 433 天线以外的硬件改动；不改动网关。

失败处理：调试器不识别 → 更换 USB 口/线缆并重试一次；仍不识别则如实记录"烧录未执行"，不要通过改工程配置绕过。

## 4. 步骤 3（可选）：用同一工程复现构建

用于确认"包内二进制可由当前源码复现"。

1. 在工程目录（`.../sensor/gpio_input_output/MDK`）执行 `mdk_build {"action":"rebuild"}`，或在 Keil 中 `Project → Rebuild all target files`。
2. 预期结果：
   - `0 Error / 1 Warning`（warning 为既有 `main.c(254) while(k--);` 空循环体，非本次引入）；
   - `Code=25964 RO-data=656 RW-data=116 ZI-data=1676`；
   - 产物 md5 与 §2 表中 axf/hex 一致。
3. `gcc/build.sh`（FLASH 34840 B / RAM 1816 B）只作交叉编译辅助验证，**不得**用于烧录。

若摘要不一致：先检查是否改动了 `USER/`、`MDK/`、`EWARM/`（`git diff` 应为空，产品源提交 `82a7e74`），不要通过改工程参数"凑"摘要。

## 5. 步骤 4：下载

**方式 A（推荐，工程保存配置）**

```
mdk_flash {}
```

该入口按工程保存的 Device/调试器/Flash 算法编译并下载。

**方式 B（Keil GUI）**

1. 打开 `MDK/Project.uvprojx`；
2. `Project → Rebuild all target files`；
3. `Flash → Download`（或 `Debug → Start/Stop Debug Session` 后 `Download`）；
4. 退出调试会话，让程序运行。

**预期可观察结果（必要条件）**

下载日志必须包含：

```
Erase Done.
Programming Done.
Verify OK.
Application running ...
```

- `Verify OK` 只表示写入内容回读校验一致，**不表示功能通过**。
- 下载后 `MDK/output/exe/Project.axf` 的 md5 应仍为 `b6a15fed…`（下载不改变产物）。
- 若日志出现 `Erase fail`、`Program fail`、`Verify fail`、`RDDI`/`Cannot access target`：按 §7 表处理，不要连续反复重烧同一镜像。

---

## 6. 步骤 5：下载后核对（必做的最小观测）

1. 打开 `COM43`，参数 **9600 / 8 数据位 / 无校验 / 1 停止位**（详见 `docs/03_传感器调试串口手册.md`）。
2. 触发一次复位（调试器 HW reset 或整板断电重上电），在**同一采集窗口**内应依次收到：

   ```
   BOOT fw=FD-002r4 uid=6A002C00 rst=0040 uart=9600
   VDD ok=1 code=<..> bgrmv=<..> mv=<..>
   IOTEST sda_lo=0 scl_lo=0 idle=3 swap=none gc=0
   IOSIG scl=<5 位 hex> sda=<5 位 hex>
   BUS idle=3 scl=1 sda=1 ack=44
   S k=0 p=0 H=0 V=0 o=8 n=<..> x=<..> a=<..> D=0 t=<..> h=<..> q=1 r=0 s=0 y=0
   ```

3. 之后每 3 分钟出现一条 `S` 行；交付默认（`T=0`）下每行应为 `V=0 D=0`、`q=1`；采样间期不应有其它字节。
4. 记录：下载时间、调试器序列号、包 md5、`Verify OK`、`BOOT` 行原文与首条 `S` 行原文。

未取得上述日志时，只能记录"下载完成但未取得运行时观测"，不得写成功能通过。

## 7. 故障处理

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 调试器未枚举 | USB 线/口、驱动、调试器损坏 | 换线换口重试一次；仍失败则记录，不更换工程配置 |
| `Cannot access target` / 连接失败 | 板未供电（CR2032 耗尽）、SWD 接线、目标被低功耗占用 | 检查电池电压与 SWD 接线，复位后重试一次 |
| `Verify fail` | 镜像与包不一致、Flash 算法不匹配、供电跌落 | 核对 §2 摘要；确认工程 Flash 算法未被改动；测量供电 |
| 上电无任何串口字节 | 串口未接 J3、TX/RX 接反、端口被占用、波特率不符 | 按 03 文档 §2/§7 排查；确认不是 `COM26`（调试器 CDC） |
| 只有 `BOOT` 无 `VDD`/`BUS` | 程序在早期异常、供电不足 | 记录完整原始字节，交固件角色分析，不反复重烧 |
| `q=0` 伴随 `G` 行 | GXHT40 通信/CRC 失败（真实故障路径） | 保留原始 `G` 行（含 `raw`）与 `S` 行，交固件角色；不修改判据或伪造数据 |
| 有 `P` 行但手机无数据 | 433 发送/网关/App 链路（后续联调范围） | 按 05 文档联调前提处理，不在固件侧改判定 |

## 8. 升级与回退

- **无 OTA/Bootloader**：本产品升级=替换镜像后重新烧录；包内不含空中升级路径。
- **升级**：按 §2→§6 执行，烧录新包并核对其 md5 与 `BOOT` 行；旧包保留在 `fw_release/` 之外由发布方归档（发布目录只保留当前包，避免混用）。
- **回退**：用上一发布包（同工程、同调试器、同 Flash 算法）重新烧录，并重做 §6 观测；不得通过改工程 Device/算法或擦除保留区"回退"。
- **禁止**：烧录既有网关（CH592 `beiwov2`）；修改 `Project.uvprojx` 的 Device/调试器/Flash 算法；用 `gcc/build.sh` 产物烧录。

## 9. 已知限制（安装相关）

1. 交付固件 `LIGHT_DARK_THRESHOLD_CODE=0`：升温+无光上报分支不生效，仅严格 >35.0 ℃ 可用（见 01 文档 §3）。
2. 工程 Device 为 `CW32L010F8`，BOM U7 标注 `CW32L010Y8M6`；两者差异已记录，未擅自修改工程或网表。
3. `BOOT fw=FD-002r4` 是字节冻结的既有横幅，**不代表版本号**；版本以源码提交与产物摘要为准。
4. `pyocd` 可用于 HW reset，但未登记在项目环境的设备入口清单中；只按项目当前授权与既有安装使用，不自行安装或改配置。
