## 2. 安装、升级、回退

前置：设备在线（Redmi 8A，ADB 序列号 `12f046690506`）；使用项目已登记的 ADB 入口。

### 2.1 全新安装

```
adb -s 12f046690506 install <app-debug.apk>
```

预期：`Success`；桌面出现"爱守护"；`dumpsys package com.jinyuni.dengbei_care` 显示 `versionCode=10 versionName=1.9`。

### 2.2 覆盖升级（保留数据，推荐）

```
adb -s 12f046690506 install -r <app-debug.apk>
```

- 前提：设备上已安装**同签名**（Android Debug）的同包名应用；同版本号 + 同签名允许 `-r`。
- 预期：`Success`；应用数据（SQLite、MyPrefs）保留；`firstInstallTime` 保持、`lastUpdateTime` 更新。
- 升级后应重新核对：`versionCode/versionName`、APK SHA-256、守护状态与网关设置是否保持。

### 2.3 签名不一致

`-r` 会失败（`INSTALL_FAILED_UPDATE_INCOMPATIBLE`）。只能卸载后安装，**会清除应用本地数据**（含未上传的待发记录）：

```
adb -s 12f046690506 uninstall com.jinyuni.dengbei_care
adb -s 12f046690506 install <app-debug.apk>
```

执行前须确认数据可否丢弃并记录。

### 2.4 回退

保留上一构建的 APK，用 `install -r` 覆盖回退（同签名）。应用内不提供回退入口。

### 2.5 安装后核对清单

1. 启动无崩溃（`logcat` 无 `FATAL EXCEPTION` / ANR）。
2. 底部三个页签（首页 / 设定 / 我的）可切换；守护按钮可启动/停止。
3. `run-as com.jinyuni.dengbei_care cat shared_prefs/MyPrefs.xml` 可读（debug 变体）。
4. 记录安装时间、APK SHA-256、设备型号/API。

## 3. 首次启动与权限

1. **隐私政策**：首次启动弹出对话框，必须点「同意并继续」。
2. **通知权限**（API 33+ 会请求）：报警与早起报告依赖它；拒绝则收不到提醒。
3. **蓝牙权限**：API 31+ 需 `BLUETOOTH_CONNECT`；搜索网关还需 `BLUETOOTH_SCAN`。
4. **位置权限**：Android 11 及以下**扫描** BLE 需要；直连已保存网关不需要。API 31+ 扫描不强制定位，但系统可能仍要求定位开关开启。
5. **相机**（可选）：扫码添加设备。

权限被拒后可在 系统设置 → 应用 → 爱守护 → 权限 重新授予；应用内不会反复强制弹窗。

## 4. 绑定设备与网关（关键配置）

### 4.1 登记网关编码与注册传感器（"我的"页）

页面实际可见文字（Redmi 8A / 720×1520，当前候选 `d2054221…`）：顶部`用户：未登录`与「账户」；`请输入网关编码：`输入框、「保存」；`请输入传感器编码和别称：`输入框、「注册传感器」；底部「网关与上传设置」「查看今日报告」「打开传感器列表」。

**步骤 1：登录/注册账号**

点右上「账户」完成注册或登录。未登录时仍可保存网关编码到本机，但会提示 `mac 设置失败，请先登录`，平台不会登记该网关。

**步骤 2：登记网关编码（12 位）**

1. 在「请输入网关编码：」下方的输入框（提示 `请输入网关上的字母串`）填写 **12 位网关编码**（不带分隔符；建议大写十六进制），或点右侧「使用摄像头扫一扫」扫码填入。
2. 点「保存」。
3. 预期结果：
   - 已登录：提示 `mac 设置成功`；本机写入 `MyPrefs.mac_addr`，并调用平台 `POST /setmac`。
   - 未登录或平台失败：提示 `mac 设置失败，请先登录` / `mac 设置失败，请先注册...`，本机值仍保存。
   - 输入长度不是 12：提示 `请输入12个字符`（长度以外不校验字符集）。
4. **注意**：此步骤是“本机保存 + 平台 MAC 登记”，**不写网关的绑定列表**；仓库中 `BLE_ENQUEUE_WRITE_IDS` 只有接收端（`MqtttService.kt`），未发现发送路径，写网关绑定属 Android 实现待确认项（P-03）。

**步骤 3：注册传感器**

1. 在「请输入传感器编码和别称：」下方的两个输入框（提示 `请输入传感器的字母串`、`请输入传感器别称用于显示`）填入：
   - 传感器编码：**8 位十六进制**（`0-9`/`A-F`，不区分大小写，不带分隔符）；
   - 别称：纯中文 ≤3 字，或纯英数（`a-z0-9`）1–8 位；不可中英混合或带符号。
2. 点「注册传感器」。
3. 预期：提示 `添加传感器成功`。
4. 失败提示分三类：
   - 编码长度不等于 8 或别称为空：`请输入传感器编码和别称`；
   - 长度满足但**不是 8 位十六进制**、别称不符合格式，**或该编码已绑定**：`添加传感器失败,请联系客服`（多为输入格式或重复绑定，不是设备故障）。
5. 约束：**最多绑定 9 台**（`GatewayReadGuard.MAX_DEVICES`）；已绑 9 台时提示 `已绑定 9 台设备，超过网关完整传输上限 9 台（请先删除多余设备）`。
6. **已知阻断**：当前构建下删除/查看列表入口不可用（见步骤 4），所以“先删除多余设备”暂时无可用 UI 路径；遇到容量超限时不得假定可自行删除，需按 06 文档限制项处置。

**步骤 4：查看/删除设备（当前不可用）**

- 实测（Redmi 8A / 720×1520 / 当前候选）：`打开传感器列表` 按钮 `[164,1296][456,1392]` **整体**位于底部导航容器 `[0,1264][720,1424]` 之内；点击后被导航拦截并切到「设定」，页面未进入传感器列表。
- 代码中进入 `SensorIdListFragment` 的唯一路径就是该按钮的点击处理（`NotificationsFragment.kt` 的 `opensensorlistbutton`，导航图 `action_notificationsFragment_to_SensorIdListFragment`），因此**当前版本没有可用的 UI 途径查看或删除已绑定传感器**（P-04，待 Android 实现修复）。
- 处理：不要反复点击；不要把“列表未打开”判为设备或绑定失败；需要在列表内核对/删除时，先确认 Android 侧已修复该布局/导航问题。限制项见 `docs/06` §3 #20。

不要使用「网关 BLE 地址」格式（`AA:BB:CC:DD:EE:FF`，17 字符）填写上述 12 位网关编码输入框。

### 4.2 配置网关 BLE 地址与上传状态（1.9 新增）

> 区分两个值：4.1 的 **12 位网关编码**用于本机保存 + 平台 `/setmac`（平台身份 `mac_addr`）；本节配置的 **网关 BLE 地址**（`AA:BB:CC:DD:EE:FF`，17 字符）才是手机实际连接的目标（`gateway_ble_addr`）。两者格式与用途不同，不要互相填错。

入口：「我的」→ 底部「**网关与上传设置**」按钮。

对话框包含：

| 区域 | 内容/操作 |
|---|---|
| 状态 | 当前 BLE 连接目标（`gateway_ble_addr`）与平台身份（`mac_addr`，只读）；使用默认地址时标注"默认网关地址（未确认）" |
| 输入框 | 手动填写 `AA:BB:CC:DD:EE:FF` |
| 搜索附近网关 | 有界扫描（最长 10 秒），候选优先过滤 FFE0；显示名称/MAC/RSSI |
| 扩大搜索（不过滤） | 不做 FFE0 过滤，用于网关广播不含 FFE0 的情况 |
| 清除网关地址 | 清空并写"已清除"标记，**不回退默认值** |
| 保存网关地址 | 校验格式后保存，并通知服务立即触发下一轮读取（不等待 180 s） |
| 上传状态区 | 云端上传状态/HTTP 状态/待发条数/最近被拒时间 |
| 重试上传 | 手动恢复被全局暂停的自动上传 |

操作步骤（发现并绑定网关）：

1. 确认手机蓝牙已开启；Android 11 及以下还需开启定位。
2. 打开「网关与上传设置」→「搜索附近网关」；首次会请求扫描权限，授予后重新点击。
3. 在候选列表中点击目标项，MAC 会填入输入框；核对名称与 RSSI。
4. 点「保存网关地址」，提示"已保存网关地址"。
5. 关闭对话框，回首页启动守护；若干秒内应出现新的链路状态文本；一轮读取成功后卡片出现数值。

预期可观察结果：状态区显示 `BLE 连接目标：<MAC>` 与平台身份；上传状态区显示待发条数（初始通常为 0）。

失败处理：

| 现象 | 处理 |
|---|---|
| 未找到网关 | 重试、点「扩大搜索（不过滤）」；确认网关已上电且在范围内；必要时手动输入 MAC |
| 提示"未授予扫描权限" | 到系统设置授予"附近的设备"或位置权限后重试 |
| 提示地址格式不正确 | 必须是 6 组十六进制 `AA:BB:CC:DD:EE:FF` |
| 保存后仍读不到数据 | 见 §7；确认绑定列表与网关一致（≤9 台） |

> **已知 UI 观察**：
> - **O-PKG-1**：「网关与上传设置」按钮 `[32,1168][688,1264]` 与上方「传感器别称」输入框 `[33,1104][533,1224]`、「注册传感器」按钮 `[452,1128][688,1224]` 在 720×1520 下重叠约 56 px；两控件上部仍可见且可点击，注册路径未失效。
> - **O-PKG-2**：既有「查看今日报告」`[32,1280][688,1376]` 整体位于底部导航 `[0,1264][720,1424]` 之下，点击被导航拦截（会切到「设定」），**当前不可用**；报告内容通过早报通知打开。
> - **P-04**：「打开传感器列表」`[164,1296][456,1392]` 同样被底部导航拦截，**无法查看/删除已绑定传感器**（细节见 §4.1 步骤 4）。
> - 「我的」页**不是可滚动容器**，滑动无效；旋转屏幕的可行性未实测。以上布局/导航缺陷属 Android 实现，本轮未修。

### 4.3 守护与上报语义（易误判点）

- 守护按钮启动后 App 每 **180 s** 读取一次网关；关闭守护则停止读取与上传。
- 传感器每 3 分钟采样，但**只在满足条件时上报**；因此"长时间没有新数据"是正常现象，卡片不再显示"离线"，只显示"最近上报时间"。
- 上报规则（1.9 文案）：温度较上次升高超过 0.9 ℃ 且无光，或温度超过 35.0 ℃。
  **注意**：当前交付固件的"无光"判据未启用（见 01 文档 §3），实际只有 >35.0 ℃ 分支会在板上触发。

## 5. 云端上传行为（运维关注）

| 状态 | 行为 |
|---|---|
| 守护关闭 或 未注册手机号 | **不入队、不上传**（数据只在本机 SQLite） |
| 守护中且已注册 | 经 `POST /upload_data` 上传；断网/失败进入本地待发箱，退避重试；本地待发箱幂等去重（服务端 `(设备ID, 时间)` 唯一键为部署资料声明，本轮未验证） |
| 401 / 403 | 视为鉴权拒绝：保留全部待发数据，**全局暂停自动上传**，状态区显示"云端上传被拒绝（HTTP 401/403）" |
| 408 / 429 | 视为可重试（超时/限流）：在 20 次上限内按退避自动重试，状态区显示"云端上传失败，重试中"，**不会**进入全局暂停 |
| 除 401/403、408/429 外的其他 4xx | 视为请求被拒：全局暂停并保留数据，状态区显示"云端上传请求被拒绝（HTTP 4xx）" |
| 5xx / 网络异常 | 可重试：在 20 次上限内按退避继续，状态显示"重试中" |
| 手动「重试上传」 | 清除暂停，并把已达上限的行重置为可重试后立即触发一次上传；成功后才恢复正常自动上传 |

**重试上限**：单行最多自动重试 **20 次**（`DEFAULT_MAX_ATTEMPTS`），退避上限 **1800 s（30 分钟）**。达到上限后该行保留在待发箱但**停止自动重试**；即使网络恢复也不会自行补传，必须由用户点「重试上传」。因此长时间断网/持续 5xx 后出现“待发不降”时，应先检查是否已达上限。

注意：**2xx 只表示 HTTP 受理，不证明服务端已持久化**；本轮未验证真实写入与回读（见 05 文档）。

## 6. 报警与本地数据（摘要）

- 三类报警：下降报警（与 5/10/15 分钟前样本比较）、超限报警（阈值可全局/每设备设置）、紧急报警（>65 ℃，不节流）。
- 普通报警 15 分钟节流；报警方式可配震动/蜂鸣；任意点击屏幕停止当前报警。
- 本地数据：`temperature`、`alarm_events`、`pending_uploads`（SQLite v3）、`MyPrefs`（参数）、`dev_<id>_*`（每设备参数）。
- 卸载应用会清除本地数据；已上传的云端数据不受影响。
- 详细用户操作见 `dengbei_care/用户使用说明书.md`。

## 7. 常见问题（部署/支持）

| 现象 | 排查与处理 |
|---|---|
| 首页卡片"未收到" | 守护是否启动；蓝牙是否开启；网关编码（平台身份）与网关 BLE 地址（连接目标）是否都已配置；传感器编码是否正确 |
| 卡片长时间无新数据 | 正常：按条件上报。看"最近上报时间"与链路状态；不要按"离线"处理 |
| 链路状态提示网关未配置/权限缺失 | 按状态文本点击跳转（应用设置/蓝牙设置/定位设置）；到「我的」页配置网关 |
| 读取不完整（MTU 不足） | 状态显示 `READ_INCOMPLETE`/MTU 相关提示；靠近网关重试；绑定数 >9 会直接拒绝（当前无可用删除入口，见下行） |
| 无法查看/删除已绑定传感器 | 已知阻断：`打开传感器列表` 被底部导航拦截（P-04），当前无 UI 路径；不要重复点击，等 Android 修复；详见 06 文档 §3 #20 |
| 无法上传且显示 401/403 | 先确认手机号注册状态与网络；问题属平台鉴权，需平台侧确认受理条件，**不要**在客户端加临时鉴权头或改服务器 |
| 注册收不到验证码 | 平台短信通道；确认手机号；联系管理员 |
| 提示 `您登录/退出次数太多，需要重新安装软件` | 既有防刷：`LOGIN_CNT > 30`（第 31 次起）拦截登录/退出；需重装应用 |
| 早起报告未推送 | 通知权限、电池白名单；WorkManager 有分钟级漂移 |
| 安装失败 `INSTALL_FAILED_UPDATE_INCOMPATIBLE` | 签名不一致，需卸载（清数据）后安装 |
