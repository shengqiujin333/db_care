# 爱守护 用户使用说明书

> 版本:1.7(2026-07)
> 适用平台:Android 8.0 (API 26) 及以上

## 1. 应用简介

爱守护是一款温湿度监控应用,适合为老人房、婴儿房、储物间等需要持续监控的环境提供实时数据查看与异常报警。

主要功能:
- **多设备监控**:可同时绑定多个温湿度传感器,每个设备一张卡片,实时显示当前温度/湿度/状态
- **守护模式**:启动后持续接收数据并触发报警;可设时长,到时自动停止
- **报警通知**:温度超限、温湿度突降、紧急(温度 > 65°C 火灾预警)三种报警,通过震动 + 铃声 + 系统通知提醒
- **每设备参数**:每个设备可以单独设置阈值和报警方式,未设置的字段会回退到全局默认值
- **历史查询**:任意时间范围(50 分钟内)的温湿度曲线,含报警事件列表
- **早起报告**:每天定时推送一份昨日汇总,包括各设备的最高/最低/平均温湿度、报警次数及建议

## 2. 安装与权限

### 2.1 安装
直接安装 `爱守护.apk` 即可。无需 Google Play。

### 2.2 首次启动权限
应用启动时会弹窗要求:
- **通知权限**(必须):用于推送报警和早起报告。拒绝将收不到任何报警提醒。
- **位置权限**(必须):Android 12+ 扫描蓝牙设备需要位置权限。
- **蓝牙权限**(必须):连接 BLE 温湿度传感器。
- **相机权限**(可选):扫码添加设备时使用。

如果误点了拒绝,可以到系统设置 -> 应用 -> 爱守护 -> 权限 重新授予。

### 2.3 隐私政策
首次启动会弹出隐私政策对话框,必须点「同意并继续」才能使用。

## 3. 注册与登录

进入「我的」标签页,顶部有「注册」和「登录」入口。

### 3.1 注册新账号
1. 勾选「注册」checkbox
2. 输入手机号(11 位,1 开头)
3. 点「获取验证码」(60 秒倒计时,5 分钟有效)
4. 输入验证码、密码(6-16 位字母/数字/符号)、确认密码
5. 点「注册」按钮

注册成功后自动登录。

### 3.2 已有账号登录
1. 勾选「登录」checkbox(此时注册相关字段会禁用)
2. 输入手机号、密码
3. 点「登录」按钮

### 3.3 忘记密码
点「忘记密码」按钮,提示用相同手机号重新注册即可覆盖原密码。

### 3.4 退出登录
点「退出登录」按钮,会清除本地登录态。

### 3.5 注销账号
连续点「注销用户」3 次以上,会触发注销(实际是改掉密码,数据保留)。

## 4. 添加传感器设备

### 4.1 通过传感器 ID 列表添加
1. 进入「我的」->「传感器 ID」
2. 在「传感器地址」输入框填入网关地址,点「发送」
3. 用摄像头扫描传感器上的二维码,或手动输入 8 位传感器 ID
4. 给设备起一个名字(中文 ≤ 3 字,或英文/数字 1-8 位)
5. 点「添加」

### 4.2 设备 ID 规则
- 8 位十六进制(0-9, A-F),不区分大小写
- 名称规则:纯中文 ≤ 3 字,或纯英数 1-8 位,不可中英混合或带符号

### 4.3 删除设备
进入「传感器 ID 列表」,每行右侧有垃圾桶图标,点击删除单个;或勾选多个后点底部「删除选中」。

> 删除设备会同时清掉该设备的独立参数设置。

---

## 5. 首页 - 设备仪表盘

进入「首页」标签页,看到所有已添加设备的卡片墙。

每张卡片显示:
- **设备名称**
- **状态 chip**:
  - 灰色「未收到」- 设备已添加但从未上报数据
  - 灰色「离线」- 超过 5 分钟没有新数据
  - 绿色「正常」- 数据正常
  - 橙色「警告」- 触发下降报警或阈值报警
  - 红色「紧急」- 温度 > 65°C 火灾预警
- **当前温度**(大字)
- **当前湿度**(大字)
- **迷你曲线图**(最近 30 分钟温度趋势)
- **报警消息**(如果当前在报警,会显示报警类型)

### 5.1 查看设备详情
点击任意卡片,进入该设备的详情页:
- 顶部 toolbar 显示设备名,右上角有「该设备参数」菜单
- 温湿度变化曲线图(可按时间范围查询,时间范围 ≤ 50 分钟)
- 报警记录列表(最近 24 小时)

---

## 6. 启动 / 停止守护

首页顶部右上角有「启动守护」按钮。

### 6.1 启动
1. 点「启动守护」按钮
2. 按钮变红,文字变「停止」
3. 系统开始接收数据并按设置的阈值报警
4. 如果在「设定」页设置了守护时长(小时),会启动倒计时,到时自动停止

### 6.2 停止
- 点「停止」按钮,或
- 等待守护时长到时自动停止

### 6.3 状态保持
应用被杀进程重启后,会自动恢复到之前的守护状态(启动/停止)和剩余倒计时。

## 7. 设置报警参数

报警参数分为两层:**全局默认值** 和 **每设备独立值**。

### 7.1 全局默认值(设定页)
进入「设定」标签页:
- **下降报警** checkbox + 温度下降阈值 + 湿度下降阈值
- **阈值报警** checkbox + 温度上下限 + 湿度上下限
- **报警方式**:震动、蜂鸣
- **守护时长**(小时)
- **延时报警**(秒)

点「确定」保存,点「取消」恢复默认值(温度下降 1°C、湿度下降 4%、温度 29-35°C、湿度 40-70%、守护 8 小时、延时 5 秒、所有报警方式开启)。

> 这些是「默认值」,所有新设备会自动使用这套参数,直到你为某个设备单独设置。

### 7.2 每设备独立参数
在首页点开某个设备卡片进入详情页,点右上角「该设备参数」菜单:
- 字段与全局页一一对应
- **未填写的字段会回退到全局默认值**
- 已填写的字段以设备值为准
- 删除设备时,该设备的独立参数也会被清除

这样你可以:
- 给所有卧室设备用一套宽松阈值
- 给厨房/阳台设备单独设置高温阈值
- 给婴儿房设备关闭震动报警(避免吵醒)

### 7.3 报警触发条件

#### 温度湿度下降报警
当 5/10/15 分钟前的数据相比当前,温度下降超过 `tempdrop` 且湿度下降超过 `humdrop`,触发报警。
典型场景:门被打开、空调/加湿器停了、传感器位置被移动。

#### 温湿度超限报警
当温度超出 `[tempmin, tempmax]` 范围 或 湿度超出 `[humimin, hummax]` 范围,触发报警。
典型场景:温度过高/过低、湿度异常。

#### 紧急报警(火灾预警)
温度 > 65°C 时立即触发,不受节流限制。
典型场景:火灾、传感器暴露在直射阳光下或加热器旁。

### 7.4 报警节流
为避免同一设备反复报警,普通报警(下降/超限)有 15 分钟节流:15 分钟内只触发一次报警(震动 + 铃声 + 通知)。紧急报警(温度 > 65°C)不节流,每次数据上报都报警。

## 8. 收到报警时怎么办

报警触发时:
1. **手机震动**(最长 5 分钟,可循环)
2. **手机响铃**(系统闹钟铃声,循环播放)
3. **系统通知**弹出,标题格式 `[设备名] 报警`,内容是报警类型
4. **首页卡片**状态 chip 变色,卡片下方显示报警消息

### 8.1 停止报警
在屏幕上**任意位置点击一下**即可停止震动和铃声(BaseActivity.onTouchEvent)。

### 8.2 查看是哪个设备在报警
- **看通知**:通知标题会写 `[设备名] 报警`,通知展开后 BigText 会显示完整报警消息和设备名
- **看首页**:打开 app 后,红色/橙色卡片就是正在报警的设备
- **看详情**:点开卡片可以看到最近 24 小时的报警历史

### 8.3 报警通知不工作?
检查:
1. 系统设置 -> 应用 -> 爱守护 -> 通知 -> 是否开启
2. 通知渠道「设备报警」是否启用(系统设置 -> 应用 -> 爱守护 -> 通知 -> 设备报警)
3. 是否在「设定」页关闭了震动/蜂鸣(关闭后只通知不响铃)
4. 守护状态是否已启动(首页按钮显示「停止」)

## 9. 早起报告

每天定时(默认早 7:00)推送一份昨日数据汇总通知。

### 9.1 修改推送时间
当前版本暂未提供 UI 修改入口,如需修改:
- 用 `adb shell` 改 SharedPreferences:
  ```
  adb shell run-as com.jinyuni.dengbei_care \
    sh -c "echo 'report_time=08:00' >> shared_prefs/MyPrefs.xml"
  ```
  然后重启 app。

### 9.2 手动查看
进入「我的」-> 滚到底部 -> 点「查看今日报告」按钮,会立即生成并打开 ReportActivity。

### 9.3 报告内容
- 摘要:昨日总数据条数、有报警的设备数
- 每设备:最高/最低/平均温度湿度、报警次数及类型
- 建议:基于数据给出(如「温度连续下降,建议检查卧室通风」)

## 10. 常见问题

### Q1:卡片显示「未收到」?
- 检查传感器是否在工作(电池、距离)
- 检查手机蓝牙是否开启
- 检查守护是否已启动(首页按钮显示「停止」)
- 检查设备 ID 是否输入正确(8 位 HEX)

### Q2:卡片显示「离线」?
- 超过 5 分钟没有新数据就会显示离线
- 检查网关是否在线(MQTT 路径)或蓝牙是否在范围内(BLE 路径)

### Q3:MQTT 模式下数据对不上?
MQTT 网关上报的 payload 不含设备 ID,app 按 saved IDs 顺序匹配。如果网关固件不按顺序回传,数据会错位。检查 logcat 中是否有 `Log.w` 告警「设备数量不匹配」。

### Q4:图表搜不到数据?
- 时间范围必须在 50 分钟以内
- 时间格式 `yyyy-M-d HH:mm`
- 守护必须曾启动过(否则没存数据)

### Q5:注册了但收不到验证码?
- 验证码通过云平台短信发送,5 分钟有效
- 确认手机号正确
- 联系管理员:`snack_yx@126.com`

### Q6:登录次数太多被锁?
登录/退出累计超过 30 次后会提示需要重装。这是防刷机制。

### Q7:早起报告没推送?
- 检查通知权限
- 检查 app 是否被系统省电策略冻结(华为/小米/OPPO 等需要把 app 加入电池白名单)
- WorkManager 的定时任务可能有几分钟漂移,属正常

## 11. 数据与隐私

### 11.1 数据存储
- **温湿度数据**:本地 SQLite,按设备 ID 分流(`temperature` 表,字段 `time, device_id, temperature, humidity`)
- **报警事件**:本地 SQLite,`alarm_events` 表
- **用户参数**:SharedPreferences(`MyPrefs`)
- **每设备参数**:SharedPreferences,前缀 `dev_<devId>_`

### 11.2 数据不会上传
所有数据存储在本地,不上传到云端(除了注册/登录请求会经过云平台)。

### 11.3 清空数据
卸载 app 即可清空所有本地数据。
