# 跨专业联合测试计划（E2E-SW-ALM-001 rev 1.0 / 传感器→网关→安卓 App）

状态：跨专业联合测试计划（`software_tester.software_test_design`，输出端口 `e2e_plan`）。**只做计划，不执行安装、烧录、串口、ADB、UI、网关或平台操作。**
关联设计：`artifacts/embedded_test_design_alarm_chain.md`（TD-EMB-ALM-001 rev 1.0，嵌入式侧用例 `EMB-*`）与 `artifacts/software_test_design_alarm_chain.md`（TD-SW-ALM-001 rev 1.0，软件侧用例 `SW-*`）。本文件只规定两专业如何在同一真实环境、同一版本组合和同一事件关联下协同采集与判定，不重复两份设计的全部判据。
目标来源：当前 Project Goal（真机核对固件/App 版本；覆盖采集、网关转发、手机显示、正常不误报、异常报警；优先复现/修复反复报警与点停止关不掉；验证取消后铃声/震动停止、停止守护后不再报警、重启守护后新事件仍报警；修复版完整复测传感器→手机；平台/云/DB/iOS 不纳入）。

**结论先行**：`DESIGN_READY` 只表示本联合计划可执行，**不表示任何端已执行或通过**。本计划有两个必须共同遵守的可执行性事实：

1. **当前环境下传感器不会自然产生新的 433 上报**（量产固件 `LIGHT_DARK_THRESHOLD_CODE=0`、现场有光、用户不调温/不调光）。受控正向事件必须使用固件实现提供的测试构建（TD-EMB-ALM-001 §4）；没有它，受控正向/报警/完整链路用例记 `NOT EXECUTED`，不得用真实缓存读数冒充“本轮传感器→手机新事件”。
2. **网关缓存复读是优先缺陷复现的真实入口**：若执行时缓存值在当前默认阈值之外，App 会对同一未变化缓存值产生普通报警；这可以复现“反复报警/点停止关不掉”，并证明**网关→App 的当前 BLE 链路**。它不证明本轮传感器→网关的 433 新事件，也不证明注入值的物理响应。

## 2. 链路、事件与关联键

```text
传感器采样/判定（180 s）
  → 433 10 B 加密帧（uid4|temp_le2|hum_le2|crc16_le2）
  → 网关 433 接收 → 按绑定 ID 组 16 B 块 → AES-ECB → FFE2 160 B 缓存
  → App 每 180 s BLE 读取 → 解密/长度守卫/逐 ID 消费
  → AlarmEvaluator → 本地库 + 卡片/详情 + 铃声/震动/通知
```

### 2.1 关联键

- `uid4`：传感器 `BOOT uid` 前 4 字节（8 位大写 HEX）= 433 帧设备 ID = 网关块 `id4` = App `MacIdBook` ID。
- 受控载荷：固件测试构建固定 `(mode, temp_x10, hum_x10)`；传感器 `TINJ/P` 的冻结值、App 日志 `id=uid4, T/H`、本地库 `temperature` 行、UI 必须逐项一致。
- 模式切换（`NORM→THR→THR_NEW→DROP_BASE→DROP_CUR→EMG→EMG_NEW`）是同一/不同事件的区分手段；同一未变化值无法靠数值区分，必须结合模式、读取序号、点击/静音时刻与 `lastAlarmTime` 窗口。
- 时间语义：传感器 `S/P` 的 `k` 是 RTC 累计分钟节拍；App 的接收时间是手机读取时刻；网关缓存复读会产生“同值不同秒”。**不以“时间接近”猜同一事件**，以 `uid4 + 注入模式/值 + 采集窗口 + 读取时刻` 关联。

### 2.2 接收端先就绪（触发前检查表）

在触发任何传感器注入/复位/网关读取前，以下接收端必须已就绪并记录基线：

1. 传感器：COM43 已按 9600 8N1 打开，原始字节+时间戳落盘；记录上电五行/`BOOT uid`；测试构建模式与 `TINJ` 约定已确认。
2. 网关：上电、手机 App 已保存经用户确认的 BLE 地址；记录 MAC/名称/`GwID`/`devCount`/`valueSize`/MTU；网关缓存当前值与时间已记录。
3. App：实际安装字节/versionCode/Name/签名已核对；`MacIdBook` 含 `uid4`；守护状态、参数、通知渠道、音量/勿扰已记录；logcat 已开始采集并记录起点；UI 基线已保存。
4. 平台/云：按范围关闭/排除；若不能离线，记录实际网络状态，任何 MQTT/HTTP 观测不进入判据。
5. 本地库：已复制 `bwtemperature_database1`（含 `-wal/-shm`）到主机；记录 `temperature` 行数/最大时间与 `alarm_events` 计数；测试期间只读副本查询。

> 触发发生在以上全部就绪之后；不得先注入后补日志/DB 基线。

### 2.3 串行节点间的采集编排（本次授权内）

- 首选：同一执行窗口内由具备对应授权的执行能力同时持有 COM43 采集与 ADB 观测；传感器注入/上报与 App 读取/判定在同一时间窗完成。
- 若当前授权下无法保持一个跨节点的持续采集通道：不等待、不阻塞后序。改用**模式/值可区分**的分段采集：
  - 每个分段只使用一个测试模式/固定值，记录分段起止、COM43 原始日志、App logcat、DB 副本、版本身份；
  - 用 `TINJ` 的 `k`/模式、App `id=uid4/T/H`、DB 行、UI 时刻做关联；
  - 分段之间不得拼成“连续未验证”；联合结论只在同一构建身份、同一事件关联成立时给出。
- 不得把“未同时采到”写成“通过”，也不得要求另一专业重做不属于其职责的观测。

## 4. 联合刺激序列（同一会话的推荐编排）

> 每个箭头后的等待时间是最小观测窗口；实际以 App 180 s 读取与传感器 180 s 采样为准，允许 1 个周期错位。触发前确认接收端就绪。

1. **P0 身份/新数据准备（如需要）**：如需清数据/全新安装，**先**完成安装/清数据；随后核对 App/传感器/网关身份，重新登记 `uid4`、保存网关、记录参数与守护状态；记录基线 DB/dumpsys/UI。**清数据若发生在 P0 之后，必须重做绑定/网关/参数与 `SW-VER-02`，不得沿用清数据前的基线。**
2. **P1 真实采集**：发布构建或测试构建 `OFF`，静置 ≥10 min；COM43 取 `S`（`k` 步长 3、`q=1`、`r/s/y=0`）；App 侧记录网关缓存/链路状态（不要求新读数）。→ `EMB-ACQ-01` + `SW-NF-02`。
3. **P2 显示/正常**：切 `NORM` 30.0/55.0；确认 P0 已在清数据/全新安装后重新完成绑定/网关/参数且守护启动；等待 ≥2 个读取周期。观察 `TINJ/P`→App 日志→卡片/详情/DB；`SW-NF-01` 再持续 ≥3 个周期确认无报警。→ `EMB-CHN-01` + `SW-DSP-02` + `SW-NF-01`。
4. **P3 异常**：
   - 确保距上次普通报警副作用 ≥900 s；`THR 36.0/55.0` → 超限报警；记录首次报警时刻。
   - 确保距上次普通报警副作用 ≥900 s；`DROP_BASE 34.9/60.0` → 约 6 min 后 `DROP_CUR 32.0/55.0` → 下降报警。
   - `EMG 66.0/55.0` → 紧急报警；逐字核对文案。
5. **P4 重复**：
   - 确保距上次普通报警副作用 ≥900 s；`THR` 保持 36.0 ≥20 min；首次报警后**空白区域静音**（守护保持）；观察 `lastAlarmTime+900 s` 后是否第 2 次副作用。A 复现，B 判修复。→ `SW-REP-01`/`EMB-REP-01`。
   - `EMG` 保持 66.0 ≥20 min；同样空白静音；记录下一次读取是否再次报警；按范围决定判据。→ `SW-REP-02`/`EMB-REP-02`。
6. **P5 停止**：在普通报警进行中，用 `uiautomator` 定位 `startGuardButton`（文字「停止」）并点击；≤2 s 核对铃声/震动停止、按钮「启动」、`measure_state="starting"`；随后同值不再普通报警。→ `SW-STP-01`/`EMB-STP-01`。再用一次普通报警，点空白区域对照。→ `SW-STP-02`。
7. **P6 守护**：守护已停止；注入 `THR_NEW 36.2/55.0`，≥2 个读取周期无普通副作用（卡片/`alarm_events` 可更新，记录）。→ `SW-GRD-01`/`EMB-GRD-01`。距上次普通报警副作用 ≥900 s 后点「启动」，继续/注入 `THR_NEW`，1 个读取周期内应产生新报警。→ `SW-GRD-02`/`EMB-GRD-02`。`EMG` + 守护停止按范围记录。→ `SW-GRD-03`/`EMB-GRD-03`。
8. **P7 完整复测**：B 相位修复版 App + 同一测试构建，按 `SW-RET-01`/`EMB-RET-01` 顺序复跑；会话开始/结束版本一致；无 `FATAL`/`ANR`。
9. **P8 恢复/交付**：按 `EMB-BLD-01` 恢复发布镜像并 `Verify OK`；按 `SW-BLD-01` 核对 App 交付身份与测试钩子排除。

**判定规则**：

- 任何联合用例只有在**同一构建身份、同一 `uid4`、可关联的事件/值/窗口**下，两端观察都成立时才判 PASS。
- 一端 `NOT EXECUTED`、观察缺失、或只有“时间接近”而无 `uid4+值/模式+窗口` 关联 ⇒ 整例不通过，不得部分通过。
- 局部 PASS 只证明对应观察点；受影响组件修复后，重新采集受影响链路，不得沿用旧结论。
- 阶段 PASS 不等于完整产品通过；平台/云/DB/iOS 与调温/调光/功耗不进入本轮判据。

## 7. 就绪、过期与清理

### 7.1 就绪条件

- 设备：手机 ADB `device`、蓝牙/定位/通知/音量/勿扰/白名单；传感器 COM43 可打开；网关上电；逻辑分析仪/示波器非必需。
- 版本：App/传感器/网关身份已记录；`uid4`/`MacIdBook`/`gateway_ble_addr` 一致。
- 观测：logcat、COM43、DB 副本、dumpsys、UI 基线均已开始/保存。
- 参数：默认值已读取/记录；独立覆盖已清除或记录；执行后恢复。

### 7.2 过期/失效

- App 安装字节、传感器镜像、网关身份、`uid4` 或参数在会话中变化 ⇒ 之前未完成的用例证据过期，重新采集。
- 网关缓存超过约 1000 s 无新帧可能清零占位 ⇒ 依赖缓存的 L0 用例在窗口内完成；超过窗口未完成则改用测试构建注入，不把占位当读数。
- App 进程重启/强停 ⇒ 内存节流/历史状态清零；依赖状态的重复/重启用例必须记录并重新建立基线。
- 手机断连/蓝牙关闭/网关断电 ⇒ 当前用例暂停，记录原因；不得用“没响/没读到”直接判产品失败。

### 7.3 清理

- 停止传感器注入，恢复发布镜像并 `Verify OK`（嵌入式）。
- 停止守护/前台服务；恢复 App 参数/网关地址到执行前值（若为用户数据）；关闭 logcat/COM43/UI 采集。
- 保存原始证据与主机副本；删除临时测试脚本产物（保留脚本与摘要）；不上传任何平台/云数据。
- 不修改网关固件、平台、数据库或产品源码。

## 8. 分工与边界

| 工作 | 责任 | 说明 |
|---|---|---|
| 固件测试构建/注入/`TINJ`/正式版排除 | 固件实现 | 按 TD-EMB-ALM-001 §4；测试侧不修改产品源码 |
| 传感器串口/烧录/复位/恢复 | 嵌入式测试执行 | 按 TD-EMB-ALM-001 §5；COM43 原始日志与 `Verify OK` |
| 网关 433→BLE 转发观测 | 嵌入式/软件联合 | 无网关调试口；以 App BLE 读取结果为转发观测；不烧录 |
| App 安装/版本/UI/logcat/dumpsys/DB | 软件测试执行 | 按 TD-SW-ALM-001 §2.3/§4/§7 |
| App 停止/重复报警/守护修复 | Android 实现 | 基于 A 相位证据；重建候选；记录新身份 |
| 紧急 >65 守护/重复是否纳入“不再报警/不重复” | 当前用户/验收范围所有者 | 明确决定后更新用例；未决定前不阻塞普通用例 |
| 平台/云/DB/iOS | 不在本轮 | 不创建下游节点、不修改 |

**边界**：本计划不把平台/云/DB/iOS 纳入；不安排调温/调光/功耗；不修改网关固件；不把 mock/宿主机单测当作真机链路通过。真实物理事件不可自然触发时，受控注入位于产品输入边界，明确其不能证明的物理/电气部分。

## 9. 联合退出准则

1. P0 身份/就绪全部有证据；App/传感器/网关版本与 `uid4`/网关身份一致。
2. P1 真实采集有 `S` 证据；P2 显示/正常有 `TINJ/P`→App→UI/DB 一致且正常值无副作用。
3. P3 三类异常报警按各自判据通过。
4. P4 `SW-REP-01` 的修复判据通过；`SW-REP-02/03` 按范围记录。
5. P5 `SW-STP-01` 按钮路径停止且守护关；`SW-STP-02` 空白路径回归。
6. P6 `SW-GRD-01` 普通报警停止后静默；`SW-GRD-02` 重启后新事件报警；`SW-GRD-03` 按范围记录。
7. P7 修复版完整复测全部强制子用例通过；版本会话内一致；无 `FATAL`/`ANR`。
8. P8 发布镜像恢复 `Verify OK`；App 交付身份记录；正式候选无测试钩子。
9. 任一强制项失败/未执行 ⇒ 联合结果不通过；写明用例、期望/实际、证据缺口与责任建议。**未执行不等于通过；阶段通过不等于完整产品通过。**
