## 4. 证据有效性规则

1. **版本绑定**：每条证据必须对应提交号、构建/镜像摘要（axf/APK/服务端版本）、采集时间；证据与受测件不一致即无效。
2. **原始性**：串口证据为 COM43 原始字节捕获（不得只给转述/摘要）；App 为截图 + 日志；云端为 SQL 查询结果；服务器为命令输出/健康检查。
3. **独立性**：F/O 级判定由非实现者执行；实现者自测可作为 I 级证据，但不能单独作为 F 级通过依据。
4. **时间**：跨设备场景必须记录时间基准与偏差；不得把 App 接收时间当作传感器采样时间。
5. **完整性**：失败/超时/空抓包必须保留，不得只保留成功片段；失败证据同样入库。
6. **旧证据无效**：旧提交、旧镜像、旧 COM42、旧运行记录的“通过”不得复用；旧失败可作为排查背景，但不作为本轮结论。
7. **不可推断**：不得从代码“看起来正确”、单元测试通过、日志无报错推出真实条件通过；不得合成缺失读数或暗态。

## 6. 全目标真实条件场景（F 级）

> 每个场景必须记录：提交/镜像、设备/板号、时间基准、操作方式、原始证据。未执行 = NOT EXECUTED，不得记作通过。

### E2E-01 暗环境升温 → 全链路上报

- 前置：`C_dark` 已标定；传感器处于完全遮光；网关/手机/服务器可用；App 守护中且已注册手机号。
- 刺激：连续两个有效周期，使温度从 T 升至 T+1.0℃ 或更多（安全、可记录的方式；不得改硬件）。
- 可观察：传感器恰好发送一次；`S` 行 `p=1 r=1 s=1`；网关 BLE 帧含对应 ID/T/H；App 出现新读数；`sensor_data` 出现对应行。
- 通过：全链路字段一致；仅一次；时间顺序合理；无重复行。
- 失败：无发送、发送多次、网关/App/云端缺一、字段不一致、重复行。

### E2E-02 有光升温 → 不上报

- 前置：同 E2E-01，但传感器处于有光（`dark=false`）。
- 刺激：同样升温 ≥1.0℃。
- 通过：传感器不发送；App/云端无新行；`S` 行 `p=0 r=0 s=0`。
- 失败：有光仍上报（违反 PR-004）。

### E2E-03 边界与降温反例

- 子场景：
  1. 暗、Δ=0.8℃ → 不报；
  2. 暗、Δ=0.9℃ → 不报；
  3. 暗、降温 → 不报；
  4. 无前值、恰好 35.0℃ → 不报；
  5. 暗、34.0→35.0℃ → 报（升温分支）；
  6. 有光、34.0→35.0℃ → 不报；
  7. 35.1℃（有光/无前值）→ 报（超温分支）。
- 通过：逐项与 PDR 表一致；无“等于阈值也触发”。
- 失败：任一方向/边界错误。

### E2E-04 长时间无上报

- 前置：条件长期不满足（如有光/温度平稳）；App 守护中。
- 观察：>30 分钟无新读数。
- 通过：App 显示“最近上报 X 前”+条件上报说明，不显示“离线”；不补点；图表无虚假样本。
- 失败：以固定 3 分钟/30 分钟判离线；补点/零值；文案写成“下降”。

### E2E-05 故障与恢复

- 子场景：GXHT40 断线/无 ACK；ADC 全超时；433 发送失败；BLE 帧非法；MQTT 数量不符；断网。
- 通过：各自按 PSPEC §4 处理；不伪造；有诊断；恢复后继续工作。
- 失败：假数据、错配、永久失联、无限重试、把失败当通过。

### E2E-06 云端断网/恢复/幂等

- 步骤：断网产生读数 → 恢复 → 补传；重复上传同一 `(dev_id,time)`；检查数据库。
- 通过：outbox 保留；恢复补传；恰好 1 行；无旧 IP；无管理凭据。
- 失败：丢数据、重复行、上传成功但无行、凭据泄漏。

### E2E-07 多设备归因

- 前置：网关绑定 ≥2 台传感器；分别触发。
- 通过：BLE 按帧内 ID 归因；MQTT 数量一致时按顺序；数量不符拒绝；无跨设备错配。
- 失败：把 A 的读数记到 B；静默截断。

### E2E-08 部署手册独立演练

- 前置：未参与实现的人员；干净/可恢复环境；手册当前版本。
- 步骤：服务器部署/恢复 → App 安装/注册 → 网关配对 → 传感器烧录/标定 → 联调 → 回滚。
- 通过：每步可执行；健康检查通过；偏差记录；不依赖未声明资源。
- 失败：缺步骤/凭据/端口/证书/回滚；必须口头补充才能完成。

## 7. 退出标准与失败处理

### 7.1 产品交付门禁（全部满足才可宣告通过）

4. **真实条件 F 级完成**：E2E-01..E2E-08；未覆盖项必须列出，不能写成通过。
5. **O 级手册演练完成**：独立人员、可复现、可回滚。
6. **证据合规**：PA-024；每条结论可追溯到当前受试件；独立于实现者；旧证据未混用。
7. **开放条件关闭**：FB-01..FB-09 中标记“阻断 F 级”的项已由用户/产品/运维确认或提供。
8. **无伪造**：任何 0 值、暗态、读数、上传成功、通过结论均不得合成。

### 7.2 失败处理

- 任一 P0 失败：记录 AC ID、刺激、期望/实际、原始证据、复现条件；反馈给对应实现/测试能力，按 Runtime 的 loop 机制重试。
- P1 失败：可申请风险接受；未获批则按 P0 处理。
- 条件缺失（暗环境、服务器、网关、方向/容差确认）：标记 `CONDITIONAL/NOT EXECUTED`，不得判通过；由用户/运维提供后重做；不得用模拟替代。
- 实现者不得自判“不可修复”；验证者不得自行终止 loop；不得返回 BLOCKED。
- 旧通过结论在需求/构建/设备变化后自动失效，必须重验。

### 7.3 不可宣称事项

- 未执行 F 级：不得宣称“产品总功能测试通过”。
- 未做全暗标定：不得宣称“无光判定通过”。

- 未做独立演练：不得宣称“操作部署手册可交付”。
