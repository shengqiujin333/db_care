## 1. 系统上下文

```text
[传感器]  GXHT40(I²C) + 光敏分压(PB04/AIN11, PB05 供电)
   │        CW32L010；3 分钟采样；条件门控；UART1 调试
   │ 433 MHz（10 B 加密帧，无 ACK）
   ▼
[中继器]  CH592 + UM2006A 接收；解密/CRC；按 ID 缓存；BLE 聚合
   │ BLE FFE0/FFE2（AES-ECB；16 B 头 + N×16 B 设备块）
   ▼
[Android] 解码/归因/时间戳/入库/用户报警/展示
   │ MQTT ssl://8.140.23.253:8883（既有 topic）
   │ HTTP http://8.140.23.253:5000/upload_data（守护 + 已注册手机号）
   ▼
[云平台]  EMQX 5.8.0 / abr.py(Flask) / MySQL bwusernamebase.sensor_data
```

说明：
- 传感器与网关之间无应用层 ACK；433 发送成功只代表本地发送完成。
- 光照状态、上报原因、采样时刻不上 433/BLE；下游不能反推“无光”，也不得重算门控。
- 网关既有 MQTT 上行路径保持不变；本轮不把 CH592 描述为新增 MQTT 客户端。
- App 的既有 MQTT 订阅路径保持不变；发布端与上行实现不在本轮改动范围。

## 2. 传感器行为规格

### 2.1 上电与周期状态机

```text
上电/复位
  → 初始化时钟/GPIO/RTC/软 I²C/光照/433
  → UART1 初始化并打印 BOOT
  → 上电诊断：VDD → IOTEST → IOSIG → BUS
  → sample_flag = 1（允许一次立即采样）
  → 采样周期：
       光照采样（PB05 供电→稳定→ADC 多次→均值→PB05 低）
       温湿度采样（探测 0x44/0x45 → 0xFD → 10 ms → 6 B → 双 CRC → 换算/量程）
       若温湿度有效：
           用“更新前的 prev”做条件判定
           置/不置待上报
           推进 prev 与最近有效湿度
       若失败：
           保留上一有效值；不判定上报；记录诊断
       发布 UART1 S 行（失败再发 G 行）
       若待上报：组帧/加密/有界发送
       否则不发送
  → 清除 sample_flag
  → 深睡；RTC 每 1 分钟唤醒计数，累计 3 次置 sample_flag
```

### 2.2 采样顺序与依赖

| 步骤 | 行为 | 失败处理 |
|---|---|---|
| 1. 光照 | PB05 高 → 等待 ≥100 ms → 最多 8 次 ADC → 均值 → PB05 低 | 部分成功用成功均值；全部失败 `valid=false`；不影响温湿度采样 |
| 2. 温湿度 | 探测地址 → `0xFD` → 等待 10 ms → 读 6 B → 双 CRC → 换算 → 量程 | 有界重试；仍失败则整周期失败；不更新 prev、不发送 |
| 3. 判定 | 见 §2.3 | 光照无效只关闭升温分支 |
| 4. 发送 | 组 10 B 明文 → Feistel → 200 ms 超时 ×3 | 用尽放弃本轮；不伪造成功；下一周期按新判定 |
| 5. 轨迹 | UART1 `S`/`G` | 打印失败不得影响业务结果 |

### 2.3 条件上报判定表

变量（整数，0.1℃）：
- `cur`：本周期有效温度；`prev`：上一有效温度；`have_prev`：是否存在 `prev`。
- `dark`：`light.valid && 3*mean_adc >= C_dark`。

```text
if (!sample_valid)                      -> 不上报；不推进 prev
else if (cur > 350)                     -> 上报（超温分支，独立于光照/prev）
else if (have_prev && dark && cur-prev > 9) -> 上报（升温 + 无光）
else                                    -> 不上报
```

关键边界：
- `cur - prev = 9`（+0.9℃）不上报；`= 10`（+1.0℃）上报。
- `cur = 350` 不满足超温；若 `dark && cur-prev > 9` 仍上报。
- `dark=false`（有光/无效/未标定）时升温分支不成立。
- 每次成功温湿度采样（无论是否上报、光照是否有效）都推进 `prev`。
- 上报的温湿度必须是触发本次判定的那一笔有效样本；重试期间保持一致。

### 2.4 光照与标定规格

- 拓扑（网表）：`PB05 → R3 5 MΩ → PB04(AIN11) → 光敏电阻 → GND`。
- 极性：越暗 → 光敏阻值越大 → PB04 电压/ADC 码越高。
- ADC：12 位，0..4095；参考为 VDD（比率式）。
- `C_dark`：完全遮光、同板、同供电/等待/取样策略下的有效均值；范围 1..4095。
- 阈值：`T_dark = ceil(C_dark / 3)`；`mean >= T_dark` 且 `valid` 判暗。
- 标定记录字段（最低）：
  - 板件标识（MCU UID/板号）、固件提交与构建标识；
  - 供电方式与实测电压（如有）；
  - 遮光方式与环境（完全遮光/暗室）、时间；
  - 每次样本的 ADC 码或 min/max/mean、样本数；
  - 回填的 `C_dark`、`T_dark`、配置版本。
- 禁止：用满量程 4095、旧 350/250、当前亮态读数、估算值直接当 `C_dark`。

### 2.5 UART1 调试行规格（产品可观察）

物理：`PA06=TXD`、`PA05=RXD`，9600 8N1；当前入口 `COM43`。
每行 ≤96 字节；字段仅整数/大写十六进制；以换行结束。

| 行 | 时机 | 最低字段 |
|---|---|---|
| `BOOT` | 上电/复位 | 固件标识、UID 前 4 字节、复位来源、`uart=9600` |
| `VDD` | 上电诊断 | `ok=`、ADC 码、BGR 修调、`mv=` |
| `IOTEST` | 上电诊断 | SDA/SCL 拉低回读、空闲电平、角色互换探测、general call 结果 |
| `IOSIG` | 上电诊断 | 事务内 20 个半位的 SCL/SDA 签名 |
| `BUS` | 上电诊断 | 空闲电平、0x08..0x77 中 ACK 地址集合（无则 `none`） |
| `S` | 每个采样周期（判定/发送后） | tick、prev 与 have_prev、光照 valid/成功数/min/max/mean/dark、temp_x10、hum_x10、sample_ok、report、send、retry |
| `G` | 温湿度失败周期（`S` 后） | 结果码、a44、a45、读重试、整帧重测、最近 6 B 或占位 |

约束：
- 打印不得改变采样/判定/发送；同一业务状态下开/关 UART 的结果必须一致。
- 深睡期间无输出；唤醒后重新初始化。
- 不得复位 GPIOA、不得关闭 GPIOA 时钟、不得影响 PA03/PA04/PA07/PA08。

### 2.6 433 帧规格（不变）

| 偏移 | 长度 | 字段 | 编码 |
|---:|---:|---|---|
| 0 | 4 | sensor_id | 原字节 |
| 4 | 2 | temperature_x10 | int16 小端 |
| 6 | 2 | humidity_x10 | uint16 小端 |
| 8 | 2 | CRC16 | CCITT-FALSE，小端 |

加密：既有 8 轮 Feistel，10 B 密文；密钥/置换不变。无光照/原因/时间/版本字段。

### 2.7 配置参数（单一配置点）

| 参数 | 值 | 说明 |
|---|---:|---|
| 采样节拍 | 1 min × 3 | RTC |
| 测量等待 | 10 ms | GXHT40 高重复率 |
| 读重试 | 5 | 上限 |
| 整帧重测 | 3 | 上限 |
| 升温阈值 | >9（0.1℃） | 严格 |
| 超温阈值 | >350（0.1℃） | 严格 |
| 光照样本 | 8 | 成功值上限 |
| 光照稳定 | 100 ms | PB05 上电后 |
| 全暗基准 | `C_dark`（待实测） | 1..4095 |
| 暗阈值 | `ceil(C_dark/3)` | 整数 |
| RF 超时/重试 | 200 ms ×3 | 有界 |
| UART | 9600 8N1，≤96 B/行 | COM43 |

## 3. Android 行为规格

### 3.1 输入与归因

两条输入路径汇聚到同一处理链：

1. **BLE 直读**：连接网关 → FFE0/FFE2 → AES-ECB 解密 → 帧校验 → 每设备块解码。
2. **MQTT**：订阅既有 topic → 解析 `time:temp1,...:humi1,...` → 按绑定顺序归因。

规则：
- BLE 帧长必须为 `16×(1+N)`；`N≥1`；密文 16 B 对齐；否则拒绝整帧。
- 设备块：`id(4) | hum u16be@4 | temp s16be@6`；单位 /10 一次。
- MQTT 数量与本地 ID 集合不一致：拒绝整批，不静默截断。
- 未知 ID 不映射到其他设备；不得用列表位置替代 BLE 帧内 ID。
- 收到时间 ≠ 传感器采样时间；不得声称精确采样时刻。
- 不补点、不插 0、不按 3 分钟生成样本。

### 3.2 展示与文案

| 元素 | 规格 |
|---|---|
| 卡片状态 | 不再用“30 分钟无数据=离线”；显示“最近上报 X 分钟/小时/天前”+“按条件上报，可能长时间无上报”；连接状态单独表达 |
| 状态 chip | 保留 未收到/正常/警告/紧急 |
| 详情规则 | “采样周期 3 分钟。本次温度比上次高超过 0.9℃ 且无光，或温度超过 35.0℃ 才上报；未满足条件不会上报，可能长时间没有新数据。” |
| 高温强调 | `>35.0℃` 强调；`=35.0℃` 不强调 |
| 图表范围 | 上限 24 小时；提示稀疏数据 |
| 早起报告 | 说明“按条件上报、条数非等间隔”；当日无上报显示“昨日无上报” |
| 光照 | 不显示、不推断、不解释 |

### 3.3 用户报警（保持既有语义）

| 类型 | 条件 | 文案/级别 | 节流 |
|---|---|---|---|
| 未设置 | 两个开关都关 | “未设置报警”/NORMAL | — |
| 下降 | 5/10/15 分钟时间窗基准，温度与湿度都低于基准超过用户阈值 | “温度湿度下降报警”/WARNING | 900 s |
| 超限 | 严格超过用户设置上下限 | “温湿度超限报警”/WARNING | 900 s |
| 紧急 | 温度 `>65.0℃` | “紧急报警，温度超过65度，谨防火灾”/ALARM | 不节流 |

注意：此“下降报警”是 App 既有用户功能，**不是**传感器上报条件；不得把两者混为一谈，也不得因 PR-004 升温判据而删除既有下降报警。

### 3.4 云上传

- 触发：守护运行中 + 手机号非空 + 有新归因读数。
- 入队：本地 outbox，主键 `(dev_id, time)`；空集不发。
- 上传：`POST /upload_data`，请求体见 PR-009；HTTP 2xx 视为成功并删除；失败保留并按退避重试。
- 幂等：服务端 `UNIQUE(dev_id,time)` + `INSERT IGNORE`；重试沿用原 `time`。
- 限制：Unix 秒键无法区分同秒多个真实样本；不同接收秒的同一缓存复读可能被当作新数据（记录为已知限制）。

## 4. 故障与恢复矩阵

| 故障 | 传感器行为 | App/云端行为 | 可观察证据 |
|---|---|---|---|
| GXHT40 无 ACK | 有界重试；失败不更新 prev/不发送；下一周期重探 + 总线恢复 | 无新读数；不补点 | `G s=… a44=0 a45=0`、`BUS ack=none` |
| CRC 错 | 丢弃整笔；重测；失败不发送 | 无新读数 | `G` 结果码/重试计数 |
| 温度超量程 | 样本无效；不发送 | 无新读数 | `S q=0` / `G` |
| 光照 ADC 全超时 | `valid=false,dark=false`；升温分支关闭；超温分支仍可用 | App 无光照信息 | `S o=0/V=0/D=0` |
| 未标定 `C_dark` | `valid=false`；升温分支不触发 | — | `S V=0 D=0` |
| 433 发送失败 | 200 ms ×3；用尽放弃；不伪造成功 | 无新数据 | `S s=2 y=n` |
| BLE 帧非法 | — | 拒绝整帧；不入库/上传/告警 | App 日志/单测 |
| MQTT 数量不符 | — | 拒绝整批 | App 日志/单测 |
| 断网/HTTP 失败 | — | 入 outbox；恢复后幂等补传 | outbox/服务器行 |
| 服务器不可用 | — | 本地数据保留；不丢历史；重试有界 | 健康检查/日志 |
| 重启/断电 | `have_prev=false`；首样本仅超温可报 | 旧数据保留 | `S H=0` |

## 6. 验收场景（产品级）

> 每个场景均要求：当前提交 + 当前构建/镜像标识 + 时间 + 原始证据；未执行或未覆盖必须显式记录，不能写成通过。

### AT-01 3 分钟采样节拍

- 前置：当前交付固件已烧录；COM43 连接；设备上电。
- 步骤：捕获 ≥20 分钟 UART1；统计 `S` 行周期与 tick。
- 期望：每 3 个 1 分钟 tick 一个周期；周期间无额外采样；间隔中位数 180 s（暂定 ±10%）。
- 证据：原始 `.cap`/文本、解析脚本输出、构建/镜像标识。

### AT-02 温湿度有效采集

- 前置：GXHT40 焊接/连线正常；上电诊断 `BUS` 出现 `0x44` 或 `0x45`。
- 步骤：连续捕获 ≥5 个周期。
- 期望：`q=1`；`t/h` 在有效域；稳定环境下不出现异常跳变；`G` 行不出现。
- 证据：`S` 行、`BUS` 行、必要时参考温湿度计（未提供则记录“准确度未覆盖”）。

### AT-03 全暗标定与光照判据

- 前置：传感器板、完全遮光容器/暗室、稳定供电；记录板号与固件版本。
- 步骤：完全遮光下采集 ≥N 次（N 以能给出稳定分布为准），记录 min/max/mean；回填 `C_dark`；在亮环境与全暗环境分别采样。
- 期望：全暗 `mean ≥ ceil(C_dark/3)` → `dark=true`；亮环境 `mean < 阈值` → `dark=false`；边界相等判暗；ADC 全失败 `valid=false`。
- 证据：原始 ADC 码、配置 diff、`S` 行。

### AT-04 条件上报正例（暗 + 升温）

- 前置：标定完成；`dark=true`；传感器处于可升温环境。
- 步骤：使相邻两次有效采样升温 ≥1.0℃（如 30.0→31.0）；观察 RF 与下游。
- 期望：仅该周期触发一次上报；网关收到；App 显示新读数；数值与传感器一致。
- 证据：`S` 行（`p/r/s/y`）、网关/App 记录、时间对齐。

### AT-05 条件上报反例

| 子场景 | 期望 |
|---|---|
| 有光 + 升温 1.0℃ | 不上报 |
| 暗 + 升温 0.8/0.9℃ | 不上报 |
| 暗 + 降温 | 不上报 |
| 暗 + 无前值 + 35.0℃ | 不上报 |
| 暗 + 34.0→35.0℃ | 上报（升温分支） |
| 任意光照 + 35.1℃ | 上报（超温） |
| 任意光照 + 36.0℃ + 无前值 | 上报（超温） |
| 光照无效 + 升温 1.0℃ | 不上报；超温仍可上报 |

- 证据：逐个场景的 `S` 行与下游记录；不得用宿主机结果替代真实目标正例。

### AT-06 采集失败与恢复

- 步骤：断开 GXHT40/短接总线/注入 CRC 错；观察 ≥2 个周期；恢复接线；再观察 ≥2 个周期。
- 期望：失败周期 `q=0`、无上报、prev 不推进、`G` 行给出原因；恢复后重新探测成功、`q=1`、判定恢复。
- 证据：原始捕获、故障注入方式、恢复时间。

### AT-07 调试串口规格

- 步骤：COM43 9600 8N1 捕获上电与 ≥3 周期。
- 期望：`BOOT→VDD→IOTEST→IOSIG→BUS` 顺序完整；每周期恰一行 `S`；失败周期恰一行 `G`；每行 ≤96 B；字段格式符合 §2.5；深睡无输出。
- 证据：逐字节捕获、行长统计。

### AT-08 Android 解码/归因/非法帧

- 步骤：用参考向量与非法帧驱动单元测试/仪器化测试；多设备 BLE 帧；MQTT 数量不符。
- 期望：参考向量逐字段正确；非法帧全部拒绝；多设备归因正确；MQTT 不符整批拒绝；负温/边界正确。
- 证据：测试报告、向量输出。

### AT-09 Android 展示与既有报警回归

- 步骤：构造长时间无数据、稀疏数据、35.0/35.1℃、下降/超限/紧急场景。
- 期望：无“离线”误报；相对时间与条件上报说明正确；规则文案为升温；高温强调边界正确；既有报警阈值/文案/节流不变。
- 证据：截图/UI 测试、单元测试。

### AT-10 云上传与幂等

- 步骤：守护 + 注册手机号；产生一条读数；重复上传；断网后恢复。
- 期望：`sensor_data` 出现一行；重复不新增；断网入 outbox，恢复补传且不重复；空集不发。
- 证据：HTTP 日志、SQL 查询、outbox 状态。

### AT-11 真实条件总功能测试

- 前置：真实传感器（标定完成）+ 真实网关 + 真实手机 + 真实服务器；真实暗/光与温度变化窗口。
- 步骤：
  1. 暗环境升温触发 → 观察全链路；
  2. 有光升温 → 不触发；
  3. 35.1℃ → 触发；
  4. 长时间不满足条件 → App 显示相对时间而非离线；
  5. 断网/断器件 → 恢复。
- 期望：数据、告警、展示、云端记录与需求一致；无伪造/错配/重复；失败可诊断。
- 证据：时间同步的串口捕获、网关/App 日志、SQL 行、现场记录；未覆盖项列清单。

### AT-12 部署手册独立演练

- 步骤：未参与实现的人员按手册从零/从备份恢复部署服务器与 App，完成传感器烧录/标定/联调。
- 期望：步骤可执行；端口/证书/服务/权限/回滚可核验；偏差有记录。
- 证据：演练记录、命令输出、健康检查、问题清单。
