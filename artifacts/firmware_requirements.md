状态：固件方案设计的伴随需求视图（firmware_engineer.firmware_solution_design）
版本：5.0（替代 rev 4.0；本轮 run8 在基线 `1dd8e4b` 上重新核对当前实现与最新 readme，新增 FWR-116「GXHT40 采集失败可诊断」与 FWR-117「验收以当前构建的实板再观测为准」，并收紧 FWR-110 的标定门槛与 FWR-114 的冻结语义；rev 4.0 已冻结的升温方向/严格边界、光敏 1/3 全暗判据、光照有效性保持不变）
范围：本次「GXHT40 替换温湿度传感器 + 光敏分压 + 3 分钟采集 + 条件上报 + UART1 调试串口」改动在**固件域**内的需求分解。只覆盖传感器（CW32L010Y8M6）与网关（CH592 beiwov2）固件；Android/iOS/服务器/硬件不在本文。
输入来源：`readme.txt`（需求方，权威）、接口契约 IC-002 `artifacts/interface_contract.md` v3.0（CONTRACT_READY）、`sensor_hardware/` 网表与 BOM（硬件事实）、`gxht40.pdf`（器件手册）、本轮用户请求（基线 `1dd8e4b`、保留已有实现、只修复已证实问题、历史证据不作当前结果）、既有固件源码（参考输入）。

编号规则：`FWR-1xx`；每条给出需求、来源、可检验的验收行为。**本文不引入 readme 之外的产品行为**；readme 未定义处一律标注为设计决策或未决项，见 §4。

## 1. 功能需求

| ID | 需求 | 来源 | 可检验验收行为 |
|---|---|---|---|
| FWR-101 | 传感器固件使用 GXHT40 完成温湿度采集 | readme 修改点 1；gxht40.pdf | I²C 地址 0x44 或 0x45 均可被探测并读数；每个采样周期输出一次 `temp_x10`(int16, 0.1℃，有效域 -400..1250) 与 `hum_x10`(uint16, 0.1%RH, 0..1000)；温度字与湿度字各一次 CRC-8 校验；**真实目标每周期采集有效（对应 OBS-1 闭环）** |
| FWR-102 | 传感器固件经光敏电阻分压电路判定「无光」 | readme 修改点 2/7；`sensor_hardware/pstxnet.dat`、`MAIN_BOARD.BOM`；IC-002 §3 | 每次采样周期输出光照结果 `{valid, adc_ok, samples_ok, mean_adc_code, code_min, code_max, dark}`：PB05 供电、PB04/AIN11 多次取样取均值、采样后 PB05 回低；`dark = valid AND 3*mean_adc_code >= C_dark`（C_dark = 完全遮光实板基准码），整数运算、边界相等为暗、**每笔独立、无滞回或历史暗态** |
| FWR-103 | 采集周期改为 3 分钟 | readme 修改点 3 | 相邻两次温湿度/光照测量的间隔为 3 分钟（RTC 1 分钟节拍累计 3 次触发）；同一周期内不重复测量 |
| FWR-104 | 上报规则：本次有效温度比上次有效温度**高**超过 0.9℃ 且无光，或温度**严格超过** 35.0℃ | readme 修改点 4；IC-002 §2 | 判定式 `report = 温湿度均有效 AND ((have_prev AND (int32)cur-(int32)prev > 9 AND 光照有效 AND dark) OR cur > 350)`；方向为升温；边界：恰好 +0.9℃ 不触发；恰好 35.0℃ 不满足超温分支但若同时满足升温分支（如 34.0→35.0、无光）仍触发；无前值时仅超温分支可触发 |
| FWR-105 | 不改变传感器→网关→手机的既有数据布局 | IC-002 §4/§5；readme「不需要修改硬件内容」 | 433 明文仍为 `uid(4) | temp_x10_LE(2) | hum_x10_LE(2) | crc16_LE(2)` 共 10 B 并沿用既有 Feistel 加密；BLE 每设备记录仍为 `id(4) | hum_x10_BE(2) | temp_x10_BE(2)` 共 8 B；光照状态、有效性与上报原因不上空口、不上 BLE |
| FWR-106 | 传感器保持纽扣电池可用的低功耗行为 | readme（CR2032 焊装供电）；项目常识 | 非采样期 MCU 深睡；GXHT40 待机；PB05 为低（分压无电流）；I²C 引脚释放；调试 UART 关闭；433 仅在满足判据时发射且有界超时 |
| FWR-115 | 传感器使用 UART1 作为调试串口，初始化并输出必要调试信息 | readme 修改点 8 | 上电初始化 UART1（PA06=`UART1_TXD`/PA05=`UART1_RXD`、9600 8N1）并打印启动横幅（固件标识/UID 前 4 字节/复位来源/串口参数）；每个采样周期在判定与发送之后打印一行 ≤96 B 的整数 `S` 轨迹（节拍、前一有效温度与存在标志、光照 valid/成功数/极值/均值/无光、温度 x10、湿度 x10、采样有效标志、上报判定、发送结果、重试计数）；打印后等 `TXE` 再等 `TXBUSY` 清零再关闭串口、唤醒后重新初始化；关闭串口只复位/关闭 UART1 与改写 PA05/PA06，**不得**复位 GPIOA、不得关闭 GPIOA 时钟、不得改动 PA03/PA04（软 I²C）与 PA07/PA08（SWD）；打印不改变采样/判定/发送结果 |
| FWR-116 | GXHT40 采集失败在真实目标上可诊断（无逻辑分析仪条件下的一手数据） | 本轮用户请求「q=0 需查明并验证」；现有资源仅 COM42 串口 | 上电横幅之后输出一条 `BUS` 诊断行：任何 I²C 事务前的 PA03/PA04 空闲电平 + 有界地址扫描（0x08..0x77）中收到 ACK 的 7bit 地址集合（无则 `none`）；温湿度测量失败的周期在 `S` 行之后输出一条 `G` 诊断行：本轮结果码、0x44/0x45 各自是否收到地址 ACK、最近一次读事务消耗的重读次数、整帧重测次数、最近一次成功读回的 6 字节（未读成功则占位）；各行 ≤96 B、仅整数/大写十六进制；诊断只观测不改变采样/判定/上报，成功周期输出与 FWR-115 冻结格式逐字节相同，采样间期仍无字节；探测不得写任何器件命令，NACK 后必须释放总线 |
| FWR-117 | 验收以**当前交付构建**的实板再观测为准 | 本轮用户请求「历史证据只作背景，不能冒充当前测试结果」；「针对当前构建确认观测」 | 每一项「可观测」验收的原始证据必须来自本轮交付构建在真实目标上的采集（`mdk_flash` 校验成功后的 COM42 原始字节、手机端读数）；不得引用更早提交/镜像的历史证据作为本轮通过依据；构建标识（提交 + 产物摘要）须与证据对应 |

## 2. 异常与边界需求

| ID | 需求 | 来源 | 可检验验收行为 |
|---|---|---|---|
| FWR-107 | 采集失败不得伪造数据、不得污染判定状态 | IC-002 §2/§3「读取失败不得构造 0 值或更新前值」 | GXHT40 I²C 超时/CRC 错/量程无效时按上限有界重试；整周期失败时不上报、不更新前一有效温度、不构造 0 值；温度/湿度输出保持上次有效值或由有效标志标记 |
| FWR-108 | 重启/断电后的首个样本行为确定 | IC-002 §2 接口生命周期决策 | 上电或复位后 `have_prev=false`，升温分支不成立，仅超温分支（>35.0℃）可上报；不强制上报首样本；恰好 35.0℃ 的首笔样本不上报 |
| FWR-109 | 判定使用「上次有效采集」而非历史窗口统计 | readme 修改点 4 原文「比上次采集的温度数据」；IC-002 §2 | 仅保存前一**有效**样本温度参与比较（跨失败周期保留）；不使用历史环、不使用湿度阈值或湿度变化参与上报决策；每次成功温湿度采样（含未上报或光照失败/无效）推进前值 |
| FWR-110 | 光照判据参数化、可标定，未标定时不得冒充无光；标定不得被无依据门槛阻塞 | IC-002 §3；readme 修改点 7；本轮用户请求（需要现场遮光时说明最小必要操作与时间窗口，不自加固定样本数量或额外仪器作为门槛） | 全暗基准 `C_dark` 与标定完成标志集中在单一配置头；`C_dark` 必须来自完全遮光、相同供电/ADC 参考/建立时间/平均策略的有效实测；缺少有效 `C_dark` 时 `valid=false`、升温分支关闭；不得用满量程、旧默认 350/250、有光读数或估算值冒充 `C_dark`；标定记录含板件标识、供电、遮光方式、原始样本分布（min/max/mean）、实际取样次数与配置版本；**不得**以固定样本数量、额外仪器或额外时长作为通过门槛；若有光读数与 `ceil(C_dark/3)` 分离不足，如实记录原始数值并作为阈值/器件问题交接，不得修改判据掩盖 |
| FWR-113 | ADC 转换失败不得合成暗态 | IC-002 §3 | 全部转换超时 → `samples_ok=0`、`adc_ok=false`、`mean/min/max=0`、`valid=false`、`dark=false`，不得用满量程合成暗态；部分成功可沿用实际成功转换的均值并记录成功数；光照失败不影响超温分支（温湿度有效时仍可上报） |
| FWR-114 | 待上报样本在重试期间保持身份一致，且原待上报样本不被新触发覆盖 | IC-002 §2；FWR-105 | 置待上报时冻结当次温湿度与 ID 快照；有界重试期间（含跨 3 分钟周期）组帧只读该快照，帧内容逐字节一致，不因新采样、前值推进或最近有效湿度变化而改变；待上报未清除期间新的触发不得覆盖原有冻结样本；仅发送成功才清除；重试用尽放弃本轮且不伪造成功；帧布局/字节序/单位不变，不新增光照/原因/时间字段 |
| FWR-118 | 采集失败后必须重新探测候选地址并做有界总线恢复 | IC-002 §3；本轮 OBS-1 定位需要 | 任一测量失败（含缓存地址读失败、CRC 错、读 NACK 用尽）后，下一周期必须重新探测 0x44/0x45 并先执行有界总线恢复（如 9 个 SCL 脉冲 + STOP）；不得因缓存地址使器件永久失联；恢复与重试均有上限，不无限等待 |

## 4. 未决项（不在本能力内静默决定）
