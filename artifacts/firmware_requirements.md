# 固件需求（FWR-002）

状态：固件方案设计的伴随需求视图（firmware_engineer.firmware_solution_design）
版本：3.0（替代 rev 2.0；按 IC-002 v3.0 更正上报方向、35.0℃ 边界、光敏 1/3 全暗判据与光照有效性）
范围：本次「GXHT40 替换温湿度传感器 + 光敏分压 + 3 分钟采集 + 条件上报」改动在**固件域**内的需求分解。只覆盖传感器（CW32L010Y8M6）与网关（CH592 beiwov2）固件；Android/iOS/服务器/硬件不在本文。
输入来源：`readme.txt`（需求方，权威）、接口契约 IC-002 `artifacts/interface_contract.md` v3.0（CONTRACT_READY）、`sensor_hardware/` 网表与 BOM（硬件事实）、`gxht40.pdf`（器件手册）、既有固件源码（参考输入）。

编号规则：`FWR-1xx`；每条给出需求、来源、可检验的验收行为。**本文不引入 readme 之外的产品行为**；readme 未定义处一律标注为设计决策或未决项，见 §4。

> rev 3.0 更正说明：rev 2.0（及既有实现的 fw_core.c:105–121）把修改点 4 误读为「温度较上次**下降** 0.9℃」，并整体排除恰好 35.0℃。IC-002 v3.0 §2 与 readme 原文「本次采集到的温度数据比上次采集的温度数据**大于** 0.9℃」一致规定方向为**升温**，且恰好 35.0℃ 仍可经升温分支上报。光敏判据由旧 350/250 滞回改为「全暗基准 C_dark 的 1/3、每笔独立、无滞回」，并增加光照有效性。

## 1. 功能需求

| ID | 需求 | 来源 | 可检验验收行为 |
|---|---|---|---|
| FWR-101 | 传感器固件使用 GXHT40 完成温湿度采集 | readme 修改点 1；gxht40.pdf | I²C 地址 0x44 或 0x45 均可被探测并读数；每次采样周期输出一次 `temp_x10`(int16, 0.1℃，范围 -400..1250) 与 `hum_x10`(uint16, 0.1%RH, 0..1000)；CRC 校验分别覆盖温度字与湿度字 |
| FWR-102 | 传感器固件经光敏电阻分压电路判定「无光」 | readme 修改点 2/7；`sensor_hardware/pstxnet.dat`、`MAIN_BOARD.BOM`；IC-002 §3 | 每次采样周期输出一次光照结果 `{valid, mean_adc_code, dark}`：PB05 供电、PB04/AIN11 多次采样取均值、采样后 PB05 回到低电平；`dark = valid AND 3*mean_adc_code >= C_dark`（C_dark = 完全遮光实板基准码），整数运算、边界相等为暗、**每笔独立判断、不使用滞回或历史暗态** |
| FWR-103 | 采集周期改为 3 分钟 | readme 修改点 3 | 相邻两次温湿度/光照测量的间隔为 3 分钟（RTC 1 分钟节拍累计 3 次触发）；同一周期内不重复测量 |
| FWR-104 | 上报规则改为：本次有效温度比上次有效温度**高**超过 0.9℃ 且无光，或温度**严格超过** 35.0℃ | readme 修改点 4；IC-002 §2 | 判定式 `report = valid_sample AND ((have_prev AND (int32)cur-(int32)prev > 9 AND light_valid AND dark) OR cur > 350)`；方向为升温；边界：恰好 +0.9℃ 不触发；恰好 35.0℃ 不满足超温分支，但若同时满足升温分支（如 34.0→35.0、无光）则触发；无前值时仅超温分支可触发 |
| FWR-105 | 不改变传感器→网关→手机的既有数据布局 | IC-002 §4/§5；readme「不需要修改硬件内容」 | 433 明文仍为 `uid(4) | temp_x10_LE(2) | hum_x10_LE(2) | crc16_LE(2)` 共 10 B 并沿用 Feistel 加密；BLE 每设备记录仍为 `id(4) | hum_x10_BE(2) | temp_x10_BE(2)` 共 8 B；光照状态、有效性与上报原因不上空口、不上 BLE |
| FWR-106 | 传感器保持纽扣电池可用的低功耗行为 | readme（CR2032 焊装供电）；项目常识 | 非采样期 MCU 深睡；GXHT40 处于待机；PB05 为低（分压无电流）；I²C 引脚不主动拉低；调试 UART 关闭；433 仅在满足判据时发射且有界超时 |

## 2. 异常与边界需求

| ID | 需求 | 来源 | 可检验验收行为 |
|---|---|---|---|
| FWR-107 | 采集失败不得伪造数据、不得污染判定状态 | IC-002 §2/§3「读取失败不得构造 0 值或更新前值」 | GXHT40 I²C 超时/CRC 错时按上限有界重试；整周期失败时不上报、不更新前一有效温度、不构造 0 值；温度/湿度输出保持上次有效值或明确无效标志 |
| FWR-108 | 重启/断电后的首个样本行为确定 | IC-002 §2 接口生命周期决策 | 上电或复位后 `have_prev=false`，升温分支不成立，仅超温分支（>35.0℃）可上报；**不**强制上报首样本；恰好 35.0℃ 的首笔样本不上报 |
| FWR-109 | 判定使用「上次有效采集」而非历史窗口统计 | readme 修改点 4 原文「比上次采集的温度数据」；IC-002 §2 | 仅保存前一**有效**样本温度参与比较（跨失败周期保留）；不使用 20 项历史环、不使用湿度阈值/湿度下降参与上报决策；每次成功温湿度采样（含未上报或光照失败）推进前值 |
| FWR-110 | 光照判据参数化、可标定，且未标定时不得冒充无光 | IC-002 §3；readme 修改点 7 | 全暗基准 `C_dark` 与标定完成标志集中在单一配置头；`C_dark` 必须来自完全遮光、相同供电/参考/建立时间/平均策略的有效实测；缺少有效 `C_dark` 时 `light_valid=false`、标定状态未完成，升温分支关闭；不得用满量程、旧默认 350/250 或当前亮态值冒充全暗标定 |
| FWR-113 | ADC 转换失败不得合成暗态 | IC-002 §3 | 全部转换超时 → `light_valid=false`、`dark=false`，不得用满量程合成暗态；部分成功可沿用实际成功转换的均值并记录成功数；失败不影响超温分支（温湿度有效时仍可上报） |
| FWR-114 | 待上报样本在重试期间保持身份一致 | IC-002 §2 | 置待上报时冻结当次温湿度与 ID 快照；有界重试期间帧内容必须与该快照一致，不因新采样推进前值而改变；仅发送成功才清除；重试用尽放弃本轮 |

## 3. 兼容与退役需求（由新硬件推导，非新增产品行为）

| ID | 需求 | 来源 | 可检验验收行为 |
|---|---|---|---|
| FWR-111 | 退役与新硬件冲突的旧配置通路 | `sensor_hardware/pstxnet.dat`：PB04=LIGHT_ADC、PB05=LIGTHT_POWER、PB06=NC；BOM 无霍尔器件 | 固件不再把 PB04 配置为霍尔 EXTI 输入、不再把 PB05 配置为数字输入、不再使用 PB06；hall/OPTCFG/params/history 相关初始化、中断与 NVM 写 Flash 路径从工程移除；PB04 仅作 AIN11 模拟输入、PB05 仅作光照供电输出 |

## 4. 未决项（不在本能力内静默决定）

| ID | 未决内容 | 影响 | 处置 |
|---|---|---|---|
| FWR-OPEN-1 | 完全遮光基准 `C_dark` 的实板标定值 | 决定「无光」判定正确性；未标定则升温分支不可用 | 设计给出机制、极性（暗=码高）与标定/回填方法；数值由实板标定后回填配置头并置 `LIGHT_DARK_CALIBRATED=1`；标定记录须含板件、供电、遮光环境、原始样本分布、配置版本 |
