## 0. rev 8 变更摘要

1. 最新 `readme.txt` 第 7 点只声明“当前的情况是有光的”，**已不含“无光阈值取完全无光的 1/3”**；同时新增“不能调节温度、不能改变光强、不能测功耗，涉及这些功能不要安排相关硬件的测试设计与执行”。rev 7 以“现场无光 + 待受光/全遮光双态标定”为前提的需求条目据此重写。
2. **LIGHT-DEF-1（1/3 判据）退役**：要求受光均值 ≤ `C_dark/3` ≤ 1365 码，而实测声明受光最低 3061、房间灯 3514（去重 103 条 `S` 行统计），无任何合法 `C_dark` 可区分 → 该形式不可实现，不再作为实现/标定目标。
3. 新增 **FWR-121 LIGHT-DEF-2（绝对阈值形制）** 与 **FWR-122 启用门禁**：单一常量 `T`（0 = 未启用），候选 3590、可用带 (3514, 3660]，启用需接受记录 + 同机同位置被动双态证据。
4. 新增 **FWR-123 本阶段测试边界**：不设计、不执行调温、改变光强、遮光作为刺激、功耗测量等硬件实验；相关终验保留为未执行/后续阶段。
5. 修订 FWR-110/FWR-120：删除“受光 + 受控全遮光双态标定”作为唯一路径，改为“形制可审查 + 数值有来源 + 证据齐备才启用；分离不足升级决策，不改判据”。
6. 保留 FWR-101/103/104/105/106/107/108/109/111..119 与 FWR-112（网关）不变；T1–T4/F-1 已实现部分继续冻结为回归基线。

## 3. 异常与边界需求

| ID | 需求 | 来源 | 可检验验收行为 |
|---|---|---|---|
| FWR-107 | 采集失败不得伪造数据、不得污染判定状态 | IC-002 §3 | GXHT40 超时/CRC 错/量程无效按上限有界重试；整周期失败时不上报、不更新前一有效温度、不构造 0 值；温湿度输出保持上次有效值并由 `q=0` 标记 |
| FWR-108 | 重启/断电后的首个样本行为确定 | IC-002 §3.2 | 上电/复位后 `have_prev=false`，升温分支不成立，仅超温分支（>35.0℃）可上报；不强制上报首样本；恰好 35.0℃ 的首笔样本不上报 |
| FWR-109 | 判定使用「上次有效采集」而非历史窗口统计 | readme 修改点 4；IC-002 §3.2 | 仅保存前一**有效**样本温度（跨失败周期保留）；不使用历史环、湿度阈值或湿度变化参与判定；每次成功温湿度采样（含未上报或光照无效）推进前值 |
| FWR-113 | ADC 转换失败不得合成暗态 | IC-002 §4.2 | 全部转换超时 → `samples_ok=0`、`adc_ok=false`、`mean/min/max=0`、`valid=false`、`dark=false`；不得用满量程合成暗态；部分成功沿用实际成功样本均值并记录成功数；光照失败不影响超温分支 |
| FWR-114 | 待上报样本在重试期间保持同一笔读数，且原待上报不被新触发覆盖 | IC-002 §3.2 | 置待上报时冻结当次温湿度（与 ID）快照；有界重试期间（含跨 3 分钟周期）组帧只读快照，帧内容逐字节一致；待上报未清除期间新触发不得覆盖；仅发送成功才清除；用尽放弃且不伪造成功；`P` 行（`rq/s/y/t/h`）可观测实际组帧样本且 ≤96 B、不改变业务状态 |
| FWR-118 | 采集失败后必须重新探测候选地址并做有界总线恢复 | IC-002 §4.1 | 任一测量失败（含缓存地址读失败、CRC 错、读 NACK 用尽）后，下一周期重新探测 0x44/0x45，并在重探前执行有界恢复（9 个 SCL 脉冲 + STOP）；不得因缓存地址使器件永久失联；恢复与重试均有上限 |
