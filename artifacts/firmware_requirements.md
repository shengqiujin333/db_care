# 传感器/中继器固件需求（FR-001）

状态：固件设计产物（firmware_engineer.firmware_solution_design）
版本：1.0
对象：蹬被报警器**传感器固件（CW32L010Y8M6，本次主要改动）** 与 **中继器固件（CH592 beiwov2，兼容性改动）**。Android 侧（闪光灯设参）由后续 Android 能力依据 IC-001 承接，不在本需求清单内实现。
上游输入：
- 需求：readme.txt（霍尔检测磁铁、GPIO 供电光敏接收手机闪光灯、6 个 float 阈值、1 min 测量、约 20 min 缓冲、超阈值立即上报/平时 1 h 上报）
- 接口契约：artifacts/interface_contract.md（IC-001，已验证）
- 硬件接口：artifacts/hardware_interface.md（HWI-001）、artifacts/hardware_solution.md（HW-001）、artifacts/schematic.md（SCH-001，引脚核定 PB04/PB05/PB06）

优先级：P0=本功能必须；P1=应有（可缺省但有验收影响）；P2=建议。

## 1. 配置会话与光学接收（OPTCFG/1）

| ID | 优先级 | 需求 | 来源 | 验收要点 |
|---|---|---|---|---|
| FR-101 | P0 | Hall 有效沿触发后，传感器给光敏前端（F2）供电并开启有界接收窗口；窗口超时/成功提交/连续 3 帧失败即断电。Hall 未触发时忽略光信号、F2 保持断电。 | IC-001 §3.1 | 深睡中 Hall 沿可唤醒；窗口内 PB06 使能、结束后恢复断电；未触发时 PB05 不采样 |
| FR-102 | P0 | 同一时间只存在一个配置会话：窗口活跃期间忽略再次 Hall 触发；会话结束后需新的有效沿才能开启新窗口。 | IC-001 §3.1/§1 | 单会话有界；二次触发不叠加窗口 |
| FR-103 | P0 | 接收端解码 OOK/Manchester：亮=1、灭=0；位周期 40 ms（0=亮20ms+灭20ms，1=灭20ms+亮20ms），允许半位宽 ±25%；16 字节 0x55 前导 + 35 B 字节帧，MSB-first。 | IC-001 §3.1/§3.2 | 对 40 ms 位与 ±25% 抖动健壮；相位锁定正确 |
| FR-104 | P0 | 帧校验链：magic(0x44 0x42)、version(0x01)、message_type(0x01)、payload_len(0x18)、CRC16-CCITT-FALSE(覆盖 0..32)、数值范围与关系约束全部通过才接受；未知 version/message_type 必须拒绝。 | IC-001 §3.2/§7 | 任一校验失败即整帧丢弃并复位解码器 |
| FR-105 | P0 | 六个参数按固定顺序、IEEE-754 binary32、little-endian 解析：temp_drop_c、humidity_drop_pct、temp_low_c、humidity_low_pct、temp_high_c、humidity_high_pct。NaN/±Inf/负零/越界/关系倒置（temp_low≥temp_high、hum_low≥hum_high）均拒绝。 | IC-001 §2/§3.2 | 互操作向量 [2.5,10,28,30,36,85] 正确解析 |
| FR-106 | P0 | 接收端先完整校验整帧，再以一次原子操作替换当前配置；失败时保留旧配置。 | IC-001 §2 | 配置仅在校验全通过后提交 |
| FR-107 | P0 | 与最近成功 transaction_id 相同的帧为幂等重放：不得重复写 Flash，但可结束会话。transaction_id 为 uint32 LE，Android 每次设置递增，0 禁用。 | IC-001 §3.2 | 重复帧不触发二次 Flash 写 |
| FR-108 | P1 | 配置更新写入带版本与 CRC 的非易失记录；掉电恢复只能装载校验通过的完整记录，否则装载编译期安全默认值并标记"未配置"。 | IC-001 §3.2/§7 | 掉电中断写入后上电仍能启动且回到默认/上次完整配置 |
| FR-109 | P2 | 解码器支持帧间暗区 500 ms：长暗区（>300 ms 无有效信号）复位同步状态，准备接收下一帧。 | IC-001 §3.1 | 3 帧连发中的间隔不产生伪解析 |

## 2. 参数模型与阈值语义

| ID | 优先级 | 需求 | 来源 | 验收要点 |
|---|---|---|---|---|
| FR-201 | P0 | 阈值使用严格越界：`current < low` 或 `current > high` 触发越界告警（六个参数中 temp 两阈值与 hum 两阈值分别判定）。 | IC-001 §2 | 恰好等于阈值不告警（严格不等） |
| FR-202 | P0 | 下降告警：最近 20 个有效的一分钟样本中，任一样本与当前值之差 ≥ `temp_drop_c` 或 ≥ `humidity_drop_pct` 即触发。 | IC-001 §2 | 回绕（≥20 样本）时仍按最近 20 项判定 |
| FR-203 | P0 | 任一告警条件成立立即上报；否则距离上次成功上报满 60 个采样周期上报；传感器重启后首个有效样本立即上报。 | IC-001 §2/readme | 立即/小时/首样本三条上报路径均验证 |
| FR-204 | P0 | 采样周期改为 1 min；历史环形缓冲固定 20 项、每项 4 B（int16 temp_x10 + uint16 hum_x10），共 80 B；仅成功测量写入。 | IC-001 §4/readme | 读取失败不写缓冲、不参与判定、不伪造 0 值 |
| FR-205 | P0 | 内部标准值：温度有符号 0.1 °C，湿度无符号 0.1 %RH；RAM 内阈值换算为 x10 整数参与比较，避免逐样本 float。 | IC-001 §2/§4 | 全部判定在整数域完成，结果与 float 一致 |

## 3. 上报与 433 链路

| ID | 优先级 | 需求 | 来源 | 验收要点 |
|---|---|---|---|---|
| FR-301 | P0 | 433 MHz 空口保持现有 10 B Feistel 帧：明文 `sensor_id(4) | temperature_x10(2,LE) | humidity_x10(2,LE) | crc16(2,LE)`，8 轮 Feistel + 系统密钥加密。 | IC-001 §5 | 与中继器 decode 互操作 |
| FR-302 | P0 | **修正** `encode_frame10` 调用实参顺序：现为 `(huminityvalue, tempvalue)`，须改为 `(tempvalue, huminityvalue)`，使线上温度字段=温度、湿度字段=湿度。 | IC-001 §5 | 端到端温湿度数值正确（配合中继器记录顺序调整，见 FR-401） |
| FR-303 | P0 | 上报调度：立即上报=完成当前测量和帧编码后即启动 433 发送，不等小时定时器；发送失败不得记作成功上报。 | IC-001 §4 | 失败后成功计数不归零 |
| FR-304 | P1 | 发送失败策略：单次发送失败可重试（有界次数 + 退避）；重试仍失败则保留待上报状态，小时调度器下一次自然重试；不得将失败计入"成功上报"。 | IC-001 §4 | 连续失败不阻塞后续采样/睡眠 |
| FR-305 | P1 | 配置窗口活跃期间若有待发送的 433 帧，延后到窗口结束再发（避免 433 突发与 F2 前端电流叠加，且 LPTIM 为两功能共享资源）。 | HW-001 §4/IC-001 | 窗口与 433 发送互斥时序正确 |

## 4. 中继器（CH592 beiwov2）兼容

| ID | 优先级 | 需求 | 来源 | 验收要点 |
|---|---|---|---|---|
| FR-401 | P0 | 中继器按契约明文布局解码 `temperature_x10 | humidity_x10`；**BLE 每设备记录调整为 IC-001 §6 顺序 `sensor_id(4) | humidity_x10_be(2) | temperature_x10_be(2)`**。当前中继器 `sensorres` 变量序为 `[id|tempervalue|humivalue]`（受传感器实参颠倒影响，其值实为 `[id|湿度|温度]`，与 Android 期望恰好一致）；**传感器实参修正后该记录将变为 `[id|温度|湿度]`，须同步交换第 4..7 字节为 `[id|湿度|温度]`**，与传感器修正一起落地，否则 Android 读到交换值。 | IC-001 §5/§6 | 传感器修正 + 中继器顺序调整后，Android 现有 `parsePlainFrame`（u16be@4/s16be@6）无需改动即正确 |
| FR-402 | P0 | 保持现有 433 解码（EV1527/UM2006A）、Feistel 解密、CRC 校验、绑定表与 BLE GATT（FFE0/FFE2/FFE3）兼容；不承担光学配置转发。 | IC-001 §6/§8 | 旧 Android/中继器不因本功能失效 |
| FR-403 | P0 | 中继器对未知 version/message_type/长度/命令一律丢弃，不得猜测解析。 | IC-001 §7 | 异常帧不影响绑定与上报 |

## 5. 功耗、资源与异常

| ID | 优先级 | 需求 | 来源 | 验收要点 |
|---|---|---|---|---|
| FR-501 | P0 | 常态深睡总电流目标 <10 µA（新增 F1 Hall 约 8 µA + F2 断电≈0）；配置窗口 30–35 s 持续 <2 mA；433 突发保持现状。 | HW-001 §4/SCH-001 §4 | 深睡与窗口电流预算满足 CR2032 寿命预期 |
| FR-502 | P0 | RAM 预算：新增 ≤300 B（历史 80 B + 参数 ~32 B + 解码缓冲 ~64 B + 状态 ~96 B），总体 <4 KB SRAM 的 60%。 | IC-001 §4/readme（看 ram 情况） | 编译后 RAM 用量记录在案 |
| FR-503 | P0 | 所有跨 MCU 多字节字段按契约显式字节序处理，不得用结构体裸拷贝。 | IC-001 §7 | CRC/字节序互操作向量通过 |
| FR-504 | P0 | 日志不得记录系统密钥；密钥轮换/设备认证由独立安全设计承接。 | IC-001 §7 | 固件日志无密钥明文 |
| FR-505 | P1 | 读取 AHT 失败属诊断状态：不写缓冲、不判定、不伪造 0 值遥测；连续失败计数用于诊断。 | IC-001 §4 | 传感器故障时不产生误导告警 |
| FR-506 | P1 | Hall 输入去抖（约 5–10 ms）防止噪声误触发；触发极性（有效沿）按 Hall 器件输出结构以编译期宏配置。 | HWI-001 §2 | 噪声不误开配置窗口 |
| FR-507 | P2 | 上电/复位默认安全：PB06 默认输出高（F2 断电），PB05 输入不采样，PB04 输入+中断，参数默认值为编译期安全默认。 | SCH-001 §3/IC-001 | 复位后无意外使能 F2 |

## 7. 与本能力边界的关系

- 本需求清单只定义**传感器/中继器固件需求**，不包含 Android 闪光灯设参实现（后续 Android 能力依据 IC-001 承接）。
- 需求来源均为 readme/IC-001/HWI-001/HW-001/SCH-001；未新增产品需求，仅将既有契约转化为可实现的固件需求。
- 固件实现、单元测试、联调分别由后续固件实现与嵌入式测试能力负责。
