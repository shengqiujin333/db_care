## 1. 功能需求

| ID | 需求 | 来源 | 可检验验收行为 |
|---|---|---|---|
| FWR-101 | 传感器固件使用 GXHT40 完成温湿度采集 | readme 修改点 1；gxht40.pdf | I²C 地址 0x44 或 0x45 均可被探测并读数；每采样周期输出一次 `temp_x10`（int16，0.1℃，有效域 −400..1250）与 `hum_x10`（uint16，0.1%RH，0..1000）；温度字与湿度字各一次 CRC-8；**真实目标连续多周期采集有效** |
| FWR-102 | 传感器经光敏电阻分压判定「无光」 | readme 修改点 2/7；网表/BOM；IC-002 §3 | 每采样周期输出 `{valid, adc_ok, samples_ok, mean_adc_code, code_min, code_max, dark}`：PB05 供电、PB04/AIN11 多次取样、采样后 PB05 回低；`dark = valid AND 3·mean >= C_dark`；整数运算、边界相等为暗、每笔独立、无滞回 |
| FWR-103 | 采集周期改为 3 分钟 | readme 修改点 3 | 相邻两次温湿度/光照测量间隔为 3 分钟（RTC 1 分钟节拍累计 3 次触发）；同一周期不重复测量 |
| FWR-104 | 上报规则：本次有效温度比上次有效温度**高**超过 0.9℃ **且无光**，或温度**严格超过** 35.0℃ | readme 修改点 4；IC-002 §2 | `report = 温湿度均有效 AND ((have_prev AND int32(cur)-int32(prev) > 9 AND 光照有效 AND dark) OR cur > 350)`；方向为升温；恰好 +0.9℃ 不触发；恰好 35.0℃ 不满足超温分支，但若同时满足升温分支仍触发；无前值时仅超温分支可触发；降温恒不触发 |
| FWR-105 | 不改变传感器→网关→手机的既有数据布局 | IC-002 §4/§5；readme「不修改硬件」 | 433 明文仍为 `uid(4), temp_x10_LE(2), hum_x10_LE(2), crc16_LE(2)` 共 10 B 并沿用既有 Feistel；BLE 每设备仍为 `id(4), hum_x10_BE(2), temp_x10_BE(2)` 共 8 B；光照/有效性/上报原因不上空口、不上 BLE |
| FWR-106 | 保持 CR2032 可用的低功耗行为 | readme（焊装纽扣电池）；项目常识 | 非采样期 MCU 深睡；GXHT40 待机；PB05 为低；I²C 释放；UART 关闭；433 仅在满足判据时发射且有界超时；不新增周期唤醒 |
| FWR-115 | 传感器使用 UART1 作调试串口，初始化并输出调试信息 | readme 修改点 8 | 上电初始化 UART1（PA06=TXD/PA05=RXD，9600 8N1）并打印横幅（固件标识/UID 前 4 字节/复位来源/波特率）；每采样周期在判定与发送后打印一行 ≤96 B 整数 `S` 轨迹（节拍/前值/光照/温湿度/采样有效/上报判定/发送结果/重试）；打印后有界排空并关闭；唤醒后重开；关闭只碰 UART1/PA05/PA06，不得复位 GPIOA/关 GPIOA 时钟/改 PA03/PA04/PA07/PA08；打印不改变业务结果 |
| FWR-116 | GXHT40 采集失败在真实目标上可诊断（无逻辑分析仪条件下的一手数据） | 本轮系统分析；现有 COM43 串口 | 上电后输出 `VDD`（供电轨）、`IOTEST`（拉低/回读/角色对调）、`IOSIG`（事务内逐位回读）、`BUS`（空闲电平 + 0x08..0x77 有界地址扫描 ACK 集合）各一次；温湿度失败周期在 `S` 后输出 `G`（结果码/0x44 与 0x45 ACK/重读次数/整帧重测次数/最近成功读回的 6 字节）；各行 ≤96 B、仅整数/大写十六进制；诊断不改变采样/判定/上报，成功未上报周期与冻结 `S` 行逐字节一致，采样间期无字节；探测不写器件命令、NACK 后释放总线 |
| FWR-117 | 验收以**当前交付构建**的实板再观测为准 | 本轮系统分析与需求方约束 | 每项「可观测」验收的原始证据必须来自本轮交付构建在真实目标上的采集（构建摘要 + 下载校验 + **COM43/9600 8N1** 原始字节 + 手机端读数）；不得引用更早提交/镜像/COM42 的历史证据作为本轮通过依据；构建标识须与证据对应 |
| FWR-119 | 调试发送等待必须有界，诊断故障不得阻塞采样/深睡 | 本轮系统分析（`debug_trace.c` 静态关注） | `TXE` 与 `TXBUSY` 等待均有计数上限（单一配置点，按 9600 8N1 行长推算并留余量）；超时后放弃本行剩余输出并完成 UART1 关闭流程，返回主循环继续采样/深睡；超时不修改 `report_req`/前值/冻结快照/发送结果，不复位 GPIOA；正常硬件路径输出字节不变 |

## 2. 异常与边界需求

| ID | 需求 | 来源 | 可检验验收行为 |
|---|---|---|---|
| FWR-107 | 采集失败不得伪造数据、不得污染判定状态 | IC-002 §2/§3 | GXHT40 超时/CRC 错/量程无效按上限有界重试；整周期失败时不上报、不更新前一有效温度、不构造 0 值；温湿度输出保持上次有效值并由 `q=0` 标记 |
| FWR-108 | 重启/断电后的首个样本行为确定 | IC-002 §2 生命周期决策 | 上电/复位后 `have_prev=false`，升温分支不成立，仅超温分支（>35.0℃）可上报；不强制上报首样本；恰好 35.0℃ 的首笔样本不上报 |
| FWR-109 | 判定使用「上次有效采集」而非历史窗口统计 | readme 修改点 4 原文；IC-002 §2 | 仅保存前一**有效**样本温度（跨失败周期保留）；不使用历史环、湿度阈值或湿度变化参与判定；每次成功温湿度采样（含未上报或光照无效）推进前值 |
| FWR-110 | 光照判据参数化、可标定；未标定时不得冒充无光；标定不得被无依据门槛阻塞 | IC-002 §3；readme 修改点 7 | `C_dark` 与标定完成标志集中在单一配置头；`C_dark` 必须来自完全遮光、相同供电/ADC 参考/建立时间/平均策略的有效实测；缺少有效 `C_dark` 时 `valid=false`、升温分支关闭；不得用满量程、旧默认 350/250、有光读数或估算值冒充；标定记录含板件标识、供电、遮光方式、原始样本分布（min/max/mean）、实际取样次数与配置版本；不得以固定样本数/额外仪器/额外时长作为通过门槛；有光读数与 `ceil(C_dark/3)` 分离不足时如实记录并作为阈值/器件问题交接，不得改判据 |
| FWR-113 | ADC 转换失败不得合成暗态 | IC-002 §3 | 全部转换超时 → `samples_ok=0`、`adc_ok=false`、`mean/min/max=0`、`valid=false`、`dark=false`；不得用满量程合成暗态；部分成功沿用实际成功样本均值并记录成功数；光照失败不影响超温分支 |
| FWR-114 | 待上报样本在重试期间保持同一笔读数，且原待上报不被新触发覆盖 | IC-002 §2；FWR-105 | 置待上报时冻结当次温湿度（与 ID）快照；有界重试期间（含若待上报跨越 3 分钟周期）组帧只读快照，帧内容逐字节一致，不因新采样、前值推进或最近湿度变化而改变；待上报未清除期间新触发不得覆盖原冻结样本；仅发送成功才清除；用尽放弃且不伪造成功；帧布局/字节序/单位不变；可用周期 `P` 行（`rq/s/y/t/h`）观测组帧实际使用的冻结样本，`P` 行 ≤96 B 且不改变业务状态 |
| FWR-118 | 采集失败后必须重新探测候选地址并做有界总线恢复 | IC-002 §3 | 任一测量失败（含缓存地址读失败、CRC 错、读 NACK 用尽）后，下一周期必须重新探测 0x44/0x45，并在重探前执行有界恢复（如 9 个 SCL 脉冲 + STOP）；不得因缓存地址使器件永久失联；恢复与重试均有上限，不无限等待 |
