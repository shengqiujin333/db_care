# 固件需求（FWR-002）

状态：固件方案设计的伴随需求视图（firmware_engineer.firmware_solution_design）
版本：2.0（与 FD-002 rev 2.0 同步重发）
范围：本次「GXHT40 替换温湿度传感器 + 光敏分压 + 3 分钟采集 + 条件上报」改动在**固件域**内的需求分解。只覆盖传感器（CW32L010Y8M6）与网关（CH592 beiwov2）固件；Android/iOS/服务器/硬件不在本文。
输入来源：`readme.txt`（需求方，权威）、接口契约 IC-002（`artifacts/interface_contract.md`，已批准上游产物）、`sensor_hardware/` 网表与 BOM（新硬件事实）、`gxht40.pdf`（器件手册）、既有固件源码（参考输入）。

编号规则：`FWR-1xx`；每条给出需求、来源、可检验的验收行为。**本文不引入 readme 之外的产品行为**；readme 未定义处一律标注为设计决策或未决项，见 §4。

## 1. 功能需求

| ID | 需求 | 来源 | 可检验验收行为 |
|---|---|---|---|
| FWR-101 | 传感器固件使用 GXHT40 完成温湿度采集 | readme 修改点 1；gxht40.pdf | I²C 地址 0x44 或 0x45 均可被探测并读数；每次采样周期输出一次 `temp_x10`(int16, 0.1℃，范围 -400..1250) 与 `hum_x10`(uint16, 0.1%RH, 0..1000)；CRC 校验覆盖温度字与湿度字 |
| FWR-102 | 传感器固件经光敏电阻分压电路判定「无光」 | readme 修改点 2；`sensor_hardware/pstxnet.dat`、`MAIN_BOARD.BOM` | 每次采样周期输出一次布尔光照判据：PB05 供电、PB04/AIN11 采样；**读数 ≥ 阈值判为无光（DARK）**；采样后 PB05 回到低电平 |
| FWR-103 | 采集周期改为 3 分钟 | readme 修改点 3 | 相邻两次温湿度/光照测量的间隔为 3 分钟（RTC 1 分钟节拍累计 3 次触发）；同一周期内不重复测量 |
| FWR-104 | 上报规则改为：温度较上次下降超过 0.9℃ 且无光，或温度超过 35.0℃ | readme 修改点 4；IC-002 §2 | 判定式 `report = ((prev_temp_x10 - cur_temp_x10) > 9) && DARK || (cur_temp_x10 > 350)`；边界：恰好 0.9℃ 不触发（IC-002 严格解释）；恰好 35.0℃ 不触发 |
| FWR-105 | 不改变传感器→网关→手机的既有数据布局 | IC-002 §3/§4；readme「不需要改硬件」 | 433 明文仍为 `uid(4) | temp_x10_LE(2) | hum_x10_LE(2) | crc16_LE(2)` 共 10 B 并沿用 Feistel 加密；BLE 每设备记录仍为 `id(4) | hum_x10_BE(2) | temp_x10_BE(2)` 共 8 B；光照状态不上空口、不上 BLE |
| FWR-106 | 传感器保持纽扣电池可用的低功耗行为 | readme（CR2032 焊装供电）；项目常识 | 非采样期 MCU 深睡；GXHT40 处于待机；PB05 为低（分压无电流）；I²C 引脚不主动拉低；调试 UART 关闭；433 仅在满足判据时发射且有界超时 |

## 2. 异常与边界需求

| ID | 需求 | 来源 | 可检验验收行为 |
|---|---|---|---|
| FWR-107 | 采集失败不得伪造数据、不得污染判定状态 | IC-002 §2「读取失败不得构造 0 值或更新前值」 | GXHT40 I²C 超时/CRC 错时按上限有界重试；整周期失败时不上报、不更新前一有效温度、不推进「无光」缓存；温度/湿度输出保持上次有效值或明确无效标志 |
| FWR-108 | 重启/断电后的首个样本行为确定 | IC-002 §7 待确认项 3（本能力确认） | 上电或复位后无「前一次有效温度」，下降分支不成立，仅超温分支（>35.0℃）可上报；**不**强制上报首样本 |
| FWR-109 | 判定使用「上次采集」而非历史窗口统计 | readme 修改点 4 原文「比上次采集的温度数据」 | 仅保存前一有效样本温度参与比较；不使用 20 项历史环、不使用湿度阈值/湿度下降参与上报决策 |
| FWR-110 | 光照判据稳定、可校准 | IC-002 §7 待确认项 1（本能力给出机制与校准要求） | 阈值与滞回集中在单一配置头；阈值数值必须由实板实测标定；AD 读数达满量程（疑似光敏器件未装/失效）时给出确定行为（见设计 §11） |

## 3. 兼容与退役需求（由新硬件推导，非新增产品行为）

| ID | 需求 | 来源 | 可检验验收行为 |
|---|---|---|---|
| FWR-111 | 退役与新硬件冲突的旧配置通路 | `sensor_hardware/pstxnet.dat`：PB04=LIGHT_ADC、PB05=LIGTHT_POWER、PB06=NC；BOM 无霍尔器件 | 固件不再把 PB04 配置为霍尔 EXTI 输入、不再把 PB05 配置为数字输入、不再使用 PB06；OPTCFG/hall/params 相关初始化、中断与 NVM 写 Flash 路径从工程移除；PB04 仅作 AIN11 模拟输入、PB05 仅作输出 |
| FWR-112 | 网关固件对新传感器帧保持兼容 | IC-002 §3/§4；既有网关源码 | 网关按 `temp=p[4..5]`、`hum=p[6..7]` 解密；BLE 记录按 `id | hum_be | temp_be` 组装；网关**不得**再按自身温度历史二次过滤上报 |

## 4. 未决项（不在本能力内静默决定）
