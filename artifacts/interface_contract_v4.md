## 2. IF01：温湿度与光照内部结果（B01）

### 2.1 GXHT40 → 采样事务

现有API：`gxht40_init(i2c_dev*)`仅绑定并清探测缓存；`gxht40_measure(int16_t *temp_x10,uint16_t *hum_x10)`返回gxht40_status_t；成功才同时写输出，失败不修改调用方输出。`gxht40_detected_addr7()`返回7bit地址或0（未探测）；`gxht40_diag_fetch()`只读诊断，不发总线请求。

| 字段/结果 | 编码/单位 | 有效性与所有权 |
|---|---|---|
| temp_x10 | int16，0.1℃，-400..1250 | 仅status=0有效；0是合法数值 |
| hum_x10 | uint16，0.1%RH，0..1000 | 仅status=0有效；0/1000合法 |
| status | 0 OK；1 PARAM；2 NO_DEVICE；3 IO；4 CRC；5 RANGE | 失败整笔不判定/不推进prev/不发RF；不得用保留输出冒充本次新样本 |
| diag | status/ack44/ack45/read_retry/attempt/raw_valid/raw[6] | ACK0/1，重读0..5，尝试上限3；raw_valid说明成功读回而非CRC通过；不能把raw当已验证业务数据 |

现有周期事务：7bit 0x44/45（写地址0x88/8A，读地址0x89/8B），写0xFD、等待10ms、读6B。回包依次`T_MSB T_LSB T_CRC RH_MSB RH_LSB RH_CRC`；原始字大端。CRC8分别覆盖两字节，poly0x31/init0xFF/non-reflected/xorout0；参考`BE EF→92`。任一CRC错整笔无效。

现有整数换算：`T=-450+((1750*rawT+32768)>>16)`；`RH=clip(-60+((1250*rawRH+32768)>>16),0,1000)`；用足够宽整数计算。温度超域拒绝，不写输出；湿度按上述规则裁剪。该换算对齐当前源码，器件真实准确度仍需专业证据，不从转换函数推出实板采集通过。

有界配置：首次访问余量2ms；测量等待10ms；READ_RETRY=5、间隔1ms；MEAS_RETRY=3。这些是驱动循环配置，不把“重试5”擅改成另加5次的新循环，也不从宏值推算全部事务总耗时。周期禁止使用加热或软复位指令；既有启动诊断中一次性general-call恢复与周期测量分开，本文不新增主机控制接口。失败后下周期有界总线恢复并重探；目标不响应保持具体失败，不猜替代地址。

### 2.2 光照 → 采样事务

现有API：`light_result_t light_sample(void)`，不是旧bool接口；`light_init()`准备PB05供电输出低、PB04/AIN11模拟输入。PB06不用，硬件不改。

| 字段 | 类型/域 | 规范不变量 |
|---|---|---|
| adc_ok | bool | samples_ok>0 |
| samples_ok | uint8，0..8 | 成功转换数；不是尝试次数 |
| mean_adc_code | uint16，0..4095 | 成功样本整数算术均值，当前实现使用整数除法；无成功样本为诊断占位0 |
| code_min/code_max | uint16，0..4095 | 有成功样本时min<=mean<=max；无成功样本均0 |
| valid | bool | adc_ok && 标定有效；C_dark必须同板实测且1..4095 |
| dark | bool | valid && uint32(3)*mean>=C_dark；每笔独立无滞回 |

PB05高→等待100ms→最多8次转换并只平均成功值→关ADC/PB05低。全失败：adc_ok=false、samples_ok=0、valid=false、dark=false；不得把占位0解释为有效光照，更不能用4095回退。未标定可保留真实ADC诊断值，但valid/dark均false；源码当前LIGHT_DARK_REF_CODE=0、CALIBRATED=0是未完成状态，不是标定值。

无光阈值为`ceil(C_dark/3)`，等号判暗。C_dark=4000→阈值1334只是算术例子，不是项目标定结果。标定责任提供板号、固件/配置版本、供电、遮光方法、取样策略及亮暗原始分布；按PACC PA-005/031核对有光均值L满足`C_dark>3*L`等可分离条件。不能用当前有光785、满量程或旧350/250代替全暗；不满足时交产品处理，不改规则伪通过。

## 3. IF02：门控、发送快照与周期生命周期（B02）

生产者C04，消费者C05/C06。每个180s机会形成一笔业务采样结果；上电允许一次立即采样机会，不强制上报。prev只存RAM，复位have_prev=false。

规范：

```text
report = sample_valid && (
    cur_x10 > 350 ||
    (have_prev && light.valid && light.dark && int32(cur_x10)-int32(prev_x10)>9))
```

`sample_valid`只表示温湿度有效；湿度不参与触发。判定使用更新前prev/have_prev；每笔有效温湿度采集判定后都更新prev，即使不报/光照无效/发送失败；采集失败不更新。不按上次上报温度比较。

触发时冻结同次ID/T/RH，RF重试期间不更换样本、不再次采样/判定、不更新第二次prev；最多3次、每次200ms本地超时，用尽结束本周期，不保留跨周期发送队列。一次触发的多个发送尝试不算多次触发；本地完成不是网关/App确认。下一周期按新采样自然判定，无强制补报。

实现/验证消费的14规范向量沿用PDR：+0.8/+0.9不报；暗+1.0报；亮/无效+1.0不报；降温不报；暗34→35报；亮34→35不报；无前值35.0不报、35.1/36.0报；35.2→35.1仍报；ADC全失败的非超温不报；采集失败不报不推进。

当前偏差：fw_core仍用prev-cur且35.0提前返回，measure轨迹p/H在推进后读取。由固件实现按本契约修正并独立验证；本节点未修源码。PACC PA-008/009/017/020为判据，不接受旧错误方向测试全绿替代。

| 头6 | 1 | N，无符号设备块数 |
| 头7 | 9 | 既有自定义pad，消费者忽略 |

规范明文设备前8B：`01 02 03 04 02 58 FF CE`→ID01020304、RH60.0、T-5.0；只除一次10。0℃/0%RH合法，不得仅因二者均0而延迟/丢弃有效读数。当前MqtttService有isZeroValue/bleZeroCount路径：计数从0起时忽略前两次连续全零读数，第三次起才送入业务，与PA-026合法零要求存在偏差；交Android修复/验证，不改固定网关或把零当未收到。

## 9. IF08：UART诊断与验证消费（B08）

UART1：PA06 TX/PA05 RX/GND，9600 8N1；当前登记入口COM43，COM26不是传感器口。上电顺序BOOT→VDD→IOTEST→IOSIG→BUS；每周期发送判定结束后恰一S，温湿度失败追加一G；CRLF结尾，每行含CRLF<=96B，ASCII数字/键/大写HEX。关闭调试不得影响采样/判定/发送，深睡关闭UART；不能复位GPIOA影响I2C/SWD。

既有线格式（尖括号为变量，不是线上字符）：

```text
BOOT fw=<当前构建标识> uid=<8HEX> rst=<4HEX> uart=9600
VDD ok=<0|1> code=<uint> bgrmv=<uint> mv=<uint>
IOTEST sda_lo=<0|1> scl_lo=<0|1> idle=<0..3> swap=<none|addr7[,addr7]> gc=<uint>
IOSIG scl=<5HEX> sda=<5HEX>
BUS idle=<0..3> scl=<0|1> sda=<0|1> ack=<none|addr7[,addr7...]>[+]
S k=<uint32> p=<int> H=<0|1> V=<0|1> o=<0..8> n=<uint> x=<uint> a=<uint> D=<0|1> t=<int> h=<uint> q=<0|1> r=<0|1> s=<0|1|2> y=<uint>
G s=<1..5> a44=<0|1> a45=<0|1> rd=<0..5> at=<uint> raw=<12HEX|------------>
```

| S字段 | 含义/约束 |
|---|---|
| k | 累计分钟RTC tick；周期通常+3；不等于Unix秒/精确180s |
| p/H | 本次判定使用的上一有效温度x10/是否存在；H=0时p不可当有效前值 |
| V/o/n/x/a/D | 光照valid/成功数/min/max/mean/dark；码0..4095；V=0不得用D判暗 |
| t/h/q | 温度x10/湿度x10/本次温湿度有效；q=0时数值可能是旧值或初始占位，不进业务 |
| r | 本周期门控结果，不是用户报警或远端收据 |
| s | 0未发送，1本地完成，2本地失败；不是G行的驱动status |
| y | 现有待发送失败重试计数器快照；成功/用尽会重置0，不能据y=0推出无重试，也不能将它当总尝试数 |

G.raw来自最近一次成功读总线的6B，CRC可仍失败；未读到使用12个'-'。BUS地址为2位大写HEX，'+'说明ACK列表截断；idle bit0=SCL、bit1=SDA。VDD ok=0数值无效；ok=1仅供轨量级参考，不证明器件引脚局部供电/波形正确。IOTEST.gc和IOSIG只是软件诊断事实，不代表电气结论；gc语义沿现生产者实现与相应手册解释，不凭日志值猜控制动作。

当前y属于兼容诊断状态字段；总重试数若验收需要，应由固件在同版本证据中明确捕获/解释，不在本契约擅改y语义或加RF字段。p/H的现有推进后打印须修正；BOOT现硬编码FD-002r4只能作为日志标识，不单独证明Flash身份，须配提交/镜像hash。
