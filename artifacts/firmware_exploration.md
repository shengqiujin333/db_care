## 0. 结论摘要

1. **GXHT40 不应答已从“固件疑似”收敛到“器件/焊接/器件引脚供电”层**：本轮逻辑分析仪在夹线所接的 SCL/SDA 网络上解出与固件代码逐项一致的 6 笔地址事务（`0x44/0x45` 各 3 次，全部 NACK，无 `0xFD`、无读事务）。因此主机位序列、地址、START/STOP、重试编排均**已被外部仪器证明正确**；继续改固件 I²C 代码不会产生 ACK。当前可区分手段（无万用表/无 X 光/无返修授权）**不能**区分“U9 焊点开路/虚焊”“U9 本体损坏”“U9 引脚未真正得电”三者，**不能**据此宣称器件已损坏或不可修复。
2. **上报判据存在确定性逻辑偏差**：现实现按“降温 >0.9℃”判定，且 `cur == 350` 提前返回；PDR-001 PR-004 的 14 个规范向量中 **3 个不符**（v3、v6、v7）。更严重的是**宿主机测试资产把“下降”写成了期望**，`build_test.sh` 184 项全绿也不能作为本需求的通过门禁。
3. **无光判据的 1/3 规则在当前光环境下存在现实误判风险**：本轮实测环境（readme 称“有光”）ADC 均值 **785**。按 `3×mean ≥ C_dark`，只有当全暗基准 `C_dark > 2355`（对应 LDR 暗阻约 >6.8 MΩ，为当前亮态阻值约 1.19 MΩ 的 5.7 倍）时，当前环境才不会被判为“暗”。`C_dark` 未标定、LDR 器件（J4 外接）无资料，必须现场实测后才能判断该判据是否可分离。
4. **采样节拍、UART1、引脚/外设资源、构建规模未见不可行项**：COM43 观察到 `k=105→108`（Δ3，约 3 分钟）且只有周期行；UART 行 69/44 B ≤96 B；Flash 20,860 B / 64 KB、RAM 1,792 B / 4 KB；PA03/04、PA05/06、PB04/05、PB02/03 无功能冲突。LSI 的实际 180 s 误差、深睡电流、CR2032 发射峰值压降**未测**。
5. **433/网关/BLE/手机/服务器不在本能力可验证范围**：本轮未发射、未接收、未安装 App。既有空口布局与网关兼容性只按版本引用历史证据，不能作为本轮通过结论。

**对后续工作的总建议：先完成 U9 的电气/焊接核查与必要返修，再投入固件判据修正与全暗标定；在 GXHT40 能 ACK 之前，不要继续用固件重试次数或“再烧一版”掩盖上游硬件问题。**

## 3. 增量 A：GXHT40 温湿度采集（PR-001 / PR-013）

### 3.1 本轮原始观察

**串口（COM43，300 s，逐字节）：**

```text
S k=105 p=0 H=0 V=0 o=8 n=785 x=787 a=785 D=0 t=0 h=0 q=0 r=0 s=0 y=0
G s=2 a44=0 a45=0 rd=0 at=3 raw=------------
S k=108 p=0 H=0 V=0 o=8 n=783 x=787 a=785 D=0 t=0 h=0 q=0 r=0 s=0 y=0
G s=2 a44=0 a45=0 rd=0 at=3 raw=------------
```

- 2/2 周期 `q=0`，`p=0 H=0`（从未有有效温度），`r=0 s=0`（不上报、不发送），`D=0 V=0`（光照未标定 → `valid=false`）。
- `G` 行 `s=2`（ERR_NO_DEVICE）、`a44=0 a45=0`（两候选地址均未 ACK）、`rd=0`（未进入读事务）、`at=3`（整帧重试 3 次用尽）、`raw` 全 `-`（从未读回 6 字节）。
- 失败发生在**地址探测层**，不是 CRC/量程/读重试。

**逻辑分析仪（被动，5.0 s，20 M 样点 @4 MHz）：**

按实际接线 `scl=D1, sda=D0` 解码，原始事务序列为：

| # | 采样点范围（4 MHz） | 事务 |
|---:|---|---|
| 1 | 18168–31206 | START → `0x44` + Write → **NACK** → STOP |
| 2 | 32078–45115 | START → `0x45` + Write → **NACK** → STOP |
| 3 | 46506–59544 | START → `0x44` + Write → **NACK** → STOP |
| 4 | 60417–73454 | START → `0x45` + Write → **NACK** → STOP |
| 5 | 74845–87882 | START → `0x44` + Write → **NACK** → STOP |
| 6 | 88754–101791 | START → `0x45` + Write → **NACK** → STOP |

- 6 笔 = `GXHT40_MEAS_RETRY(3) × {0x44,0x45}`，与 `gxht40_acquire()` 的控制流完全一致；地址 NACK 后不发送 `0xFD`，因此没有命令/读事务，`rd=0` 自洽。
- 每笔地址事务约 3.3 ms，SCL 位周期约 214 µs（≈4.7 kHz，由 D1 相邻上升沿 856 样点 @4 MHz 独立复算），6 笔跨约 20.9 ms；数字采样分辨率 0.25 µs。
- ACK 时隙内 SDA 保持高（NACK），与主机释放 SDA 的行为一致；没有从机拉低。
- **通道标签事实**：`environment.yaml` 标注 `D0=SCL、D1=SDA`，但只有 `D1=SCL、D0=SDA` 能解出固件代码实际发送的 `0x44/0x45`。按配置标注解码会得到“`0x10` Read + ACK”的**伪结果**。说明当前夹线/标签与登记不一致（或登记写反），后续不能直接按旧标签使用。

### 3.2 为何影响方案

GXHT40 是 PR-001 的唯一温湿度源，也是 PR-004 判据的输入。`q=0` 时：

- 不推进 `prev`、不产生上报、不发送 433；App 侧不会产生读数；任何“3 分钟/0.9℃/35℃”行为都不可观测。
- 因而本轮无法在真实目标上验证采集→判定→发送→网关的整链；这不是“逻辑未实现”，而是**输入物理层不成立**。
- 如果在这一状态下继续调整驱动重试、等待时间或地址，只会改变失败耗时，不会改变结果；属于无效迭代。

## 4. 增量 B：光照采集与“无光”判据（PR-002 / readme 点 2、7）

### 4.1 本轮观察与硬件事实

- 串口两周期：`o=8`（8 次 ADC 成功）、`n=783/785`、`x=787`、`a=785`；周期内极差 ≤4 码，跨周期均值一致（785）。说明 PB05 供电、100 ms 建立、AIN11 采样、均值路径**工作正常且稳定**。
- 网表：`LIGTHT_POWER` = `PB05` + `R3.2`；`LIGHT_ADC` = `PB04` + `R3.1` + `J4.1`；`J4.2` = GND；`R3 = 5 MΩ`（BOM 第 31 行）。BOM 只把 **J4** 记为 `HEADER 2`（封装/命名含 `GL4539_2`），**没有独立 LDR 器件行**；项目内**没有该 LDR 的数据手册/亮暗阻参数**，只能确认它是两脚外接器件（J4.1=LIGHT_ADC，J4.2=GND）。
- 极性：PB05 高 → R3 → 节点 → LDR → GND；越暗 LDR 阻值越大 → 节点电压/ADC 码越高。该极性来自网表推导，**未用照度计/暗室实测**。
- 当前配置 `LIGHT_DARK_REF_CODE=0`、`LIGHT_DARK_CALIBRATED=0`（`sensor_config.h:113/116`），因此 `valid=false → dark=false`，升温上报分支被**永久关闭**。这是设计上的“不伪造”行为，但也意味着**在标定前 PR-004 的升温分支不可能在真机上通过**。

### 4.2 1/3 规则的可分离性计算（本轮关键风险）

以本轮 `mean=785`、EV-017 同板 `VDD≈3.289 V`（本轮未复测）估算：

```text
V_node = 785/4095 × 3.289 V ≈ 0.630 V
R_ldr  = 5 MΩ × 0.630 / (3.289 − 0.630) ≈ 1.19 MΩ
```

判据 `dark = 3×mean ≥ C_dark`。要让“当前有光环境（785）”**不**被判暗，必须：

```text
3 × 785 < C_dark  ⇒  C_dark > 2355  ⇒  C_dark ≥ 2356
```

`C_dark = 2356` 对应 LDR 暗阻约 `5M × 2356/(4095−2356) ≈ 6.8 MΩ`，即暗阻至少是当前亮态阻值的 **5.7 倍**。如果该 LDR 在完全遮光下的阻值只有 1–3 MΩ（是否如此必须实测，不能假设），则：

- `C_dark ≈ 1170`（R≈2 MΩ）→ 阈值 `ceil(1170/3)=390` → 当前 785 **会被判为“无光”**；
- 结果是：在用户明确说“有光”的环境中，升温分支被错误打开，产品可能在有光时上报，违反 PR-002/PR-004。

> 这不是说 1/3 规则一定不可行；而是说**必须用实际 LDR 模块实测亮/暗两端码值**，并检查对比度是否大于 3（码值意义下）。若 `C_dark / 当前有光码值 ≤ 3`，该规则在该硬件上无法分离，需要回到产品/需求层讨论（本能力不擅自改需求）。

**注意**：完整暗室/遮光操作属于现场条件，本能力未执行；不得用“当前亮态读数 ÷ 3”或“满量程 4095”代替 `C_dark`（PDR-001 C-08）。

## 5. 增量 C：启动、3 分钟节拍、深睡与低功耗（PR-003 / PR-012）

### 5.1 已观察事实

- 本轮 300 s 窗口内只有 2 条 `S` 行，`k=105` 与 `k=108`，差值 **3**，与 `SENSOR_SAMPLE_TICKS=3` 一致；两条 `S` 之间无其它字节，符合“周期之间不打印、深睡”的设计。
- 上一轮 EV-017 在同一镜像上记录 `k=0,3,6,9,12,15,18` 共 7 个连续周期（约 21 分钟），失败形态稳定、无自愈；该证据在其版本范围内可复用。
- 本轮未复位，因此未捕获 `BOOT→VDD→IOTEST→IOSIG→BUS`；启动顺序的当前轮证据缺失，按 EV-017 复用（同镜像）。
- `main.c` 在每次循环调用 `debug_trace_flush_close()` 后 `SYSCTRL_GotoDeepSleep()`；RTC 1 分钟中断累计 3 次置 `sample_flag`。串口在深睡期间确实无输出（300 s 仅 4 行）。

### 5.2 仍未知/风险

| 项 | 现状 | 影响 | 最小实验 |
|---|---|---|---|
| LSI 实际频率与 180 s 误差 | 未测；验收暂定 ±10%（OQ-03） | 节拍漂移会影响“3 分钟”验收与 App 时间对齐 | 带主机时间戳连续捕获 ≥30 min（4×300 s 首尾相接），统计 `S` 到达间隔中位数/极差 |
| 深睡电流、RTC 唤醒电流 | 未测（无电流表） | CR2032 寿命（OQ-04 未给目标） | 硬件测试用电流表/功耗仪；不在本能力 |
| CR2032 在 433 发射峰值下的压降 | 未测 | 可能复位/发射失败；VDD 静态 3.289 V 不能代表峰值 | 发射时并联示波器/电流探头（未登记） |

## 6. 增量 D：条件上报判据（PR-004，核心）

### 6.1 静态事实与最小原型结果

当前实现（`USER/src/fw_core.c:109-122`）：

```c
if (cur > 350) return true;
if (cur == 350) return false;                 // 提前返回，跳过了升温分支
if (!have_prev) return false;
if (!dark) return false;
return (prev - cur) > 9;                      // 降温方向
```

用 14 个 PDR-001 向量执行真实 `fw_core.c`（`evidence/ev018/proto_report_rule.c`）：

| 向量 | prev→cur / 光照 | 期望 | 当前 | 判定 |
|---|---|---:|---:|---|
| v1 | 300→308，暗 | 否 | 否 | 一致 |
| v2 | 300→309，暗 | 否 | 否 | 一致 |
| **v3** | **300→310，暗** | **是** | **否** | **不符（升温分支缺失）** |
| v4 | 300→310，亮 | 否 | 否 | 一致 |
| v5 | 300→310，光照无效 | 否 | 否 | 一致（调用方传 `dark=false`） |
| **v6** | **310→300，暗** | **否** | **是** | **不符（把降温当触发）** |
| **v7** | **340→350，暗** | **是** | **否** | **不符（`cur==350` 提前返回）** |
| v8 | 340→350，亮 | 否 | 否 | 一致 |
| v9 | 无前值，351 | 是 | 是 | 一致 |
| v10 | 无前值，350，暗 | 否 | 否 | 一致 |
| v11 | 无前值，360 | 是 | 是 | 一致 |
| v12 | 352→351，亮 | 是 | 是 | 一致（超温分支） |
| v13 | 300→310，ADC 全失败 | 否 | 否 | 一致 |
| v14 | 采样失败 | 否 | 不适用 | 一致（`measure.c` 不调用判定；原型标记 applicable=false） |

汇总：**当前实现 3 项不符；按 PR-004 字面实现的参考函数 0 项不符**。

### 6.2 测试资产的同向偏差（比代码偏差更危险）

- `test/host_fw_core_pure_check.c:93-97` 与 `test/host_sensor_core_test.c:140-145` 的期望写的是 **“下降 9/10/11”**；`host_measure_flow_check.c:187-204` 同样按“下降”构造用例。
- 本轮 `test/build_test.sh` 运行 5 组 **184 项 0 失败**（`evidence/ev018/host_tests_current.log`），其中 fw_core 40 项、measure flow 43 项。
- 结论：**“宿主机测试全绿”不能证明 PR-004 满足**；在修正测试向量之前，任何“回归通过”都是假阳性。实现能力必须同时修改被测逻辑与测试期望，不能只让旧测试继续绿。

### 6.3 调试轨迹的语义缺陷（影响可诊断性）

`measure.c` 的顺序是：

```text
sensor_decide_report(s_prev_temp_x10, ...)   // 用旧 prev 判定
...
s_prev_temp_x10 = tempvalue;                // 判定后才推进（497 行）
...
out->prev_temp_x10 = s_prev_temp_x10;       // 取轨迹时已是新值（531 行）
```

因此成功周期的 `S` 行 `p=` 与 `t=` **恒相等**，失败周期两者也都是“最近有效值”。`p` 字段无法表达“判定时使用的上一有效温度”，现场无法从日志直接看出 `cur-prev` 是否跨过 0.9℃。这是 PR-010（可诊断）与 PR-004 证据能力的缺口，应在设计阶段明确“判定前快照”的字段语义。

### 6.4 候选路径与最小实验

| 路径 | 说明 | 风险 |
|---|---|---|
| D1 单点修正纯逻辑 | 删除 `cur==350` 提前返回；把差值改为 `cur - prev > 9`；保持 `int32`、严格边界 | 低；只影响纯函数 |
| D2 同步修正测试资产 | 用 14 向量替换“下降”期望；保留 35.0/35.1、无前值、光照无效、失败不推进 | 中；必须防止“改测试迎合实现” |
| D3 轨迹快照 | 在判定前保存 `prev_for_trace`，判定后仍打印旧值；发送仍用触发样本 | 低；只影响调试输出 |
| D4 命名/注释 | `SENSOR_REPORT_DROP_X10` 与 `sensor_config.h:121` 注释仍写“下降”，易误导后续维护 | 低；建议改名为 `SENSOR_REPORT_RISE_X10` |

最小实验：宿主机用 14 向量跑修正后的纯函数（无需硬件）；判定标准为 14/14 与期望一致，并保留“v14 不调用判定”的控制流用例。该实验本轮已用参考函数证明可达 0 不符，但**修正尚未实施**（不属于本能力）。

## 7. 增量 E：433 发射与上游链路（PR-005 / PR-006）

### 7.1 事实与边界

- 源码：10 B 明文（ID4 | T int16 LE | RH uint16 LE | CRC16 LE），Feistel 加密，`app_um2005C_send_data_timeout()` 200 ms × 3；发送成功仅代表本地完成，无空口 ACK。
- 本轮 `q=0`、`r=0`、`s=0`，**没有任何 433 发射**；逻辑分析仪只夹在 I²C 两线上，未观察射频。
- UM2005C 使用 PB02（CLK）/PB03（DATA）三线接口 + LPTIM；与 I²C（PA03/04）、UART1（PA05/06）、光照（PB04/05）、SWD（PA07/08）**无引脚冲突**。
- 发射时间预算（静态）：10 kbps、前导 20 bit + 同步 4 B + 10 B 数据 + CRC，空口约十几 ms；`radio_init()` 通过三线接口写配置（速率本轮未测），量级为 ms–十几 ms；200 ms 超时有余量。该预算**未实测**。
- 历史 `evidence/protocol_test.md`（PROTO-002）在旧版本上做过真实传感器加密 ↔ 真实网关解密的往返；本轮源码未改该路径，但**不能**把历史结论当作本轮通过。

### 7.2 未知与设计影响

| 未知 | 影响 | 最小实验 |
|---|---|---|
| 真实发射是否在 200 ms 内完成 | 超时会丢报，且现场只看到 `s=2` | 在 GXHT40 恢复后，用暗+升温触发一次，串口看 `s/y`；同时用网关/逻辑仪观察（需相应授权） |
| CR2032 峰值压降 | 可能发射复位或功率不足 | 发射瞬间测 BAT（示波器/电流探头，未登记） |
| 网关是否仍能解本帧 | 影响端到端 | 真实网关 + App（嵌入式/软件能力） |
| 200 ms×3 的阻塞对 3 分钟节拍的影响 | 最坏约 600 ms，仍远小于 180 s | 静态可接受；实测确认无额外采样 |

**可行性判断**：在 GXHT40 与标定完成前，RF 不是当前瓶颈；无新增协议字段的必要。不要把“发射失败重试”改成无限重试或周期心跳（违反 PR-004/PR-012）。

## 8. 增量 F：UART1、启动与资源（PR-010 / PR-011）

### 8.1 事实

- COM43 9600 8N1 收到完整 `S`/`G` 行；实测行长 **69 B**（S）与 **44 B**（G），均 ≤96 B（含 CRLF 分别为 71/46）。
- 字段包含 `k/p/H/V/o/n/x/a/D/t/h/q/r/s/y`；失败周期追加 `G s/a44/a45/rd/at/raw`，与 `debug_trace.c` 的冻结格式一致。
- 引脚映射（网表 + 代码）：`PA03=SCL`、`PA04=SDA`（各 4.7 kΩ 上拉 R1/R2）、`PA05=RXD`、`PA06=TXD`、`PB04=AIN11`、`PB05=LIGHT_POWER`、`PB02/PB03=UM2005C TWI`、`PA07/PA08=SWD`。UART1 与软 I²C 不共用引脚；`debug_trace_flush_close()` 只复位 UART1、把 PA05/PA06 置输入，不复位 GPIOA。
- 配置中 `DEBUG_UART_AFTX`/`AFRX` 的宏名与实际引脚是“交叉命名”（AFTX 调 `PA05_AFx_UART1RXD()`，AFRX 调 `PA06_AFx_UART1TXD()`），但两者都执行，净效果是 AFR5/AFR6 正确；属于可读性问题，不是功能缺陷（本轮 UART 实际可用）。
- 资源：Flash 20,860 B / 64 KB；RAM 1,792 B / 4 KB；无新增外设冲突。
- 退役项：当前 `USER/**` 未发现 hall/OPTCFG/params/history 的有效调用（按源码检索；历史实现已移除）。

### 8.2 未知/风险

- 本轮未抓 `BOOT/VDD/IOTEST/IOSIG/BUS`（未复位）；启动顺序与上电诊断的当前轮证据缺失，按 EV-017 同镜像复用。
- 深睡期间 UART 是否完全关闭（引脚是否高阻）只能从“无字节”推断，未测漏电。
- 生产固件长期开 UART 的功耗/产线策略未定（OQ-12）。
- `S` 行的 `p` 语义缺陷见 §6.3；这是 UART 设计需要修正的点。

## 10. 对后续固件设计的约束与建议

> 以下是探索结论对设计/实现的输入，不是本能力已实施的设计。

1. **顺序约束**：U9 ACK 问题是 PR-001 的物理前置。硬件核查/返修完成前，固件实现的验收只能在宿主机逻辑层进行；不得把“重试更久”“换地址”“关掉诊断”当作修复。
2. **判据实现**：严格按 PR-004：
   - 超温分支 `cur > 350` 独立判断；
   - 删除 `cur == 350` 的提前返回，恰好 35.0℃ 时仍评估升温分支；
   - 升温分支 `have_prev && dark && (int32)cur - (int32)prev > 9`；
   - `prev` 仅在温湿度样本有效时推进；失败不推进；
   - 光照无效/未标定只关闭升温分支，不关闭超温分支。
3. **测试门禁**：同步把 `host_fw_core_pure_check.c`、`host_sensor_core_test.c`、`host_measure_flow_check.c` 的“下降”向量改为 PDR-001 的 14 向量；新增“恰好 35.0 + 升温 1.0 + 暗 ⇒ 上报”与“降温不报”用例。禁止只改实现让旧测试继续绿。
4. **轨迹语义**：在判定前快照 `prev_for_trace`，`S` 行 `p=` 必须表示“本次判定使用的上一有效温度”，与 `t=` 可不同；发送仍必须使用触发本次判定的样本。保持 ≤96 B。
5. **全暗标定**：
   - 在最终安装/供电/取样策略下实测 `C_dark`（≥10 周期，记录 min/max/mean/样本数与板号）；
   - 同时记录正常“有光”环境的码值分布；
   - 检查 `C_dark / 有光码值 > 3`；不满足时，1/3 规则在该硬件上不可分离，应回到产品/需求层决策，不得用调参伪装通过；
   - 未标定保持 `valid=false`；禁止用满量程/旧默认/亮态读数代替。
6. **时序/通信**：
   - 保持 `GXHT40_MEASURE_WAIT_MS=10`（≥手册 tMEAS.H 8.3 ms）、`tPU` 2 ms、地址仅 `0x44/0x45`；
   - 现有约 4.7 kHz 软 I²C 远低于常见 100/400 kHz 上限，未见速率风险；器件恢复 ACK 后仍需核对建立/保持时间，不要为了“看起来更快”改 delay 而未验证 ACK/CRC；
   - 保持有界重试/总线恢复；不要无限等待。
7. **节拍/功耗**：保持 RTC 1 min × 3、无心跳、无周期保活；`S` 行不得引入额外采样；深睡前后 UART 开关不得复位 GPIOA 或影响 PA03/04/07/08。
8. **UART1**：默认开启（readme 点 8）；关闭开关不得改变业务结果；行预算 96 B 仍有 25 B 余量。
9. **协议/兼容**：不改 10 B 空口布局、Feistel 密钥、BLE 布局、网关和 iOS；光照/原因/时间不得上协议。
10. **验证工具配置**：
