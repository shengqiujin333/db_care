# 软件端到端测试计划（E2E-SW-003）

状态：软件测试设计产物（`software_tester.software_test_design`，输出端口 `e2e_plan`）
版本：2.0（替代 E2E-SW-002 v1.0）
范围：只保留**必须端到端证明**的关键跨系统旅程：Android App 的权限与网关发现 → 真实 BLE 读取 → 本地消费 → MQTT 发布 → 云端 `/upload_data`，以及完整交付的应用级关键路径。
本文只做计划（旅程、前置、步骤、证据、判定、阻塞条件），**不执行**。与 `artifacts/software_test_design.md`（TD-SW-003）配套：TD-SW-003 负责分层与逐项用例，本文负责跨系统旅程。

上游输入：`readme.txt`、`artifacts/android_architecture.md`（AA-003 rev 2.0）、`artifacts/android_tasks.yaml`、`artifacts/interface_contract.md`（IC-002 v3.0）、`artifacts/android_feasibility.md`（AF-001）、`服务器迁移记录.md`、`artifacts/test_design.md`（TD-002，嵌入式联测边界）。

执行原则：

- 每条旅程必须给出**两类以上独立证据**（App 侧状态/截图/日志 + 本地库/HTTP 响应/broker 侧记录/网关侧记录），并注明同一操作的时间对应关系。
- 刺激优先使用可脚本化软件手段（MQTT 注入、HTTP 探测、`adb` 截图/logcat、debug 包数据库导出）；真实 BLE 必须使用真实网关，**不得以注入替代“BLE 链路通过”**。
- 不具备前置（无工具/无设备/无网关/无网络/无授权）时，该旅程记 **NOT EXECUTED** 并说明条件，**不得记为通过**。
- 真实 BLE / 真实服务 / 模拟器 / 主机单测的证据分开标注，不混写。

## 2. 关键旅程

### E2E-01 权限门与真实直连链路（API 29 核心增量）

**目标**：证明 Android 10 上“无定位授权”不再阻断 BLE 直连，且权限异常不再表现为每 180 s 静默返回。

**前置**：D1 在线并安装当前 APK；App 未授予 `ACCESS_FINE_LOCATION`；蓝牙开；网关 G 上电且地址已通过发现流程确认或使用迁移默认（标注未确认）；守护可开启。

**步骤**
1. 记录基线：权限状态、`gateway_ble_addr`、`mac_addr`、蓝牙状态、App 版本。
2. 冷启动 App → 开启守护。
3. 观察策略日志（`sdkInt=29`、`needScan=false`、缺失项、`canConnect`）与随后的 GATT 尝试。
4. 若网关在线：等待一次读取完成；观察解析、卡片、入库时间。
5. 关闭/移走网关再试：观察失败原因是否为连接失败而非权限返回。

**证据**：logcat 原文（含策略字段与连接尝试）、权限状态 dump、截图、本地库导出、网关侧记录（若有）。
**判定**：未授予定位仍出现 GATT 尝试；无“仅权限日志后返回”路径；连接成功与否按网关条件单独判定，不以“连接失败”反推权限通过或失败。
**阻塞条件**：无 `android_app_testing`/App 未安装 → NOT EXECUTED；网关上电/身份未确认时仅能判“尝试路径”，不能判“直连成功”。

### E2E-02 权限拒绝、“不再询问”与恢复

**目标**：证明拒绝路径有一等可观测状态与可执行动作，恢复后无需重启进程即可继续，数据不清空。

**前置**：D1/D2；D2 用于 API 31+ 分支；库与待发箱中有测试数据。

**步骤**
1. 触发权限请求并拒绝；选择“不再询问”后再触发。
2. 观察首页状态区的具体缺失项与动作（去授权/系统设置）。
3. 通过系统设置授予权限；等待下一轮或触发立即读取。
4. 运行中撤销权限，再恢复。
5. 每步记录 `temperature`/`alarm_events`/`pending_uploads` 行数。

**证据**：截图（拒绝/不再询问/恢复）、logcat（含 `sdkInt`/缺失/`needScan`）、权限状态、DB 行数前后对比。
**判定**：拒绝/不再询问均有具体提示与动作；授权后下一轮恢复；撤销后停止并有状态；全程无需重启进程；三类数据不丢。
**阻塞条件**：无 D2 时 API 31+ 分支 NOT EXECUTED（D1 仅能覆盖 API 29 路径）。

### E2E-03 网关发现、绑定、持久化与清除

**目标**：证明网关身份来自正常发现/用户确认并可持久化，连接目标不再来自硬编码；默认值与清除行为可区分。

**前置**：D1/D2；网关 G 上电；API<31 时定位权限与定位总开关可用；API 31+ 时 `BLUETOOTH_SCAN` 可请求；broker 可达（用于后续连接验证）。

**步骤**
1. 进入网关选择页，执行有界扫描（≤10 s），记录候选名称/MAC/RSSI/是否含 FFE0。
2. 若无候选，执行显式无过滤回退扫描；若仍无候选，记录“未找到网关”。
3. 选择候选或手动输入合法 MAC；非法输入另测。
4. 保存后触发下一轮读取；重启 App 再读取。
5. 修改 `mac_addr`（测试值）→ 观察 `gateway_ble_addr` 不变、日志分别标注。
6. 清除 `gateway_ble_addr` → 观察是否回到未配置，而非静默回退默认。
7. 构造扫描取消/页面销毁/扫描中关蓝牙/撤销权限，等待 ≥15 s 观察是否仍有回调。

**证据**：截图、logcat（扫描开始/停止时间戳、候选、连接目标）、`MyPrefs` 导出、broker/网关侧记录。
**判定**：扫描有界且所有结束路径 `stopScan`；候选去重/排序/FFE0 优先；保存后下一轮与重启后使用已保存地址；同条日志双地址分别标注；清除后不回退默认；无持续扫描。
**阻塞条件**：网关不在范围/未上电 → 候选与真实连接 NOT EXECUTED；无 `android_test` → 全部 NOT EXECUTED。

### E2E-04 真实多设备批次：本地逐条 → 完整发布 → 云端

**目标**：证明一次 BLE 读取的全部读数按 ID 逐条消费，并在数量/ID/顺序一致时按绑定顺序完整发布；不一致时拒绝且不影响本地处理。

**前置**：网关 G 带 ≥2 台设备；`MacIdBook` 顺序与帧顺序一致；broker 可达；独立 MQTT 订阅端可用；网络可用；`/upload_data` 可达。

**步骤**
1. 记录 `MacIdBook.all()` 顺序、绑定集合与设备数。
2. 触发一次真实读取；记录 App 解码的每条 `devId/T/H`。
3. 观察本地：卡片、`temperature` 行、`pending_uploads` 行、`alarm_events`（若触发）。
4. 订阅端记录 App 发布的 payload 原文与时间。
5. 观察 App 上传请求与响应；核对 `(dev_id,time)` 幂等。
6. 受控构造不一致（测试账号临时改动绑定数量或顺序，记录并复原）：重复读取，确认**无发布**、本地处理仍发生。

**证据**：App logcat、DB 导出、broker 订阅原文、HTTP 请求/响应、时间线、绑定集合快照。
**判定**：每条读数按自身 ID 完成告警/入库/入队；发布串格式为 `<epoch>:<temps>:<humis>`、按绑定顺序、包含全部读数；不一致时无任何部分载荷且本地处理不受影响；上传契约与幂等正确。
**阻塞条件**：无真实多设备网关 → NOT EXECUTED（宿主机 L0 用例不能替代本旅程）；broker 不可达 → 发布与上传部分 NOT EXECUTED。

### E2E-05 零值、条件上报语义与“长时间无数据”

**目标**：证明 `0.0/0.0` 是合法读数、App 不合成样本、长时间无新数据不显示“离线”。

**前置**：D1/D2；守护开；MQTT 注入可达；报警开关可设为隔离值；真实 BLE 0.0 源按可得性。

**步骤**
1. 注入 `T:0.0:0.0`（测试绑定）；观察是否首次即处理（入库/入队/卡片）。
2. 观察至少 2 个 180 s 周期内无新上报时：App 是否新增合成行、卡片是否刷新为 0、图表是否出现虚构点。
3. 构造 `time=now-40min` 的注入读数，观察卡片是否出现“离线”。
4. 若存在可控真实 BLE 源，重复 0.0/0.0 的真实 BLE 路径；否则记 NOT EXECUTED。

**证据**：DB 导出、卡片/详情截图、logcat、待发箱、broker 发布记录。
**判定**：`0.0/0.0` 首次即进入正常处理；无合成样本；不显示“离线”；BLE 真实 0.0 路径未测时如实保留为未满足项。
**阻塞条件**：无可控 BLE 源 → BLE 0.0 子项 NOT EXECUTED，不得用 MQTT 注入替代。

### E2E-06 完整交付应用级验收

**目标**：证明当前候选可构建、可安装、可启动，关键用户路径可用，既有功能回归不被破坏。

**前置**：本机 Gradle/JDK/SDK；D1（必要时 D2）；当前源码。

**步骤**
1. `./gradlew :app:testDebugUnitTest --offline`、`:app:assembleDebug --offline`；记录退出码、测试计数、APK SHA-256 与版本。
2. 安装 APK → 启动 → 隐私政策 → 首页。
3. 开启守护；处理权限；选择/确认网关。
4. 观察一次读数进入卡片/详情；触发一次上传。
5. 回归：卡片四状态、24 h 图表、35.0/35.1 强调、早报、守护开关、既有 5 个端点（无效数据调用）。
6. 截图与日志归档。

**证据**：构建日志、JUnit XML、APK 摘要、安装/启动日志、逐步截图、DB 导出、HTTP/broker 记录。
**判定**：构建与全部宿主机用例通过；应用可安装启动、资源与依赖装载正常；关键路径每步有证据；既有功能与兼容面未破坏。
**阻塞条件**：无安装/UI 工具 → 应用级步骤 NOT EXECUTED；构建与宿主机部分可先执行。

### E2E-07 服务链路回归：TLS、上传与幂等

**目标**：证明 App 仅按既有设计连接已部署服务，TLS/认证/明文放行未放宽，上传幂等可观测。

**前置**：D1/D2 联网；broker/HTTP 可达；获准的服务观测入口（HTTP 响应；DB 行级需另行授权）。

**步骤**
1. 启动 App，观察 `ssl://8.140.23.253:8883` 连接与状态；记录连接参数（用户名/密码拼接、topic、MTU）。
2. 核对 `network_security_config.xml` 放行域仍为既有 3 个主机。
3. 用构造载荷 `POST /upload_data` 两次；记录状态码与响应体。
4. 断网累积 → 恢复补传；记录待发箱与请求时序。
5. 若有获准 DB/服务只读入口，回读 `(dev_id,time,temperature,humidity)`；否则记 NOT EXECUTED。

**证据**：logcat、状态截图、静态 diff、HTTP 请求/响应原文、待发箱导出、服务端回读（若可得）。
**判定**：仅新服务器地址生效；TLS 信任锚未变；明文放行未扩张；2xx 成功且重复 `(dev_id,time)` 不产生第二行；断网不丢、恢复补传；服务端持久化结论仅在有回读证据时成立。
**阻塞条件**：网络/服务不可达 → NOT EXECUTED；无 DB 回读授权 → 持久化子项 NOT EXECUTED，不得以 HTTP 2xx 替代。

## 3. 证据汇总与判定规则

- 每条旅程输出一张证据索引：旅程号、执行时间、环境（设备/系统/网络/账号/网关/服务版本）、被测提交与 APK 摘要、步骤、原始证据路径、期望、实测、结论、阻塞说明。
- 全部结论必须能被保存的原始证据复现；不得以“命令成功/退出码 0”替代业务结论。
- 前置不足或环境不可达：记 NOT EXECUTED 与缺失条件，不计入通过；不伪造、不外推。
- 真实 BLE、真实服务、模拟器、主机单测证据分开标注；模拟器/主机不能替代真实链路结论。
- 跨能力边界：真实传感器/网关/固件条件由嵌入式能力提供；本计划只消费其证据，不代替其实施或判定。服务端持久化由获准服务入口核验。
- 每条旅程执行后按 TD-SW-003 §7.1 清理测试偏好/绑定、库内测试数据、设备状态、MQTT 客户端与后台任务，并保留清理前后证据。
- 最终判定遵循 TD-SW-003 §10：任一必需旅程 FAIL/NOT EXECUTED/CONDITIONAL/UNKNOWN → 完整交付不得判为通过；执行测试者返回 TEST_FAIL 并附当前版本失败报告。
