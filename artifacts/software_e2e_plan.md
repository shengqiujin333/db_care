- 复用既有部署；**不重部署、不重启服务、不改服务端配置**。若实际证据表明必须变更，先给出具体依据与所缺授权，不自行扩权。

## 2. 关键旅程

### E2E-01 权限门与真实直连链路（API 29 核心增量）

**目标**：证明 Android 10 上“无定位授权”不再阻断 BLE 直连，且权限异常不再表现为每 180 s 静默返回。

**前置**：D1 在线并安装当前 APK；App 未授予 `ACCESS_FINE_LOCATION`；蓝牙开；网关 G 上电且地址已通过发现流程确认或使用迁移默认（标注未确认）；守护可开启。

**步骤**
1. 记录基线：权限状态、`gateway_ble_addr`、`mac_addr`、蓝牙状态、App 版本/提交号/APK 摘要。
2. 冷启动 App → 开启守护。
3. 观察策略日志（`sdkInt=29`、`needScan=false`、缺失项、`canConnect`）与随后的 GATT 尝试。
4. 若网关在线：等待一次读取完成；观察解析、卡片、入库时间、**协商 MTU 与返回字节**。
5. 关闭/移走网关再试：观察失败原因是否为连接失败而非权限返回。

**证据**：logcat 原文（含策略字段、连接尝试、MTU/字节）、权限状态 dump、截图、本地库导出、网关侧记录（若有）。
**判定**：未授予定位仍出现 GATT 尝试；无“仅权限日志后返回”路径；连接成功与否按网关条件单独判定，不以“连接失败”反推权限通过或失败；读取完整性按 E2E-10 单独判定。
**阻塞条件**：无 `android_app_testing`/App 未安装 → NOT EXECUTED；网关上电/身份未确认时仅能判“尝试路径”，不能判“直连成功”。

### E2E-02 权限拒绝、“不再询问”、恢复与 API 31+ 分支

**目标**：证明拒绝路径有一等可观测状态与可执行动作，恢复后无需重启进程即可继续，数据不清空；API 31+ 分支按新权限模型工作。

**前置**：D1/D2；D2 用于 API 31+ 分支；库与待发箱中有测试数据。

**步骤**
1. 触发权限请求并拒绝；选择“不再询问”后再触发。
2. 观察首页状态区的具体缺失项与动作（去授权/系统设置/去开启定位）。
3. 通过系统设置授予权限；等待下一轮或触发立即读取。
4. 运行中撤销权限，再恢复。
5. 每步记录 `temperature`/`alarm_events`/`pending_uploads` 行数。
6. D2 上重复 1–4，覆盖 `BLUETOOTH_CONNECT/SCAN` 与通知权限；确认 API<33 不请求通知。

**证据**：截图（拒绝/不再询问/恢复）、logcat（含 `sdkInt`/缺失/`needScan`/`adapterEnabled`）、权限状态、DB 行数前后对比。
**判定**：拒绝/不再询问均有具体提示与动作；授权后下一轮恢复；撤销后停止并有状态；全程无需重启进程；三类数据不丢；请求集合与 Manifest 一致。
**阻塞条件**：无 D2 时 API 31+ 分支 NOT EXECUTED（D1 仅能覆盖 API 29 路径）。

### E2E-03 网关发现、绑定、持久化与清除

**目标**：证明网关身份来自正常发现/用户确认并可持久化，连接目标不再来自硬编码；默认值与清除行为可区分；扫描有界且必停。

**前置**：D1/D2；网关 G 上电；API<31 时定位权限与定位总开关可用；API 31+ 时 `BLUETOOTH_SCAN` 可请求；broker 可达（用于后续连接验证）。

**步骤**
1. 进入网关选择页，执行有界扫描（≤10 s），记录候选名称/MAC/RSSI/是否含 FFE0。
2. 若无候选，执行显式无过滤回退扫描；若仍无候选，记录“未找到网关”。
3. 选择候选或手动输入合法 MAC；非法输入另测。
4. 保存后触发下一轮读取；重启 App 再读取。
5. 修改 `mac_addr`（测试值）→ 观察 `gateway_ble_addr` 不变、日志分别标注。
6. 清除 `gateway_ble_addr` → 观察是否回到未配置，而非静默回退默认。
7. 构造扫描取消/页面销毁/扫描中关蓝牙/撤销权限，等待 ≥15 s 观察是否仍有回调。

**证据**：截图、logcat（扫描开始/停止时间戳、候选、连接目标）、`MyPrefs` 导出、broker/网关侧记录。
**判定**：扫描有界且所有结束路径 `stopScan`；候选去重/排序/FFE0 优先；保存后下一轮与重启后使用已保存地址；同条日志双地址分别标注；清除后不回退默认；无持续扫描；不自动连接他人网关。
**阻塞条件**：网关不在范围/未上电 → 候选与真实连接 NOT EXECUTED；无 `android_test` → 全部 NOT EXECUTED。

### E2E-04 真实多设备批次：本地逐条 → 完整发布

**目标**：证明一次 BLE 读取的全部读数按 ID 逐条消费，并在数量/ID/顺序一致时按绑定顺序完整发布；不一致时拒绝且不影响本地处理。

**前置**：网关 G 带 ≥2 台设备；`MacIdBook` 顺序与帧顺序一致；**协商 MTU 与 FFE2 返回字节覆盖完整快照 `16*(1+N)`**；broker 可达；独立 MQTT 订阅端可用；网络可用。

**步骤**
1. 记录 `MacIdBook.all()` 顺序、绑定集合、设备数 N、协商 MTU 与 `value.size`。
2. 触发一次真实读取；记录 App 解码的每条 `devId/T/H`。
3. 观察本地：卡片、`temperature` 行、`pending_uploads` 行、`alarm_events`（若触发）。
4. 订阅端记录 App 发布的 payload 原文与时间。
5. 受控构造不一致（测试账号临时改动绑定数量或顺序，记录并复原）：重复读取，确认**无发布**、本地处理仍发生。
6. 断开 broker 后触发一次读取，再恢复连接，确认只补发最近一批一次。

**证据**：App logcat、DB 导出、broker 订阅原文、时间线、绑定集合快照、MTU/字节记录。
**判定**：每条读数按自身 ID 完成告警/入库/入队；发布串格式为 `<epoch>:<temps>:<humis>`、按绑定顺序、包含全部读数；不一致时无任何部分载荷且本地处理不受影响；未连接时只保留最近一批；**读取完整性不满足时整批不产生读数，不以部分帧继续**。
**阻塞条件**：无真实多设备网关 → NOT EXECUTED（宿主机 L0 用例不能替代本旅程）；broker 不可达 → 发布部分 NOT EXECUTED；MTU/返回字节不足或不可构造 → 完整性分支按 E2E-10 记 NOT EXECUTED。

### E2E-05 占位、0.0/0.0 与观测语义

**目标**：证明网关全零占位不生成假设备/假读数，有效 ID 的 `0.0/0.0` 是合法读数，App 不合成样本、不显示“离线”。

**前置**：D1/D2；守护开；真实网关可产生无数据占位（如传感器停止上报至网关超时清零）；真实 0.0/0.0 源按可得性；MQTT 注入可达（仅用于对照，不替代 BLE）。

**步骤**
1. 触发全占位批次（真实 BLE）：观察发布、入库、待发箱、卡片、通知、状态。
2. 触发混合批次（真实 BLE）：观察占位跳过与有效读数处理。
3. 若有可控真实 BLE 0.0/0.0 源：触发一次读取，观察首次即入库/入队/卡片。
4. MQTT 注入 `T:0.0:0.0`（测试绑定）作为**对照**，观察同一处理路径；不得以此替代 BLE 结论。
5. 观察至少 2 个 180 s 周期内无新上报时：App 是否新增合成行、卡片是否刷新为 0、图表是否出现虚构点；构造 `time=now-40min` 的注入读数，观察是否出现“离线”。

**证据**：DB 导出、待发箱、卡片/详情截图、logcat、broker 发布记录、状态区文本 dump。
**判定**：全占位不发布、不写入、不生成 `00000000` 设备/卡片/通知，状态“网关暂无传感器数据”；混合批次有效读数照常处理；真实 0.0/0.0 首次即正常处理；无合成样本；不显示“离线”。
**阻塞条件**：无法可控产生占位或 0.0/0.0 → 对应真实 BLE 子项 NOT EXECUTED，不得用 MQTT 注入替代。

**目标**：证明当前候选可构建、可安装、可启动，关键用户路径可用，既有功能回归不被破坏。

**步骤**

2. 安装 APK → 启动 → 隐私政策 → 首页。
3. 开启守护；处理权限；选择/确认网关。
4. 观察一次读数进入卡片/详情；触发一次上传。
5. 回归：卡片四状态、24 h 图表、35.0/35.1 强调、早报、守护开关、既有 5 个端点（无效数据调用）。
6. 截图与日志归档。

**证据**：构建日志、JUnit XML、APK 摘要、安装/启动日志、逐步截图、DB 导出、HTTP/broker 记录。
**判定**：构建与全部宿主机用例通过；应用可安装启动、资源与依赖装载正常；关键路径每步有证据；既有功能与兼容面未破坏。
**阻塞条件**：无安装/UI 工具 → 应用级步骤 NOT EXECUTED；构建与宿主机部分可先执行。

### E2E-07 既有服务复用核验与真实上传/幂等/持久化回读（本轮核心）

**目标**：证明 App 仅按既有设计连接已部署服务；复用现有服务；真实上传可分类、可观测；同一 `(dev_id,time)` 幂等；数据在服务端持久化并可回读；401 机制有可复现结论。

**前置**
- 服务只读核验入口（执行阶段需 `existing_service_ssh_inspection`/`inspect_existing_service_readonly`）可用；不重部署、不重启、不改配置。
- 隔离测试身份：测试手机号、测试网关 MAC、测试 devId、合成温湿度；**不使用真实用户数据**。
- HTTP 写入授权（仅测试数据）；持久化回读入口（获准只读 DB 或服务端回读接口）；测试数据清理约定与单独删除授权。现有 `existing_service_ssh_inspection` 入口只允许状态/端口/日志，**不包含 DB 直连**；不得用该入口执行 SQL，DB 回读需单独授权。
- D1/D2 联网；`android_test` 可用。

**步骤**
1. **只读基线**（执行前）：服务身份/unit 状态/监听端口/6 路由存在性/近期日志/EMQX 版本与连接数；记录与 BE-EXP-004 基线的差异。不修改任何配置。
2. 记录被测 App 提交号、APK SHA-256、版本、设备/API、`gateway_ble_addr`/`mac_addr`（测试值）。
3. **D1（最高优先）**：用测试载荷 `POST /upload_data` 一次，**不带**任何凭证；若返回 401/403，再按实际可用方式（如 `/login` 获得的 token，若存在且获授权）重试一次。记录两次状态码与响应体原文（脱敏）。若 `/login` 需要短信/生产身份且未准备，记相应分支 NOT EXECUTED。
4. **D2 幂等**：相同 `(dev_id,time)` 连续 POST 两次（相同值）；记录两次状态码/响应体/`inserted`（如有）与回读行/行数。
5. **D3 边界**：同键不同值 1 次；批内一项非法 1 次；空 `readings` 1 次；记录冲突取舍、原子性、4xx 边界。
6. **D4 回读**：按获准只读入口回读 `(dev_id,time,temperature,humidity)`；与请求逐字段比对（含小数位/舍入）。
7. **D5 归属**：未知 `phone`/`mac`/`dev_id` 各 1 次（仅合成）；记录状态码/响应体与是否可任意写。
8. **D6 真实 App 上传**：由真实 BLE/MQTT 读数触发 App 上传；在服务日志与回读两侧对账；记录 App 待发箱删除与 HTTP 结果；同时观察 BLE 缓存复读造成的同值不同秒重复行（数据语义，不是服务缺陷）。
9. **执行后只读复核**：再次查看服务 unit/日志/连接数；确认未重启、未改配置；记录本次测试请求行与结果。
10. **清理**：只清理本实验的测试行；删除动作需单独授权；无授权则保留并报告，不冒充清理完成。

**证据**：两次/多次 HTTP 请求与响应原文（脱敏）、服务只读日志片段、回读行/行数、App logcat/待发箱、版本三元组、BE-EXP-004 基线对照。
**判定**
- 2xx **且**服务端存在对应行 **且**回读字段逐项一致 → 该次上传/持久化成立；**仅 2xx 不成立**。
- 同键第二次 `inserted=0` 且行数不变 → 幂等成立；若响应无 `inserted`，以回读行数/内容判定。
- 401 只记录实际状态与响应；机制定性需有可复现证据（例如无凭证 401、授权方式 2xx），否则记 UNKNOWN/未定性。
- 无回读入口 → 持久化/回读子项 NOT EXECUTED；不得以 HTTP 2xx、App 日志或本地桩替代。
- 服务版本/路由与基线不一致 → 记录差异并判断是否影响复用；若需服务变更，停止并给出依据与所需授权，不自行改服务。
**阻塞条件**：网络/服务不可达、无写入授权、无回读入口、无测试身份、无只读服务入口 → 对应子项 NOT EXECUTED；不得因此删除旅程或判完整交付通过。

### E2E-08 上传被拒、自动重试停止与手动重试

**目标**：证明 401/403 与其他 4xx 不会被当作瞬时失败无限退避；数据保留、状态可见、用户可手动重试；重试后按新结果分类。

**前置**：D1/D2 联网；App 当前候选；测试待发箱有数据；可获得真实 401/403（或经获准测试入口构造的 4xx）；`android_test` 可用。

**步骤**
1. 记录待发箱行数/内容与 MyPrefs 上传状态基线。
2. 触发真实上传并得到 401/403；观察 App 是否停止自动重试、是否保留行、是否写入原因码/HTTP 状态/时间/待发条数。
3. 观察界面：具体“上传被拒绝/请求被拒绝”状态与待发条数；BLE/MQTT/告警/入库不受影响。
4. 点击“重试上传”；观察阻塞清除、到期行恢复、立即一次上传；若仍失败，按新结果重新分类。
5. 构造一次可成功的上传（如权限/凭证条件满足，且获授权）；观察成功后逐行删除。
6. 复核日志不含请求体全文与凭据（手机号/MAC 之外）。

**证据**：HTTP 状态/响应、App logcat、待发箱行、MyPrefs、截图、服务日志（若可得）。
**判定**：401/403/4xx 无自动重试请求；行全部保留；状态与条数可见；手动重试只触发一次并清除阻塞；成功删除、失败重新分类；主链路不受影响；日志脱敏。
**阻塞条件**：无法获得真实 401/403 且无获准构造入口 → 真实服务子项 NOT EXECUTED（L0-39/40 只能证明分类/策略，不证明真实服务行为）。

### E2E-09 全链路：真实传感器→网关→BLE→App→MQTT→HTTP→服务持久化

**目标**：证明完整用户结果：传感器数据经网关与 BLE 到达 App，经 MQTT/HTTP 上传，服务端持久化并可回读，App 展示与回读一致。

**前置**：E2E-04、E2E-05、E2E-07、E2E-10 的前置全部满足；真实传感器/网关可用（嵌入式/硬件能力提供其证据）；真实温湿度/遮光刺激条件按现场提供；测试身份与回读授权。**当前现场有光且固件无光判据未启用，不得为制造升温/无光条件调温或改变光强**；条件不足的触发段记 NOT EXECUTED。

**步骤**
1. 记录传感器/网关身份、App 版本/提交号/APK 摘要、服务版本基线、协商 MTU/返回字节。
2. 制造一次可识别的真实读数（按现场条件；记录刺激与时间窗口；不伪造环境；不调温/不改光强）。
3. 记录 App 解码的 `devId/T/H/接收时间`、本地库行、待发箱、MQTT 发布原文。
4. 记录 App HTTP 上传请求/响应与服务端日志。
5. 按获准只读入口回读 `(dev_id,time,temperature,humidity)`。
6. 对照 App 展示（卡片/详情）与回读数据，记录时间对应关系与版本三元组。
7. 清理测试数据（需授权），保留清理前后证据。

**证据**：传感器/网关侧记录、logcat、DB 导出、broker 原文、HTTP 请求/响应、服务日志、回读行、截图、MTU/字节记录。
**判定**：同一笔读数在 App、MQTT、HTTP、服务端回读中逐字段一致（devId/time/temperature/humidity）；App 展示与回读一致；服务端持久化成立；读取完整性满足；任一段缺失 → 该段 NOT EXECUTED/未通过。
**阻塞条件**：无真实网关/传感器/刺激条件、无服务写入或回读授权 → 对应段 NOT EXECUTED；不得以 MQTT 注入替代 BLE 段，不得以 HTTP 2xx 替代回读段。

### E2E-10 容量与读取完整性：MTU、FFE2 返回字节、≤9 台与第 10 台拒绝

**目标**：证明当前 App 在真实网关链路上按协商 MTU 与实际返回字节判定完整快照；绑定容量被限制在 9 台；历史 >9 台不读取/不写 `0xA1`/不转发；删除多余设备后恢复。

**前置**：D1（或 D2）；真实网关 G 上电且可连接；App 当前候选；守护可开启；测试绑定 ID（8 位 HEX，非生产）；具备 `android_test`；`adb logcat` 可读。真实 9 台快照另需 ≥9 台真实设备（或测试绑定 + 网关联动，但后者不得宣称真实 9 设备联调通过）。

**步骤**
1. 记录基线：绑定集合与数量、`gateway_ble_addr`、`mac_addr`、App 版本/提交号/APK 摘要、网关身份。
2. 绑定 N（建议先 1 台，再逐步增加至 ≤9）：记录 `MacIdBook.all()` 顺序与 N。
3. 触发读取；从 logcat 记录协商 `mtu`、参数 `value.size`、期望 `16*(1+N)`、判定结果（Proceed/Refuse 原因）。
4. 正常分支：若 `mtu >= 16*(1+N)+3` 且 `value.size >= 16*(1+N)` 且 16 B 对齐 → 确认解码成功、本地逐 ID 处理、MQTT 载荷按绑定顺序完整；记录多余 16 B 对齐尾部只按 N 消费。
5. 拒绝分支（仅在可合法构造时）：MTU 不足 → 确认不发起读取/本轮回 `READ_INCOMPLETE`；`value.size` 不足或非 16 B 对齐 → 确认整帧拒绝、实际/期望字节入日志、无读数/不落库/不入队/不转发；MTU 协商失败只重连重试一次；不可构造的分支记 NOT EXECUTED。
6. 容量：通过绑定界面试图保存第 10 台 → 确认拒绝并提示“超过网关完整传输上限 9 台”，既有 9 台不变。
7. 历史 >9 台：在测试副本中注入 10 台绑定数据（记录并备份）→ 启动守护 → 确认不发起连接/读取、不写 `0xA1`、不转发，状态 `BINDING_CAPACITY_EXCEEDED`；DB/待发箱无新增。
8. 删除多余设备至 9 台 → 观察下一轮恢复读取；记录恢复时间与证据。
9. 清理：复原 `MyPrefs`/绑定集合，仅清理测试数据；保留清理前后证据。

**证据**：logcat 原始行（`mtu=`、`value.size=`、`expected=`、`reason=`、`0xA1` 写入/拒绝）、截图（容量/读取不完整状态）、`MyPrefs`/`MacIdBook` 快照、DB/待发箱、broker 订阅原文（正常分支）、网关侧记录（若可得）。
**判定**：
- 正常分支：MTU 与返回字节满足期望；完整快照解码；逐 ID 本地处理；发布按绑定顺序完整；尾部不误当设备。
- 拒绝分支：MTU 不足或返回长度不足/非对齐 → 整帧拒绝，无任何读数/落库/入队/转发；原因可区分并有实际/期望字节；不补零、不拼接、不裁掉余字节。
- 容量：第 10 台被拒；>9 台不读取/不写 `0xA1`/不转发，状态可读；删除至 9 台后恢复。
- **不得以宿主 L0 结果替代真实 MTU/返回字节结论**；无法构造的分支记 NOT EXECUTED，完整交付不得据此判通过。
**阻塞条件**：无真实网关/无法读取 MTU 与 `value.size`/无 ≥9 台真实设备 → 对应子项 NOT EXECUTED；不得删除旅程；不得把“容量上界 160 B”写成“已支持 9 台”。

## 3. 证据汇总与判定规则

- 每条旅程输出一张证据索引：旅程号、执行时间、环境（设备/系统/网络/账号/网关/服务版本）、被测提交与 APK 摘要、**协商 MTU/返回字节（若适用）**、步骤、原始证据路径、期望、实测、结论、阻塞说明。
- 全部结论必须能被保存的原始证据复现；不得以“命令成功/退出码 0”替代业务结论。
- 前置不足或环境不可达：记 NOT EXECUTED 与缺失条件，不计入通过；不伪造、不外推。
- 真实 BLE、真实服务、模拟器、主机单测证据分开标注；模拟器/主机不能替代真实链路结论。
- 跨能力边界：真实传感器/网关/固件条件由嵌入式/硬件能力提供；本计划只消费其证据，不代替其实施或判定。服务端持久化由获准服务入口核验。
- 每条旅程执行后按 TD-SW-004 §6 清理测试偏好/绑定（含第 9/10 台测试绑定）、库内测试数据、设备状态、MQTT 客户端与后台任务，并保留清理前后证据。
- 最终判定遵循 TD-SW-004 §9：任一必需旅程 FAIL/NOT EXECUTED/CONDITIONAL/UNKNOWN → 完整交付不得判为通过；执行测试者返回 TEST_FAIL 并附当前版本失败报告。

## 4. 复跑与可重复性

- 所有 HTTP/SSH/ADB 命令须设置显式超时（只读诊断 ≤60 s，HTTP ≤15 s/次，有限次数）；超时记录，不原样无限重试。
- SSH 只读脚本沿用 `evidence/backend_exploration/` 的既有入口与脱敏方式；执行阶段若该入口未授权，记 NOT EXECUTED，不以其他未登记通道替代。
- MQTT 注入使用独立 `clientId`，禁止冒用真实网关身份；注入结果只作对照，不替代 BLE 证据。
- 每次执行记录服务/网关/设备状态快照与版本三元组，确保结论可关联到当前候选。
- 容量/完整性测试的绑定数据使用 8 位 HEX 测试 ID；执行前后备份并复原 `MyPrefs`；不清理用户真实数据。
- MTU/返回字节证据必须包含原始 logcat 行，不得只记录结论数字；不得以一次“读取成功”推断所有设备/所有周期均完整。
