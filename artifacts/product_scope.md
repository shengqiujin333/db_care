## 2. 产品目标与成功定义

### 2.1 用户目标

用户要的是**能在真实睡眠场景中工作的蹬被报警器**，不是“代码改完”或“测试脚本通过”。具体目标：

1. 传感器用 GXHT40 采集被窝温湿度，用光敏分压判断安装处是否有光。
2. 每 3 分钟采样一次；仅当本次温度比上次有效采集**高超过 0.9℃ 且无光**，或温度**超过 35.0℃**时，才经 433 MHz 上报。
3. 中继器把读数经 BLE 交给 Android App；App 正确归因、入库、按既有规则告警/展示，并在守护中且已注册手机号时上传云平台。
4. 平台服务器使用迁移后的地址/证书/端口/认证；上传具备 `(dev_id,time)` 幂等。
5. 传感器 UART1 可在 9600 8N1 下观测启动、周期、失败诊断，支持现场标定与排障。
6. 安装/运维人员有一份可执行、可独立核验的操作部署手册（部署、安装、配对、烧录、全暗标定、排障、回滚）。
7. 最终在真实传感器 + 真实网关 + 真实手机 + 真实服务器 + 真实暗/光/温度变化下完成总功能测试。

### 2.2 成功定义（产品级）

只有同时满足以下条件，才可称“本轮交付成功”：

- PACC-001 中所有 P0 验收项 PASS；
- P1 项 PASS 或由产品负责人书面接受风险；
- 全目标 F 级 E2E-01..E2E-08 完成，未覆盖项明确列出且不冒充通过；
- 操作部署手册由非实现者独立演练通过；
- 证据绑定当前提交/构建/设备/时间，且独立于实现者；
- 需求中的持续限制（硬件、网关、iOS、协议、供电、安全）未被违反。

**代码完成、构建成功、宿主机测试通过、App 能启动，均不等于产品成功。**

### 4.2 边界外（本轮不做）

1. **传感器/网关硬件**：PCB、器件、BOM、接线、外壳、CR2032 焊装方式不改。
2. **网关固件/工程/管理**：不修改 CH592 `beiwov2`，不刷写网关，不新增网关管理入口，不改配对/绑定逻辑。
3. **iOS App**：不实现、不修改；只保证线上布局不变，不宣称 iOS 已兼容验证。
4. **协议重构**：不新增光照/原因/时间/版本字段，不改 433 10 B 布局、BLE 16 B 块、AES/Feistel 密钥、MQTT topic、`/upload_data` 请求体。
5. **新功能**：不做 readme 之外的功能（如周期心跳、远程控制、新的云 schema、新的报警类型、App 重算传感器门控、光照显示）。
6. **服务器重架构**：不重装系统、不更换数据库/消息中间件、不改变认证规则、不引入新的管理面；只做迁移后的可用性与上传验证。
7. **权限与环境改造**：不修改 `runtime/permissions.yaml`、不自行扩大设备/网络授权、不重装驱动/系统、不改网络或网关配置。
8. **未确认的仪器/入口**：Bit Pirate、示波器、外接摄像头、旧 COM42、旧逻辑分析仪地址、未登记的网关管理入口，均不作为本轮范围或验收前提。
9. **以模拟替代真实验收**：宿主机 mock、仿真、旧运行证据不能替代真实条件总功能测试。

### 4.3 边界接口（只定义外部契约，不规定内部架构）

| 接口 | 边界 | 本轮约束 |
|---|---|---|
| 传感器 ↔ 网关 | 433 MHz，10 B 加密帧 | ID/温度/湿度/CRC 布局与 Feistel 不变；无 ACK |
| 网关 ↔ App | BLE FFE0/FFE2，AES-ECB | 16 B 头 + N×16 B 设备块；ID `|` hum u16be@4 `|` temp s16be@6 |
