状态：嵌入式测试设计产物（embedded_tester.embedded_test_design）
版本：5.0（替代 rev 4.0；与固件方案 FD-002 **rev 5.0**、需求 FWR-002 **v5.0**、运行时架构 RTA-002 **v5.0**、接口契约 IC-002 v3.0 对齐）
对象：蹬被报警器**传感器固件（CW32L010Y8M6，本次改动主体）**、**网关固件（CH592 beiwov2，只读核对，不改）**，以及**传感器 → 433 MHz → 网关 → BLE → 手机 App** 的端到端嵌入式验证。
能力边界：本文件**只做测试设计**（范围、适用性、前置/资源、方法、数据采集、判定、标定方法与交接），**不执行测试、不烧录、不修改被测固件源码**。执行由后续嵌入式验证能力按本计划选取适用项与回归项后承接。
基线：Git `1dd8e4b322123ce8c2a2b1fe10afe44fcf7fbe62`（用户指定的本轮测试与修复基线；接手时工作区干净）。设计时已核对：自 `1dd8e4b` 起**固件源码零改动**（其后的提交只改 `artifacts/`、`evidence/`、`file_manifest.txt`），因此**当前交付的固件源码与本基线逐字节相同**，本轮受测对象就是这条基线上的源码编出的镜像——不是 run7 的旧镜像，也不是历史证据里的结论。

> **本轮 rev 5.0 变更要点**（相对 rev 4.0）：
> 1. **对齐基线换成 `1dd8e4b` 并重核 as-built**：rev 4.0 登记的 D-02（光照 1/3 判据 + `light_result_t` + 无满量程回退）与 D-04（`debug_trace` 模块与 UART1 通道）**已在本基线落地**，不再作为待修正项；仍**未修**的是 D-01（上报判定仍为**降温方向**且对恰好 35.0 ℃ **整体排除**）与 D-03（待上报**无冻结快照**）；仍**未决**的是全暗基准未标定（`LIGHT_DARK_CALIBRATED=0`）与 OBS-1（真实目标 GXHT40 每周期 `q=0`）。
> 2. **新增诊断可观测性行为与用例**：上电 `BUS` 总线诊断行（空闲电平 + `0x08..0x77` 有界地址扫描 ACK 集合）与失败周期 `G` 行（结果码 / `0x44`·`0x45` 地址 ACK / 读重读次数 / 整帧重测次数 / 最近一次读回的 6 字节），并给出**诊断行解读（证据 → 可能环节）**指引与「一行证据不能定罪」的判定纪律。
> 3. **新增 `P` 行与冻结快照可观测**：待上报冻结样本的 `rq/s/y/t/h` 在真实目标可读，重试期间冻结样本不变、新触发不覆盖原有待上报。
> 4. **S 行解析口径由「实现可自定字面标签」改为「逐字节冻结的 as-built 单字符键」**（`k/p/H/V/o/n/x/a/D/t/h/q/r/s/y`），并按**线上原始字节**判 ≤96 B（as-built 最坏 92 B，rev 4.0 登记的「示例格式 105–115 B 超预算」风险已由实际实现压缩解决，验证方仍**不得**放宽上限）。
> 5. **修正本计划自身一处无验收依据的门槛**：rev 4.0 的 `C_dark` 标定用例要求「≥30 笔」样本；readme、IC-002 与 FD-002 rev 5.0 §6.3 均**未要求固定样本数量**，且明确禁止把固定样本数/额外仪器/额外遮光时长当作通过门槛。本版改为：**取得 1 笔有效全暗样本即可作为候选 `C_dark`**，多笔样本只用于记录分散度，**不设数量门槛**、不以样本少判失败。
> 6. **失败后重探与有界总线恢复**（FWR-118）纳入行为与用例：任何失败（含缓存地址读失败）后下一周期必须重探 `0x44`/`0x45` 并先做有界恢复（9 个 SCL 脉冲 + STOP），不得因缓存地址让器件永久失联；恢复与重试均有上限。
> 7. **「当前交付构建再观测」写为硬前提**（FWR-117）：所有实板结论的原始证据必须来自**本轮部署的镜像**（提交 + 产物摘要 + 横幅一致），历史证据只作背景。
> 8. 观测方法与能力边界一节扩充：明确 `BUS`/`G`/`P` 行各自**能证明**与**不能证明**什么，防止把「软件可见的诊断事实」外推为「位级电气结论」。

## 观测方法与能力边界（防止结论外推）

| 方法 | 能证明 | **不能**证明 |
|---|---|---|
| UART1 启动横幅 + `BUS`／`S`／`G`／`P` 行（9600 8N1，COM42） | 固件上电确实初始化 UART1 并输出；复位后行为；**诊断行给出的观测事实**：上电时 PA03/PA04 的空闲电平（软件读到的高低）与 `0x08..0x77` 中哪些 7bit 地址收到 ACK、失败周期的结果码/两地址 ACK/读重读次数/整帧重测次数/最近读回的 6 字节、待上报冻结样本；每周期软件可见状态（前一有效温度与存在标志、光照 valid/成功数/极值/均值/无光、温度 x10、湿度 x10、采样有效性、上报判定、发送结果、重试计数）；RTC 节拍；字段能由冻结公式自洽重算 | **I²C 位级电气与真实波形**：`BUS idle` 是软件在事务前读到的引脚电平，**不等于**上升沿/上拉阻值/建立保持时间合格；`ack` 只证明「该地址有器件应答」，不证明命令时序、tMEAS 等待余量、位采样点正确。空口波形/功率、电流、与参考仪器的**绝对**温湿度一致性同样不可由此证明 |
| `mdk_build`/`mdk_flash` 日志 | 当前提交能编译、能下载、回读校验通过（Verify OK）、目标在运行、被部署镜像可区分（横幅固件标识 + 产物摘要） | **任何**业务功能（编译/下载成功 ≠ 功能通过） |
| 网关在链 + 手机观测 | 同一次上报能走完 433 → 网关 → BLE → 手机；端到端字段、单位、符号一致 | 空口电气/时序/丢包率；手机内部业务与 UI 判定（属软件测试） |
| 宿主机 harness（本机 gcc，链接真实实现） | 纯逻辑与流程的确定性与**精确边界**（恰好 +0.9 ℃、恰好 35.0 ℃、全量原始字域、`C_dark` 全量域、冻结快照逐字节、有界重试与用尽、诊断行格式化与行长、地址扫描原语语义） | 真实目标行为；不得以 mock/构建结果冒充实板结论 |
| 完全遮光（不透光遮蔽物包住光敏器件与受光路径） | 全暗态下的原始 `o/n/x/a` 样本与「暗 ⟺ 读数高」的方向性 | 绝对照度值、暗箱级重复性、阈值邻界的精确扫描（后者归宿主机全量域） |
| 可选仪器（§4.10） | 位级时序与电气、空口波形、功耗、绝对精度 | 本轮未执行；不得以「仪器常见/更精确」为由写成通过前提 |

## 覆盖性与前置顺序检查

- readme 修改点 1（GXHT40）、2+7（光敏分压与全暗 1/3）、3（3 分钟）、4（升温 >0.9 ℃ 且无光 / 严格 >35 ℃）、8（UART1 初始化与打印），以及「不改硬件、空口/BLE 布局不变、不改网关代码、不改 iOS」，均有可独立观测的预期行为，**可设计测试**。
- 修改点 5（broker/服务器信息）属服务器/软件能力；修改点 6（同步修改 Android）在本计划中手机仅作**端到端观测器**，其 UI/业务/通知（含微信仅实时、不缓存不补发）属 software_tester。
- 本轮用户请求新增的三项要求均可测：**GXHT40 采集失败须可诊断**（`BUS`/`G` 行）、**全暗基准须来自实板完全遮光**（未标定不得冒充）、**验收须以当前交付构建的实板再观测为准**（不得引用历史证据）。
- 前置顺序（按内容，不引入任务编号）：**调试/诊断可观测性（含 `BUS` 行与失败周期 `G` 行）是 GXHT40 失败定位与修复的前置；GXHT40 每周期 `q=1` 是「无光判据可被触发」的前置；全暗标定与 `CALIBRATED=1` 是升温分支可用的前置；判定更正与冻结快照相互独立，均可各自验证**。靠前项不依赖靠后项；**未发现缺失、矛盾或不可测的增量**。
- **as-built 偏差（必须如实记录，不由本能力修复）**——当前工作树即 `1dd8e4b`：
  1. **D-01（上报判定方向错误）**：`fw_core.c::sensor_decide_report` 仍为 `prev - cur > SENSOR_REPORT_DROP_X10`（**降温**方向），且在升温分支之前对 `cur == 350` **整体排除**（恰好 35.0 ℃ 即使同时满足升温条件也不上报）。与本轮「本次比上次升高 >0.9 ℃ 且无光，或严格 >35 ℃」不符。相关实板与宿主机用例在本轮修正前会**合法地失败**。
  2. **D-03（待上报未冻结）**：`measure.c::send_data_to_gateway()` 直接读 `s_prev_temp_x10`/`s_last_hum_x10`，无冻结快照；跨周期重试期间新采样会推进前值 → 帧内容可被悄然替换。
  3. **OBS-1（GXHT40 实板采集失败）**：历史观测显示每周期 `q=0`、`t=0`、`h=0`（光照通路 `o=8` 正常）。当前基线**没有**区分失败环节的手段（无 `BUS`/`G` 行），因此本轮先补可观测性、再由一手数据定位与修复；**不得**用历史日志或 mock 代替本轮实板观测，也**不得**在失败状态下让任何上报/标定结论虚假通过。
  4. **未标定门禁**：`LIGHT_DARK_CALIBRATED=0`、`LIGHT_DARK_REF_CODE=0`（占位）→ `V=0`、`D=0`、升温分支关闭。这是**允许的中间状态**，但不得宣称「无光判定已验收」。
  5. **已在本基线落地（不属本轮偏差）**：光照 `light_result_t`（`valid=adc_ok&&CALIBRATED`、`dark = valid && 3*mean>=C_dark`、无滞回、无满量程回退）、UART1 `debug_trace` 模块（横幅 + 每周期 S 行 + 关闭只碰 UART1/PA05/PA06）与 3 分钟节拍。
- 面向旧语义的宿主机期望（降温方向、`cur==350` 整体排除、发送读前值、无 `BUS`/`G`/`P` 行）**不能作为本轮证据**；执行前必须确认期望已按本计划与 FD-002 rev 5.0 更新（§3.2、§6）。

### 4.4 L2 UART1 调试通道与诊断行（真实目标，本轮主观测层）

**前置/资源**：受测镜像（T-L1-09/12 已确认）、CW-DAPLink、USB-TTL 接传感器 J3.1/J3.2/GND、COM42 @**9600** 8N1、捕获窗口内触发复位的能力（下载后自动复位/重新上电，必须在捕获窗口内发生，否则横幅与 `BUS` 行会丢失）、捕获单次时长上限 300 s（需分区窗口）。

**解析约定（键名与顺序冻结，按 as-built 实现）**：

```text
BOOT fw=<固件标识> uid=<8 位大写 HEX> rst=<4 位大写 HEX> uart=9600
BUS idle=<0..3> scl=<0|1> sda=<0|1> ack=<addr7[,addr7...]|none[+]>
S k=<tick> p=<prev> H=<have> V=<lvalid> o=<ok> n=<min> x=<max> a=<mean> D=<dark>
  t=<temp> h=<hum> q=<sample_ok> r=<report> s=<send> y=<retry>
G s=<1..5> a44=<0|1> a45=<0|1> rd=<0..5> at=<1..3> raw=<12 位大写 HEX | ------------>
P rq=<0|1> s=<0|1|2> y=<0..3> t=<frozen temp x10> h=<frozen hum x10>
```

字段单位与语义：`k`=RTC 累计 1 分钟节拍；`p`/`t`=温度 x10（有符号）；`H/V/D/q/r`∈{0,1}；`o`=成功转换样本数（0..8）；`n/x/a`=ADC 原始码（0..4095，`o=0` 时三者均为 0）；`h`=湿度 x10（0..1000）；`s`=433 发送结果（0 未发送/1 成功/2 失败）；`y`=待上报重试计数；`idle`=空闲电平位掩码（bit0=SCL、bit1=SDA，1=高）；`ack`=收到 ACK 的 7bit 地址集合（最多 8 个，超出以 `+` 结尾；`none` 表示无地址应答）；`G s`=驱动结果码（1 入参/2 无器件/3 读失败/4 CRC 错/5 量程无效，成功周期不打印该行）；`a44`/`a45`=本轮两候选地址是否收到地址 ACK；`rd`=最近一次读事务消耗的重读次数；`at`=本轮整帧重测次数；`raw`=最近一次成功读回的 6 字节或 12 个 `-`；`P rq`=发送后是否仍待上报。**允许实现演进固件标识字符串**，但**字段类别、键名、顺序与单位在本版本内必须稳定**。

| T-L2-10 | **打印不改变采样/判定/发送结果** | 源码 + harness + 轨迹 | ① 静态/harness：`debug_trace_*` 只做格式化与 UART 收发，不写待上报状态、冻结快照、前值、采样标志（T-L0-07/11 佐证）；② 轨迹重算（T-L2-04/05）证明打印行与状态一致；③ 可选对照：用 `SENSOR_DEBUG_UART=0` 编出的镜像在同场景下，经手机观测确认触发/不触发模式与开启态一致 | harness stdout + 轨迹 + 手机观测 | 打印无业务副作用；开启态与关闭态的触发模式一致（若执行了可选对照） |
| T-L2-11 | **`BUS` 上电总线诊断行可观测且自洽** | 捕获窗口内复位 | 在同一复位捕获窗口内解析紧跟横幅之后（任何 I²C 事务之前）的一条 `BUS` 行；记录 `idle/scl/sda/ack` 原文 | 原始字节流 + `BUS` 行原文 | 恰出现**一条** `BUS` 行（后续周期不再出现）；`idle` 与 `scl`/`sda` 位一致（`idle` bit0=SCL、bit1=SDA）；`ack` 为 `none` 或地址集合且元素为合法 7bit 地址（非 `0x00`..`0x07` 保留段之外的越界值）、最多 8 个、含 `+` 时说明被截断；**该行内容与本板实际器件应答情况自洽**（与随后周期的 `G a44/a45` 不矛盾） |
| T-L2-12 | **`G` 失败周期诊断行（仅在失败周期出现且事实可复算）** | 出现温湿度失败周期 | 对每个 `q=0` 周期：确认该 `S` 行之后**紧跟**一条 `G` 行；解析 `s/a44/a45/rd/at/raw`；① 用独立 CRC-8 实现对 `raw` 的前 3 字节与后 3 字节分别复算并与 `raw` 中 CRC 字节比对；② 核对 `s` 取值集合为 `1..5` 且与 `a44/a45` 组合不矛盾（如 `s=2` 时两地址 ACK 均应为 0）；③ 核对 `rd∈0..5`、`at∈1..3`；④ `q=1` 的周期**不得**出现 `G` 行 | 逐行原文 + 独立 CRC 复算表 | 行出现条件正确；结果码/地址 ACK/计数/原始字节互相自洽且与本周期失败形态一致；成功周期无 `G` 行 |
| T-L2-13 | **`P` 行：条件出现且冻结样本与触发一致** | 出现上报判定或发送尝试的周期 | 对 `r=1` 或发生发送尝试的周期：确认紧跟 `S` 行（有 `G` 则其后）出现 `P` 行；核对 `P` 的 `t/h` 与**该周期触发样本**（该行 `S` 的 `t/h`）一致、`rq/s/y` 与 `S` 的 `s/y` 语义一致；对既无判定又无发送尝试的周期确认**无** `P` 行 | `S`/`P` 逐对原文 | `P` 行只在规定周期出现；`t/h` 为组帧实际使用的冻结样本；无额外 `P` 行 |
| T-L2-14 | **GXHT40 每周期采集有效且稳定（OBS-1 闭环判定）** | 连续 ≥3 个采样周期 | 逐周期解析 `S` 行：`q=1`、`t∈−400..1250`、`h∈0..1000`，并与现场环境（室温/湿度常识、遮光与加温动作）相符；观察跨周期稳定性与是否再出现 `q=0` | 连续 `S` 行原文 + 环境记录 | 连续多周期 `q=1` 且读数不发散、随实际环境变化合理 → 该项通过；若仍 `q=0`，以 `BUS`/`G` 一手数据定位并交实现侧修复（**不得**以「已诊断」代替「已恢复」） |

**`G` 行证据 → 可能环节（用于定位，**不构成结论**；结论必须由本轮实板数据组合判定，见 FD-002 §6.6.2）**：

| 观察组合 | 指向的环节 | 处置方向（仍须实板证据确认） |
|---|---|---|
| `BUS idle` 有 0 位（`scl=0` 或 `sda=0`） | 总线被拉低/无上拉/短路等电气问题 | 固件侧只能有界恢复；属硬件问题登记交接，**不得**用软件掩盖 |
| `ack=none` 且 `a44=a45=0` 而 `idle=3` | 器件不应答（供电/焊接/器件未就绪/变体） | 核对命令时序与上电余量；确实无应答则按硬件问题登记，保持失败路径（不上报/不伪造） |
| `ack=44`（或 45）但 `s=3`、`rd` 用满 | 读未就绪/等待不足/总线速率 | 按手册提高等待余量（保持有界）、必要时调整软 I²C 速率；保留 NACK 重读 |
| `ack=44`、`s=4` 且 `raw` 有值 | CRC 或位时序 | 用独立 CRC-8 复算 `raw` 判定是校验还是位采样问题；修时序/顺序而非放宽校验 |
| `ack=44`、`s=5` | 量程无效 | 核对换算与器件供电；**不得**放宽有效域 |
| 偶发单周期失败 | 噪声/时序边界 | 保持有界重试，不改变判定与上报语义 |

### 4.5 L3 光照通路、1/3 判据与全暗标定（真实目标）

**前置/资源**：受测镜像、COM42、**遮光手段**（不透光遮蔽物完全包住光敏器件及其受光路径，不按压器件、不遮挡调试排针）、当前环境「有光」（readme 修改点 7）。

| 编号 | 行为 | 前置/资源 | 方法 | 证据 | 判定 |
|---|---|---|---|---|---|
| T-L3-01 | **有光态读数与 `D=0`** | 当前有光环境 | 捕获 ≥2 条 `S` 行，记录 `V/o/n/x/a/D` | `S` 行 + 环境描述（可选照片旁证） | 标定后：有光态 `a` **明显低于** `ceil(C_dark/3)`；`D=0`；`o` 为 1..8；`n<=a<=x`；未标定阶段 `V=0`（门禁） |
| T-L3-02 | **完全遮光态读数与 `D=1`** | 完全遮光 | 遮住光敏器件后捕获其后的采样周期 | `S` 行 + 遮光方式记录（可选照片旁证）+ 时间戳 | 遮光态 `a` 显著高于有光态；标定后 `D=1` 且 `3*a>=C_dark`；移开遮蔽后恢复 `D=0`（同一板同一供电） |
| T-L3-03 | **判据方向与每笔独立** | 有光/遮光切换 | 交替遮光/受光连续多周期；比较「同一码值在不同历史下」的 `D`；核对阈值上下的方向 | `S` 行序列 | `D` 仅由本笔 `V` 与 `3*a>=C_dark` 决定；无滞回带、无历史暗态残留；方向为「读数越高越暗」 |
| T-L3-04 | **有效性语义（不可见时如实记录）** | 全部转换超时的可构造性 | ADC 全超时在实板通常不可控：**主证据在宿主机**（T-L0-04 + 光照 harness 的全部/部分超时用例：全超时 → `V=0`、`D=0`，不得合成 4095；部分失败 → 均值仅取成功样本、`o` 为实际成功数）；实板仅在可复现异常时补充 | harness stdout；实板如出现 `o=0` 则记录原始行 | 全超时不得产生 `V=1`/`D=1`；实板若观察到 `o=0` 行，检查是否与 harness 结论一致；无法在实板构造时**如实记录未覆盖**，不伪装 |
| T-L3-05 | **全暗基准 `C_dark` 实板标定数据采集** | 完全遮光 + COM42 | 按 FD-002 rev 5.0 §6.3：PB05 供电/建立等待/取样次数与量产一致（由固件固定）；器件**完全遮光**（不按压器件、不遮挡调试排针）；从轨迹采集遮光期间各周期的 `o/n/x/a/D`，**取得 1 笔有效全暗样本即可作为候选 `C_dark`**；若现场能多跨 1–2 个采样周期则一并记录，用于给出样本分布（min/max/mean/中位）与分散度；随后移开遮蔽并记录恢复后的 `o/n/x/a` | 原始 `S` 行集合 + 分布统计表 + 计算过程 + 板件标识/供电/遮光方式说明/实际取样次数/固件配置版本 | `C_dark` 取全暗实测有效均值（或稳健中位），取值 1..4095；**不得**用满量程 4095、旧默认 350/250 或亮态读数冒充；**不得以固定样本数量、额外仪器或额外遮光时长作为通过门槛**，样本少本身不构成失败；有光均值必须明显低于 `ceil(C_dark/3)`，否则如实登记原始数值并作为阈值/器件问题交接 |
| T-L3-06 | **稳定等待与取样重复性（软件可见部分）** | 同一环境重复采样 | 比较同环境下多周期的 `a` 离散度与 `o` 是否稳定为 8 | `S` 行统计 | `a` 重复性落在可见噪声带内、`o` 稳定；PB05/PB04 实际波形与建立时间属可选扩展（§4.10） |
| T-L3-07 | **未标定门禁与回填闭环** | 标定数据 + `sensor_config.h` | ① 未标定阶段：轨迹 `V=0`、`D=0`，升温分支不触发（即使升温也不上报），报告明确写「无光判定未验收」；② 完成标定后：核对 `LIGHT_DARK_REF_CODE` 回填、`LIGHT_DARK_CALIBRATED=1`，重建后重跑 T-L3-01/02/03 与 T-L5 相关判定 | 配置快照 + 标定记录 + 复跑 `S` 行 | 未标定不得宣称无光判定通过；**回填与置位属实现能力**（本能力只提供方法与数据，交接见 §6） |
| T-L3-08 | **标定值可解释性（回填后）** | 回填后的镜像 | 由轨迹 `a` 反算 `ceil(C_dark/3)` 所需阈值，核对与 `sensor_config.h` 的 `C_dark` 一致（可用 `D` 翻转点或极值样本夹逼） | `S` 行 + 配置快照 | 二者一致；不一致登记为配置/实现缺陷 |

**现场最小操作与时间窗口（需用户配合，不设额外门槛）**：盖上不透光遮蔽物后，器件需跨过**下一次采样机会**才会产生一笔全暗样本（采样节拍 3 分钟，最坏等待约 3 分钟 + 采样与打印时间）；若需确认读数稳定，可保持遮蔽至其后的 1–2 个采样周期（约 6–9 分钟）再移开。若现场只能提供较短的遮光窗口，**取得 1 笔有效全暗样本即可作为候选 `C_dark`**，但必须在记录中如实写出样本分散情况；**不得**把「样本数量不足」本身当作失败，也**不得**为凑固定样本数而延长现场操作或引入额外仪器。

### 4.6 L4 3 分钟节拍、顺序与单周期单次（真实目标）

**取舍说明**：串口单次捕获时长上限 300 s 且**原始产物不含逐字节时间戳**，因此用**分区捕获窗口**：连续执行若干定长窗口（建议 10–30 s），记录每个窗口的起止时间与是否含 `S` 行；窗口宽度即时间分辨率。节拍的**内部**证据是 `k` 增量，**外部**证据是窗口归属，两者必须一致。

| 编号 | 行为 | 前置/资源 | 方法 | 证据 | 判定 |
|---|---|---|---|---|---|
| T-L4-01 | **采样周期 ≈3 分钟** | COM42 分区窗口 | 复位后在捕获窗口内开始；连续执行覆盖 ≥2 个采样间隔的窗口序列；统计相邻两条 `S` 行落在的窗口 | 每窗口起止时间 + 是否含 `S` 行 + 原文 | 相邻采样间隔 ≈180 s（误差不超过窗口宽度量级）；**同时** `k` 增量必须为 3（或每行均为 3，取决于实现语义，先由实现确认）；记录实测间隔与离散度，**不自造容差**（RTC 用 LSI，readme 未给精度） |
| T-L4-02 | **单周期单次测量 + 顺序** | 同上 | 统计一个采样间隔内 `S` 行数量；核对同期光照字段与温湿度字段来自同一周期（同一行内成对出现） | `S` 行序列 | 一个周期恰好一条 `S` 行（失败重试不算重复周期）；同一行内含光照与温湿度结果，未被拆成两行 |
| T-L4-03 | **无 1 分钟节拍残留** | 同上 | 覆盖 ≥6 分钟的窗口序列确认不存在每 1 分钟一条的结构 | 窗口序列 | 无 1 分钟节拍残留 |
| T-L4-04 | **上电启动采样机会** | 复位控制 | 复位后立即观察是否在无需等待 3 分钟即出现首条 `S` 行；核对首笔 `H=0` | `S` 行 + 窗口时间 | 上电后有一次立即采样（首行 `H=0`），随后转入 3 分钟节拍；首笔仅 `t>350` 时 `r=1` |
| T-L4-05 | **发射期间节拍不丢** | 联测 | 让某周期触发上报（见 T-L5），观察该周期与下一周期的窗口归属与 `k` | 窗口序列 + `S` 行 | 上报（有界超时内）不影响下一拍时间基准；`k` 不丢 |

### 4.7 L5 条件上报判定与端到端（真实目标/联测，核心）

**激励手段（已确认可获得）**：温度用**局部加温**（握在手心/夹于腋下/放入被窝/暖水袋隔布加热；**不得**用明火或直接接触热源烫伤器件）产生 ≥1.0 ℃ 的升温；光照用**遮光手段**产生无光；**>35.0 ℃** 用可持续高于 35 ℃ 的加温方式（细节见 §6）。
**边界说明**：恰好 +0.9 ℃（差=9）与恰好 35.0 ℃ 的精确边界**无法**在实板稳定构造，其判定以宿主机 T-L0-05 为准；实板验证方向性与门控。
**判定手段**：轨迹 `r/s/y` + `P` 行（主）+ **手机在同一时段收到该笔读数**（联动证据）。每步只改一个变量。

| 编号 | 场景 | 期望（IC-002 §2 / FWR-104） | 判定要点 |
|---|---|---|---|
| T-L5-01 | 有前值；遮光；本次比上次升温 ≥1.0 ℃ | 上报 | 该周期 `r=1` 且 `s=1`；`P` 行冻结样本与该周期 `t/h` 一致；手机收到该笔且显示温度一致（同一笔） |
| T-L5-02 | 有前值；**有光**；同样升温 ≥1.0 ℃ | 不上报 | `r=0` 且该周期无发送记录、无 `P` 行；手机无新读数（记录观察窗口） |
| T-L5-03 | 有前值；**光照无效**（未标定阶段或 `V=0`）；升温 ≥1.0 ℃ | 不上报（升温分支关闭） | `r=0`；`V=0`；无发送 |
| T-L5-04 | 有前值；遮光；**降温** ≥1.0 ℃ | 不上报 | 方向为升温，降温恒不触发（**当前基线实现为降温方向，本项会失败，属 D-01**） |
| T-L5-05 | 有前值；遮光；升温但**未达 1.0 ℃**（如仅 +0.2..0.5 ℃） | 不上报 | 记录差值（以 x10 整数差为准）与实际 `r`；只要差值 ≤9 即不得上报 |
| T-L5-06 | 无前值（复位后首笔）；温度 ≤35.0 ℃ | 不上报 | 首笔 `H=0`、`r=0`；无发送 |
| T-L5-07 | **温度严格超过 35.0 ℃**；有光 | **上报** | 超温分支独立于光照与前值；`r=1` 且手机收到 |
| T-L5-08 | **温度严格超过 35.0 ℃**；遮光或光照无效 | 上报 | 与 T-L5-07 结论一致（光照不影响超温分支） |
| T-L5-09 | 上报成功后同条件持续（无新升温） | 不重复上报 | 连续 ≥2 周期无新触发；证明「3 分钟是采样周期而非上报周期」且成功后清除 |
| T-L5-10 | 有前值；遮光；连续多个周期（≥3）无显著变化 | 不上报 | 无周期保活；无 0 值/合成样本；`t/h` 仍逐周期有效（`q=1`） |
| T-L5-11 | 上报周期内的 433 发送 | 帧内容 = 触发样本 | `P` 行冻结 `t/h` 与手机端读数一致（同一笔，非相邻周期值）；`s=1` |
| T-L5-12 | 轨迹 `s/y` 与触发自洽 | 无伪造 | `r=1` 的周期 `s∈{1,2}`；`r=0` 且无跨周期待上报时 `s=0` 且 `y=0`；若 `s=2` 出现，须与真实链路条件（遮挡/距离）对应并记录 |
| T-L5-13 | 失败周期不推进前值（实板可见部分） | 失败周期无有效读数推进、无发送 | 与 T-L6 联测；轨迹显示该周期 `q=0`、无发送；下一周期 `p` 仍为失败前的有效值 |
| T-L5-14 | 有前值、遮光、升温 ≥1.0 ℃ 但**上一周期温湿度失败** | 以失败前的前值判定 | 与 T-L5-13 联合：恢复后给出的 `p` 必须等于失败前的有效样本 |
| T-L5-15 | **`P` 行冻结样本与发送一致（含跨周期重试）** | 上报周期 + 出现重试的周期 | 触发周期的 `P t/h` 与该周期 `S t/h` 一致；若出现跨周期重试（`y>0` 持续），核对**后续周期的 `P t/h` 保持同一冻结值**，而同期 `S t/h` 随新采样变化 | `P` 行原文序列 | 冻结样本在重试期间不变、与 `S` 的新采样值解耦；成功或放弃后 `rq` 按语义翻转 |
| T-L5-16 | **待上报未清除期间新触发不覆盖** | 需构造连续两次触发（如持续加温跨≥2 周期且期间发送未成功） | 观察 `P` 行的 `t/h` 是否在首次触发后保持同一值、不被第二次触发替换；`y` 是否按重试语义递增 | `P` 行序列 + 链路条件记录 | 新触发不覆盖既有冻结样本；若实板无法构造（发送未失败或无法持续加温），记「未覆盖」并注明最小所需条件，**不伪造** |

> 所有内部判定用例必须与至少一次真实手机收到的读数结论一致；不一致时以端到端结果为准并登记缺陷。

### 4.8 L6 冻结样本、失败路径、有界性与诊断复算

| 编号 | 行为 | 前置/资源 | 方法 | 证据 | 判定 |
|---|---|---|---|---|---|
| T-L6-01 | **跨周期重试期间冻结快照逐字节一致** | 宿主机 `measure.c` + 发送桩（可脚本化失败/成功次数） | 触发一次上报后让发送连续失败并跨过 ≥1 个新采样周期（新采样值不同、光照不同），逐次导出待发送帧并逐字节比对触发时刻冻结样本 | 每次发送的帧十六进制 + 触发时刻样本 + stdout | 所有重试帧**逐字节一致**且等于触发时刻冻结样本；不随新采样/前值推进/最近湿度改变 |
| T-L6-02 | **用尽放弃不伪造成功** | 同上 | 让失败次数超过重试上限，检查待上报状态与后续行为 | stdout + 状态 dump | 达到上限即放弃本轮、不返回成功、后续周期可重新判定；不得无限重试 |

9. **0.9 ℃ 含等于（FWR-OPEN-2）**：IC-002 v3.0 冻结为「严格大于 0.9 ℃」（差 >9，即 ≥1.0 ℃）；实板按 T-L5-05 记录实际差值行为，精确边界归 T-L0-05。

## 7. 风险与限制

| 风险 | 影响 | 缓解 |
|---|---|---|
| 启动横幅/`BUS` 行丢失（复位未落在捕获窗口内） | 无法证明「上电初始化并打印」与总线身份 | 捕获先开、窗口内复位；若仍不可得，如实记证据缺口（不得用后续周期行替代横幅/`BUS` 结论） |
| 分区窗口分辨率限制节拍精度 | 节拍实测精度受窗口宽度限制 | 用 10–30 s 窗口缩小分辨率；同时用 `k` 增量作为内部证据；记录离散度，不造容差 |
| 当前基线仍为旧语义（D-01/D-03）与未标定（`CALIBRATED=0`） | 直接执行会失败，可能被误判为「测试设计错误」 | 明确期望来自 FD-002 rev 5.0/IC-002 v3.0/readme；失败即证据，登记缺陷并交接实现能力；不下调期望 |
| OBS-1（`q=0`）未闭环 | 温湿度数据不可用，且无光判据无法在真实场景触发 | 先以 `BUS`/`G` 行取一手数据定位，再按证据修复并复验 T-L2-14；**不得**以「已诊断」代替「已恢复」，也不得在 `q=0` 时宣称其它依赖温湿度的结论通过 |
| `G`/`BUS` 行被误当作位级电气结论 | 结论外推 | §4.4 明确「能证明/不能证明」；位级问题归 §4.10 可选仪器，判定中标注未覆盖 |
| 旧 harness 期望未更新 | 用旧 pass 冒充新语义证据 | T-L0-10 要求先核对期望来源；T-L9-05/06 清零旧语义并核对 `S` 行兼容 |
| `C_dark` 未标定或遮光不彻底 | 升温分支不可用或阈值错误 | T-L3-05 完全遮光采集 + 分布记录（不设样本数门槛）；T-L3-07 未标定门禁；有光均值必须明显低于阈值，否则登记器件/分压问题 |
| 实板无法精确构造 0.9 ℃/35.0 ℃ 边界与 ADC 全超时 | 边界与异常路径无法在实板证明 | 明确归宿主机 T-L0-04/05 与光照 harness；实板只验证方向性与门控；必要时记证据缺口 |
| 无法稳定加热到 >35.0 ℃ | 超温分支缺实板证据 | 尝试多种可持续加温方式；确实不可得时对应用例记 BLOCKED 并写明最小所需条件，不得伪造 |
| 目视/时间对应误差（轨迹与手机读数对应错笔） | 端到端比对结论错误 | 记录时间窗并只取同一时段唯一一笔；用 `P` 行冻结样本与手机读数双重匹配 |
| 任意诊断行超 96 B | 违反本轮明确预算 | T-L2-03 按线上原始字节判定并登记；不得放宽 |
| UART 关闭破坏软 I²C/SWD | 后续周期失效或无法再次下载 | T-L2-07/08 以「后续周期仍有效 + 再次下载 Verify OK」验证 |
| 单一证据下结论 | 误判 | 每个实板/联测结论至少两类独立证据（§5）；mock/宿主机结论必须标注层级 |
| 旧镜像/旧包冒充当前交付件 | 验证了错误对象 | T-L1-09/12 强制记录提交/产物摘要 + 横幅标识 |

## 8. 准入与退出准则

**准入（开始执行的条件）**
- 固件实现完成且 L0/L1 可运行（`test/build_test.sh` 与 Keil 构建可用）；
- 传感器板按新硬件焊装（GXHT40 + 光敏分压）且可上电；
- 已确认：下载调试探针在线、COM42（9600）在线、网关已供电、手机在位、Keil 工具授权；
- 明确受测提交 hash 并能编出与之对应的镜像，`mdk_flash` 日志含 Verify OK；
- **诊断与判定增量已由实现能力落地**（`BUS`/`G`/`P` 行、冻结快照、升温方向判定），且 harness 期望已更新；
- 可获得完全遮光手段；可获得把传感器稳定加热到 >35.0 ℃ 的方式（否则仅超温相关用例记 BLOCKED）。

**退出（执行能力的判定依据）**
- 适用用例期望与实际一致 → 判定通过；
- 期望与实际不一致 → 记录为缺陷（含最小复现、证据、时间点），交实现能力修复后重新构建复验；
- 前置条件缺失（无设备/未授权/无观测手段/无协议定义/无法构造必要激励）→ 对应用例返回 BLOCKED，不得记为通过；
- 需求未定义项（`C_dark` 数值、3 分钟精度、深睡电流合格线、保活策略、`G` 行结果码取值集合之外的扩展）→ 只记录实测与偏差，提交负责能力/需求方确认，不自行判定合格。
