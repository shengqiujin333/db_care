## 2. 测试范围与适用性

### 2.1 覆盖的产品行为

| 编号 | 行为（来源） |
|---|---|
| B1 | GXHT40 温湿度采集：地址探测（0x44/0x45）、`0xFD` 高重复率测量、按 tMEAS 上限等待、6 字节读取、温度字/湿度字分别 CRC-8 校验、x10 整数换算与有效域（readme 1；FD-002 §2.2/§6.1/§6.2） |
| B2 | 光照判据：PB05 供电 → 稳定等待 → PB04/AIN11 多次采样取均值 → 阈值 + 滞回得 DARK/LIT（无光=读数高）；采样后 PB05=低；ADC 轮询有界（readme 2；FD-002 §2.3/§6.3） |
| B3 | 3 分钟采样节拍：RTC 1 分钟中断累计 3 次触发一次采样；单周期内只测一次；先光照后温湿度（readme 3；FD-002 §4/§5） |
| B4 | 条件上报：`((prev−cur) > 0.9 ℃) 且 DARK` 或 `cur > 35.0 ℃` 才发 433（readme 4；IC-002 §2；FD-002 §6.4） |
| B5 | 失败不伪造：I²C 读 NACK/CRC 错按上限有界重试；整周期失败不上报、不更新前一有效温度、不构造 0 值（FD-002 §10；FWR-107） |
| B6 | 空口与 BLE 布局不变：433 明文 10 B `uid|temp_LE|hum_LE|crc16_LE` + 既有 Feistel；BLE 每设备 8 B `id|hum_BE|temp_BE`；不新增光照字段；网关不二次门控（IC-002 §3/§4；FD-002 §8/§9） |
| B7 | 旧通路退役且不再争用 PB04/PB05/PB06：无 hall EXTI、无 OPTCFG、无 params NVM 写、无 history 历史环；PB04 仅 AIN11 模拟输入、PB05 仅光照供电输出、PB06 不外驱动（FD-002 §3.3；FWR-111） |
| B8 | 低功耗：非采样期深睡、GXHT40 待机、分压无电流、I²C 引脚不主动拉低、调试 UART 关闭、433 有界（FWR-106；RTA-002 §3.3） |
| B9 | 运行时/中断边界：单线程超级循环，无 RTOS；RTC ISR 只计数置标志；ADC 走轮询不用中断；GPIOB 霍尔中断分支与 LPTIM OPTCFG 分支移除（RTA-002 §1.1–§1.3） |
| B10 | 未标定标志：`LIGHT_DARK_CALIBRATED` 显式为 0 时不得宣称「无光判定已验收」；标定回填后置 1（FD-002 §12 标定要求；FWR-OPEN-1） |

## 3. 测试层次、可用测试资产与总体策略

### 3.1 层次

| 层 | 名称 | 环境 | 目的 |
|---|---|---|---|
| L0 | 宿主机纯逻辑/流程 | 本机 gcc（真实 `.c` + 仿真 MCU 影子头/mock 总线） | 判定/换算/CRC/状态机的确定性与边界，回归最快 |
| L0i | 宿主机空口互操作 | 本机 gcc（真实传感器 encoder + 真实网关 decoder） | 不依赖硬件的字段顺序/字节序/加密回归 |
| L1 | 构建、静态与部署一致性 | 本机 + MDK/IAR 工程 + SWD 烧录回读 | 可构建、资源达标、退役符号消失、无浮点、部署镜像与受测提交一致、未标定标志正确 |
| L2 | 单板功能与协议 | 传感器板 + SWD + 逻辑分析仪 + 串口 | I²C 时序、光照通路、节拍、休眠 |
| L3 | 系统联测 | 传感器 + 网关 + Android + 433 通路 | 条件上报、边界矩阵、端到端数据正确 |
| L4 | 功耗 | 电流表/SMU + CR2032 回路 | 深睡/单周期/发射能量与预算核对 |

原则：先 L0/L0i/L1，再 L2，再 L3/L4；L3/L4 的每条用例至少留存「手机侧结果 + 串口/网关日志 + 波形/电流」中的两类独立证据，禁止单点证据定罪。

### 4.4 传感器 I²C 与 GXHT40 驱动 `[实板]`（用例组 T-L2）

| 编号 | 行为 | 前置/资源 | 方法 | 证据 | 判定 |
|---|---|---|---|---|---|
| T-L2-01 | 总线物理与地址探测 | 传感器板上电（3.0 V 台架或 CR2032）、逻辑分析仪接 PA03/PA04、4.7 kΩ 上拉到 BAT | 抓一个采样周期完整 I²C 事务：START→地址写（`0x88` 或 `0x8A`）→`0xFD`→STOP→（等待）→START→读地址（`0x89`/`0x8B`）→6 B→NACK→STOP | 原始波形 + 解码文本 + 时间戳 | 地址字节与实装变体一致（0x44→0x88/0x89，0x45→0x8A/0x8B）；空闲被外部上拉为高；每字节 ACK 存在 |
| T-L2-02 | tMEAS 等待下界 | 同上 | 量测 `0xFD` STOP 沿到读地址首个 SCL 上升沿的时间 | 波形时间差 | ≥ 8.3 ms（高重复率 max）；按 FD-002 §11.3 取 10 ms 更佳；读 NACK 后重读间隔 ≥1 ms 且总重试 ≤ `GXHT40_READ_RETRY` |
| T-L2-03 | 连续读时序正确 | 同上 | 复核 6 字节读取：前 5 字节主机 ACK、第 6 字节 NACK，随后 STOP；顺序 `T_MSB,T_LSB,T_CRC,RH_MSB,RH_LSB,RH_CRC` | 波形 + 解码字节 | 与手册 §7.2 一致（温度在前）；不依赖 clock stretching |
| T-L2-04 | 测量值与参考一致 | 可控温箱/冰水浴 + 参考温湿度计 | 至少 3 个温度点（≈5/25/40 ℃）与 2 个湿度点稳定后，比对**经空口或钩子读出**的值与参考值 | 参考仪器读数 + 传感器记录（含时间） | 偏差在参考仪器与 GXHT40 手册精度合计范围内；超范围登记为缺陷，不得自行放宽 |
| T-L2-05 | 负温符号 | 冰箱/冷箱 ≈ -10 ℃ | 冷透后触发一次上报（超温或下降分支），在网关/Android 侧读温度 | 端到端三方证据 | 读数为负且大小正确；BLE `s16be@6` 不出现 6 万级大数 |
| T-L2-06 | CRC 错误路径 | 逻辑分析仪 + 故障注入（拉低/断开 SDA/SCL 使回读全 1/全 0，或 I²C 从机模拟器） | 连续若干周期注入错误，观察是否重发 `0xFD` 重测、重试是否有界、周期后是否恢复 | 波形 + 电流 + 行为 | 每次 CRC 错丢弃整帧并重测；重试 ≤ `GXHT40_MEAS_RETRY`；用尽后本周期结束不挂死 |
| T-L2-07 | 总线被拉低卡死恢复 | SDA 短接 GND 一段时间后释放 | 释放后观察下一周期是否恢复通信；观察电流是否受限 | 波形 + 电流 | `sf_i2c` ACK 超时路径发 STOP 返回失败；后续周期可恢复；无无限等待（无持续 mA 级电流） |
| T-L2-08 | 无器件/未焊接 | 取下 GXHT40 | 观察一个完整采样周期行为 | 波形 + 空中（应无发射）+ 电流 | 失败路径：不上报、不构造 0 值；周期有界结束并回深睡 |
| T-L2-09 | 地址变体覆盖 | 分别装 0x44 与 0x45 变体（或从机模拟器） | 对两种地址各跑一次采样周期 | 波形 + 读数 | 两种地址均可被探测并读数；探测结果被缓存，不每周期重复扫描 |

### 4.6 3 分钟节拍与单周期单次测量 `[实板]`（用例组 T-L4）

| 编号 | 行为 | 前置/资源 | 方法 | 证据 | 判定 |
|---|---|---|---|---|---|
| T-L4-01 | 采样周期 = 3 分钟 | 传感器板 + 逻辑分析仪（PB05）或电流波形，长时基 ≥30 min | 连续记录 ≥10 个 PB05 窗口（或电流唤醒沿）的间隔 | 波形/时间戳表 | 相邻间隔为 3 分钟。RTC 基于 LSI，需求未给精度指标，故**记录实测偏差与离散度**，不自行造容差；偏差显著影响产品行为时上报需求方确认 |
| T-L4-02 | 单周期单次测量 | 同上 + I²C 波形 | 统计单个 PB05 窗口内的 I²C 事务组数 | 波形 | 一个周期只发生一次「光照 + 一次温湿度测量序列」（失败重试不算重复周期） |
| T-L4-03 | 无 1 分钟采样残留 | 同上 | 长时基确认不存在每 1 分钟一次的结构 | 波形 | 无 1 分钟节拍残留（FWR-103） |
| T-L4-04 | 唤醒后回深睡 | 电流波形 | 观察每周期活动段（约 113/140 ms 量级）之后电流回落 | 电流曲线 | 活动段有界；随后回深睡平台；无持续高频唤醒 |
| T-L4-05 | 发射期间节拍不丢 | 逻辑分析仪 + 433 发射 | 让某周期触发上报，观察该周期发射期间与下一周期 RTC 唤醒沿 | 波形 | 发射（≤200 ms 上限）不影响下一拍时间基准；RTC 计数不丢失 |

### 4.7 条件上报判定（空口边界矩阵）`[联测]`（用例组 T-L5，核心）

方法：用可控温度激励（恒温箱/热风/冰袋对传感器头部）建立「前一有效温度」，再改变温度与光照条件构造下述情形；每次只变一个变量，观测 433 空中是否出现新帧（433 接收机或网关日志），并记录解出的 `temp/hum/id`。内侧判定可用钩子报告的 `report` 值替代，但**至少一次必须以真实空中帧验证**。

| 编号 | 场景 | 期望（FD-002 §6.4 / FWR-104） | 判定要点 |
|---|---|---|---|
| T-L5-01 | 下降 1.1 ℃（`prev−cur=11`）且 DARK | 上报一次 | 帧内容=本次温湿度；之后无新变化不再重复上报 |
| T-L5-02 | 下降**恰好 0.9 ℃**（差 9）且 DARK | **不上报**（IC-002 严格解释） | 记录为「0.9 含等于」未决项双分支证据（§6）；不得因未决判缺陷 |
| T-L5-03 | 下降 >0.9 ℃ 但 LIT | 不上报 | 光照为必要条件 |
| T-L5-04 | **恰好 35.0 ℃**（`cur=350`） | 不上报 | 严格超过 |
| T-L5-05 | 35.1 ℃（`cur=351`）任意光照 | 上报一次 | 超温分支不受光照与前值限制 |
| T-L5-06 | 无前值（冷启动/复位后）且 `cur=200` | 不上报（不强制上报首样本） | 复位后首个周期无帧；与 FWR-108 一致 |
| T-L5-07 | 无前值且 `cur=351` | 上报 | 超温分支独立成立 |
| T-L5-08 | 前值存在、稳态无变化 | 不上报（无周期保活） | 连续 ≥3 周期无帧；证明 3 分钟是采样周期而非上报周期 |
| T-L5-09 | 上报成功后同条件持续 | 不重复上报 | 上报即清除待上报状态 |
| T-L5-10 | 温度上升但未超 35 ℃（25→30 ℃）且 DARK | 不上报 | 只对下降（非超温）敏感，不用历史窗口统计 |
| T-L5-11 | 光照条件在阈值带内摆动（滞回带内） | 不产生反复上报 | 滞回抑制抖动；带内多次采样判定稳定 |
| T-L5-12 | 恰好 0.9 ℃ 且超温分支同时成立（`cur=351`） | 上报 | 超温优先，独立于下降分支与光照 |

### 4.8 失败路径与有界性 `[实板/联测]`（用例组 T-L6）

| 编号 | 行为 | 前置/资源 | 方法 | 证据 | 判定 |
|---|---|---|---|---|---|
| T-L6-01 | 失败不更新前值 | 钩子（优先）或行为反推 | ①建立前值 30.0 ℃；②注入一个周期 I²C 故障（失败、不上报）；③恢复并把温度降到 28.8 ℃（相对 30.0 差 1.2 ℃）且 DARK，观察是否上报 | 波形 + 空中帧/钩子 | 恢复后必须上报（说明前值仍是故障前 30.0 ℃）；若实现用了失败周期的值，本项失败 |
| T-L6-02 | 失败周期不发 0 值帧 | 同上 | 检查故障周期空中无帧、网关无 `temp=0` 记录 | 433 接收记录 + 网关日志 | 无帧、无 0 值记录 |
| T-L6-03 | 433 发送失败有界重试 | 屏蔽 433（移开/衰减/取下接收端） | 使上报条件成立，观测发射尝试次数与时长 | 电流曲线 + PB02/PB03 波形 + 另一接收机 | 尝试 ≤ `SENSOR_RF_TX_RETRY`；单次超时 ≤200 ms；用尽后本轮放弃回深睡；**无持续发射或死循环**；下一周期正常重试 |
| T-L6-04 | 失败不阻塞下一拍 | 同上 | 移除屏蔽，等待下一周期 | 波形 | 节拍不漂移、能重新上报 |
| T-L6-05 | 光照与温湿度同时失效 | 断开光敏 + 取下 GXHT40 | 观察若干周期 | 电流 + 空中 | 不产生上报；有界结束；深睡电流正常 |
| T-L6-06 | I²C 读 NACK（转换未完成）路径 | 从机模拟器延迟应答 | 在读到 NACK 时观察重读行为 | 波形 + 钩子重试计数 | 等待 1 ms 后重读，总重试 ≤ `GXHT40_READ_RETRY`；用尽归入整周期失败路径 |

### 4.9 端到端链路（433 → 网关 → BLE → Android）`[联测]`（用例组 T-L7）

| 编号 | 行为 | 前置/资源 | 方法 | 证据 | 判定 |
|---|---|---|---|---|---|
| T-L7-01 | 10 B 帧解出正确字段 | 网关板 + 网关日志/nRF Connect + Android | 触发一次上报，抓网关接收与解密结果，核对 `uid/temp/hum` 与本次实际值 | 传感器侧（钩子/参考仪器）+ 网关日志 + 手机读数（同一时刻） | 三处一致；`hum` 与 `temp` 不交换 |
| T-L7-02 | BLE 记录顺序与 Android 解析 | 同上 + 已装 App 真机 | 读 FFE0/FFE2，核对每设备 8 B = `id|hum_BE|temp_BE`；App 显示与之一致 | BLE 原始十六进制 + App 截图/日志 | 与 `parsePlainFrame`（`u16be@4`/`s16be@6`）一致；无温湿度互换 |
| T-L7-03 | ID 归因 | 多设备同场（若可用）或单设备重复上电 | 核对空口 4 B ID = 网关记录前 4 B = App 归因 ID；反复上电 ID 稳定 | 多方十六进制对照 | 4 字节 ID 完全一致且稳定；App 不以列表顺序代替 ID |
| T-L7-04 | 网关不二次门控 | 网关日志/抓包 | 传感器上报一帧不符合「网关自身历史」条件的降温数据，确认网关仍转发 | 网关日志 + 手机读数 | 网关收到即转发（IC-002 §3、FD-002 §9） |
| T-L7-05 | 网关回归不变 | 同上 | 对照改动前后网关 BLE 特征长度、组块行为、服务/特征 UUID | 抓包/日志比对 | 未改变（本设计预期网关无功能改动）；若不一致，按接口契约对齐属网关实现能力的交接 |
| T-L7-06 | 负温端到端 | 见 T-L2-05 | 与 T-L7-01/02 联合执行 | 同上 | 手机端显示负温正确 |
| T-L7-07 | 无上报时 App 不合成数据 | 稳态无触发条件连续 ≥3 周期 | 观察 App/云端是否出现伪造样本或 0 值 | 网关日志 + App 记录 | App 不把「未收到」当 0，不按每 3 分钟合成（IC-002 §5） |

### 4.10 功耗与电池 `[功耗]`（用例组 T-L8）

| 编号 | 行为 | 前置/资源 | 方法 | 证据 | 判定 |
|---|---|---|---|---|---|
| T-L8-01 | 深睡电流 | nA/µA 级电流表或 SMU 串入电池回路；无采样活动 | ≥10 min 连续记录非采样期电流平台 | 电流曲线 + 统计 | 记录实测值并与 RTA-002 §3.3 估算（MCU 深睡 ~1.5 µA 量级）对照；RTA-002 已声明该值为待实测假设，偏差超同一数量级记「预算需回填/需求方确认」，不作自造合格线 |
| T-L8-02 | 单周期能量 | 同上 + 时间同步 | 记录 3 分钟窗口活动段电荷（光照等待 + ADC + I²C + 可选发射），计算日均 µAh | 电流曲线 + 积分 | 与 RTA-002 ≈100 µAh/天（不上报）、≈140 ms（上报周期）量级对照；异常尖峰/抖动记缺陷 |
| T-L8-03 | 分压与从机静态电流 | 同上 | 非采样期确认 PB05 低、I²C 引脚不主动拉低、GXHT40 待机 | 电流 + 波形 | 非采样期无分压电流、无 I²C 主动驱动 |
| T-L8-04 | 调试 UART 关闭 | 电流 + 波形（PA05） | 非采样期 PA05 无输出、无持续电流 | 波形/电流 | 非采样期 UART 关闭（`DebugUART_Close` 生效） |
| T-L8-05 | CR2032 实机寿命（可选、长周期） | 装 CR2032 的完整产品 | 典型场景连续运行记录电池电压/运行天数 | 电压–时间记录 | 只记录趋势；**不得用短测外推宣称寿命达标**（需求方指标未给） |

## 6. 前置条件、依赖与交接

1. **设备工具禁用（当前阻断）**：SWD/烧录器、逻辑分析仪、示波器、串口、电流表均不可用；`[实板]`/`[联测]`/`[功耗]` 用例在本环境不可执行，必须记 BLOCKED。恢复后应先做 T-L1-09/T-L1-12（部署一致性），再做 T-L2/T-L3/T-L4。
2. **观测钩子**：`SENSOR_TEST_TRACE` 已在 `sensor_config.h` 提供但**默认关闭**。打开可得到光照 code/dark、`temp_x10`、`hum_x10`、`report`、`prev_temp_x10`、重试计数；无钩子时用 PB05/电流/空中帧 + 故障注入替代，证据强度下降须如实标注。功耗用例必须用关闭态。
3. **光照阈值回填（FWR-OPEN-1）**：T-L3-03 的标定结果需回填 `sensor_config.h` 并置 `LIGHT_DARK_CALIBRATED=1`，**该修改属实现能力**；本能力只提供标定方法与数据。未完成前不得宣称「无光判定已验收」（T-L1-10/T-L3-07）。
4. **0.9 ℃ 含等于（FWR-OPEN-2 / IC-002 §7.2）**：本设计期望「严格大于 0.9 ℃」（T-L5-02），同时把「恰好 0.9 ℃ 的行为」作为实测记录项；若需求方改为「至少 0.9 ℃」，仅期望值改变，用例结构不变。
5. **是否保活上报（FWR-OPEN-3）**：本设计期望「无周期保活」（T-L5-08）。若产品追加该需求，属新需求，需重新设计用例。
6. **Android 同步修改（readme 修改点 6）**：空口与 BLE 布局不变，本计划预期 App 无需协议改动；T-L7-02/03/07 是发现「需要改 App」的证据入口，但修改属 Android 能力。
7. **串口参数**：传感器调试 UART 为 9600（`measure.h`），与常见默认 115200 不同；执行时须显式使用 9600。
8. **仪器与夹具清单**（执行前确认在位）：SWD 探针 + 烧录工具、8 通道以上逻辑分析仪、nA/µA 电流表或 SMU、可调光源/暗箱、可控温源与参考温湿度计、433 接收端或网关板、已装 App 真机。
