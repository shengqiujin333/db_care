# 嵌入式测试设计（TD-002 rev 3.0）

状态：嵌入式测试设计产物（embedded_tester.embedded_test_design）
版本：3.0（与固件方案 FD-002 **rev 3.0**、需求 FWR-002 rev 3.0、接口契约 IC-002 v3.0 及本次任务清单 T1–T7 对齐；替代 TD-002 rev 2.0）
对象：蹬被报警器**传感器固件（CW32L010Y8M6，本次主要改动）**、**网关固件（CH592 beiwov2，核对为无功能改动）**，以及**传感器 → 433 MHz → 网关 → BLE → Android** 的端到端嵌入式验证。
能力边界：本文件**只做测试设计**（范围、适用性、环境/仪器、数据采集、判定方法与标定方法），**不执行测试、不烧录、不修改被测固件源码**。执行由后续嵌入式测试执行能力按本计划选取适用项与回归项后承接。

> **本轮 rev 3.0 变更要点**（相对 rev 2.0）：
> 1. 上报方向由「降温」更正为**升温** `int32(cur)-int32(prev) > 9`；恰好 35.0 ℃ **不再被整体排除**，仍可经升温分支触发；判定新增 `light_valid` 入参（IC-002 v3.0 §2 / FD-002 §6.4）。
> 2. 光照判据由 350/250 滞回改为**全暗基准 1/3**：`dark = valid AND 3*mean >= C_dark`（uint32 乘法、边界相等为暗、**每笔独立、无滞回、无历史暗态**）；ADC **全部超时 → valid=false**，**不得**用满量程合成暗态（IC-002 §3 / FD-002 §6.3）。
> 3. 新增**全暗基准 `C_dark` 实板标定**（完全遮光、同供电/参考/建立时间/平均策略）与 `LIGHT_DARK_CALIBRATED` 未标定门禁；未标定时升温分支关闭、超温分支独立可用（FWR-110/FWR-113）。
> 4. 新增**待上报冻结样本**：触发时冻结当次温度/湿度/ID，重试期间帧内容逐字节不变、不被新采样改写；仅发送成功清除，用尽放弃本轮（FWR-114 / FD-002 §11.8）。
> 5. 明确「每次成功温湿度采样（含未上报或光照无效）都推进前一有效温度；整周期失败不推进、不冻结、不构造 0 值」（FD-002 §4/§5、FWR-109）。
> 6. 环境声明按本轮真实的**工具边界**重写，并记录已实际执行的只读枚举结果。

## 2. 测试范围与适用性

### 2.1 覆盖的产品行为

| 编号 | 行为（来源） |
|---|---|
| B1 | **GXHT40 温湿度采集**：地址探测（0x44/0x45）、`0xFD` 高重复率测量、按 tMEAS 上限等待、6 字节读取（温度在前）、温度字/湿度字分别 CRC-8（poly 0x31、init 0xFF）、x10 整数换算与有效域（−400..1250 / 0..1000）、读 NACK 与 CRC 错按上限有界重试、失败不修改输出（readme 1；FD-002 §2.2/§6.1/§6.2/§10） |
| B2 | **光照采集**：PB05 输出供电 → 稳定等待 → PB04/AIN11 多次转换 → 取**成功样本**算术平均 → 随后 PB05 置低；结果显式表达 `{valid, mean_adc_code, samples_ok, dark}`（readme 2；FD-002 §2.3/§6.3） |
| B3 | **全暗 1/3 无光判据**：`dark = valid AND (uint32)3*mean >= C_dark`（整数乘法、边界相等为暗）；**每笔独立判断、不使用滞回或历史暗态**；`C_dark=1..4095` 均有定义（readme 2/7；IC-002 §3；FD-002 §6.3） |
| B4 | **全暗基准标定与未标定门禁**：`C_dark` 必须来自完全遮光、相同供电/ADC 参考/建立时间/平均策略的有效实测；标定记录含板件、供电、遮光条件、原始样本分布、配置版本；未标定（`LIGHT_DARK_CALIBRATED=0`）时 `light_valid=false`，升温分支不触发，不得宣称无光已验收（FWR-110；FD-002 §6.3/§12） |
| B5 | **3 分钟节拍与采样顺序**：RTC 保持 1 分钟中断、累计 3 次才置一次采样请求；上电后另有一次启动采样机会；单周期只测量一次；**先采光照再测温湿度**（readme 3；FD-002 §4/§5、FWR-103） |
| B6 | **条件上报判定**：`rising = have_prev AND int32(cur)-int32(prev) > 9 AND light_valid AND dark`；`superheat = int32(cur) > 350`；`report = rising OR superheat`；恰好 +0.9 ℃、恰好 35.0 ℃（不同时满足升温分支）、无前值未超温、有光且未超温、降温均不触发；恰好 35.0 ℃ 若同时满足升温分支（如 34.0→35.0 且无光）**触发**；光照无效只关闭升温分支，超温分支**独立触发**（readme 4；IC-002 §2；FD-002 §6.4） |

| B8 失败路径 | `[实板]` 故障注入（断开器件/短接总线/CRC 注入）后观测有界结束、无空中帧、无 0 值、前值不推进 |
| B9 旧通路退役 | `[实板]` 烧录后实测无 PB04 非模拟配置、无霍尔唤醒、无 Flash 写电流，且 PB05/PB06 无越权驱动 |
| B10 空口/BLE 兼容 | `[联测]` 网关解出字段、BLE 记录顺序、Android 读数三方一致；网关不二次门控 |
| B11 低功耗 | `[功耗]` 实机电流波形（深睡/单周期/发射） |
| B12 中断边界 | `[实板]` 发射期间 RTC 节拍不丢、ADC 无中断争用；静态 + ELF 证据 |

## 3. 测试层次、可用测试资产与总体策略

### 3.1 层次

| 层 | 名称 | 环境 | 目的 |
|---|---|---|---|
| L0 | 宿主机纯逻辑/流程 | 本机 gcc（真实 `.c` + 仿真 MCU 影子头/mock 总线） | 判定/换算/CRC/光照判据/冻结门控的确定性与边界，回归最快 |
| L0i | 宿主机空口互操作 | 本机 gcc（真实传感器 encoder + 真实网关 decoder） | 不依赖硬件的字段顺序/字节序/加密回归 |
| L1 | 构建、静态与部署一致性 | 本机 + MDK/IAR 工程 + SWD 编译下载回读 | 可构建、资源达标、退役符号消失、无浮点、部署镜像与受测提交一致、未标定标志正确 |

| L3 | 单板光照与标定 | 传感器板 + 逻辑分析仪/示波器 + 可控光源/暗箱 | PB05/PB04 时序、极性、1/3 判据、`C_dark` 标定、ADC 故障有效性 |

| L5 | 条件上报系统联测 | 传感器 + 网关 + Android + 433 通路 + 可控温度 | 判定矩阵、边界、冻结样本、端到端数据正确 |

### 4.4 传感器 I²C 与 GXHT40 驱动 `[实板]`（用例组 T-L2）

| 编号 | 行为 | 前置/资源 | 方法 | 证据 | 判定 |
|---|---|---|---|---|---|
| T-L2-01 | 总线物理与地址探测 | 传感器板上电（3.0 V 台架或 CR2032）、逻辑分析仪接 PA03/PA04、4.7 kΩ 上拉到 BAT | 抓一个采样周期完整 I²C 事务：START→地址写（`0x88` 或 `0x8A`）→`0xFD`→STOP→（等待）→START→读地址（`0x89`/`0x8B`）→6 B→NACK→STOP | 原始波形 + 解码文本 + 时间戳 | 地址字节与实装变体一致（0x44→0x88/0x89，0x45→0x8A/0x8B）；空闲被外部上拉为高；每字节 ACK 存在 |
| T-L2-02 | tMEAS 等待下界 | 同上 | 量测 `0xFD` STOP 沿到读地址首个 SCL 上升沿的时间 | 波形时间差 | ≥ 8.3 ms（高重复率 max）；按 FD-002 §11.3 取 10 ms 更佳；读 NACK 后重读间隔 ≥1 ms 且总重试 ≤ `GXHT40_READ_RETRY` |
| T-L2-03 | 连续读时序正确 | 同上 | 复核 6 字节读取：前 5 字节主机 ACK、第 6 字节 NACK，随后 STOP；顺序 `T_MSB,T_LSB,T_CRC,RH_MSB,RH_LSB,RH_CRC` | 波形 + 解码字节 | 与手册 §7.2 一致（温度在前）；不依赖 clock stretching |
| T-L2-04 | 测量值与参考一致 | 可控温箱/冰水浴 + 参考温湿度计 | 至少 3 个温度点（≈5/25/40 ℃）与 2 个湿度点稳定后，比对**经空口或钩子读出**的值与参考值 | 参考仪器读数 + 传感器记录（含时间） | 偏差在参考仪器与 GXHT40 手册精度合计范围内；超范围登记为缺陷，不得自行放宽 |
| T-L2-05 | 负温符号 | 冰箱/冷箱 ≈ −10 ℃ | 冷透后触发一次上报（超温或升温分支），在网关/Android 侧读温度 | 端到端三方证据 | 读数为负且大小正确；BLE `s16be@6` 不出现 6 万级大数 |
| T-L2-06 | CRC 错误路径 | 逻辑分析仪 + 故障注入（拉低/断开 SDA/SCL 使回读异常，或 I²C 从机模拟器） | 连续若干周期注入错误，观察是否重发 `0xFD` 重测、重试是否有界、周期后是否恢复 | 波形 + 电流 + 行为 | 每次 CRC 错丢弃整帧并重测；重试 ≤ `GXHT40_MEAS_RETRY`；用尽后本周期结束不挂死 |
| T-L2-07 | 总线被拉低卡死恢复 | SDA 短接 GND 一段时间后释放 | 释放后观察下一周期是否恢复通信；观察电流是否受限 | 波形 + 电流 | `sf_i2c` ACK 超时路径发 STOP 返回失败；后续周期可恢复；无无限等待（无持续 mA 级电流） |
| T-L2-08 | 无器件/未焊接 | 取下 GXHT40 | 观察一个完整采样周期行为 | 波形 + 空中（应无发射）+ 电流 | 失败路径：不上报、不推进前值、不冻结、不构造 0 值；周期有界结束并回深睡 |
| T-L2-09 | 地址变体覆盖 | 分别装 0x44 与 0x45 变体（或从机模拟器） | 对两种地址各跑一次采样周期 | 波形 + 读数 | 两种地址均可被探测并读数；探测结果被缓存，不每周期重复扫描 |

### 4.5 光照通路、1/3 判据与全暗标定 `[实板/标定]`（用例组 T-L3）

| 编号 | 行为 | 前置/资源 | 方法 | 证据 | 判定 |
|---|---|---|---|---|---|
| T-L3-01 | PB05 供电与空闲低 | 逻辑分析仪/示波器接 PB05；可调光照 | 观察一个采样周期 PB05 高→低；非采样期（含深睡）用长时基确认保持低 | 波形 + 时间标注 | 采样后 PB05=低；非采样期无高电平；高电平窗口与被测分压电流一致 |
| T-L3-02 | 极性正确（无光=读数高） | 暗箱（遮光）与强光两种受控条件 | 全遮光与强光下分别读 `mean`（钩子）或经「构造升温后是否上报」间接观测；核对 `dark` 方向 | 钩子输出或空中帧有无 + 场景照片/照度记录 | 全遮光 → mean 高且 `dark=true`；强光 → mean 低且 `dark=false`；若反向即为致命缺陷 |
| T-L3-03 | **全暗基准 `C_dark` 实板标定** | 传感器板 + 完全遮光夹具 + 稳定供电 + 钩子（读原始码） | 按 FD-002 §6.3：PB05 恒高（固件/夹具保持），器件**完全遮光**，供电为实际电池/等效电源，等待时间与量产一致（≥100 ms），采样次数与量产一致（8 次）；记录**每次原始码样本分布（min/max/均值/中位）**、板件标识、供电电压、遮光方式、固件配置版本；取均值（或稳健中位）为 `C_dark`；阈值 = `ceil(C_dark/3)`；随后在**当前有光**环境测均值，确认明显低于阈值 | 30+ 次原始读数 + 分布统计 + 计算过程 + 环境条件 + 配置版本 | `C_dark` 来自完全遮光实测（1..4095）；**不得**使用满量程 4095、旧默认 350/250 或当前亮态读数冒充；有光均值必须明显低于 `ceil(C_dark/3)`，否则登记为器件/分压问题 |
| T-L3-04 | **每笔独立、无滞回** | 可调光源/渐变遮光 + 钩子；`C_dark` 已知 | ① 用同一 `mean` 码值（分别在「上一笔为明」与「上一笔为暗」之后）触发采样，比较 `dark` 结果；② 在阈值上下缓变扫描，确认输出仅由**本笔** `3*mean>=C_dark` 决定，无方向相关的进入/退出差 | 钩子输出序列 + 扫描记录 | 同码同结论；扫描中不存在 350/250 式滞回带；无状态残留 |

| T-L3-06 | 稳定等待充分 | 逻辑分析仪接 PB05 与 PB04 | 量测 PB05 上升沿到首次 ADC 采样时间；对比遮光/强光多次采样均值稳定性；记录 `samples_ok` | 波形时间 + 重复离散度 | 等待 ≥ 设计值（`LIGHT_SETTLE_MS`，约 100 ms，覆盖 5 MΩ 源阻抗与光敏响应）；均值重复性在可见噪声带内 |
| T-L3-07 | **ADC 全部超时 → 无效（不合成暗态）** | 故障注入（使 ADC 转换始终不完成）或从机/仿真 harness | ① 全部转换超时：核对 `valid=false`、`dark=false`、**不得**出现满量程 4095 合成暗态；核对升温分支关闭而 `cur>35.0 ℃` 仍上报；② 部分成功：核对均值仅取成功样本且 `samples_ok` 等于实际成功数；③ 真实满量程读数（器件开路）仍按同一判据参与判定并记录为诊断线索 | 钩子输出 + 空中帧 + harness stdout | 全失败无效且不合成暗态；部分成功均值与成功数正确；超温分支不受光照无效影响 |
| T-L3-08 | **未标定门禁与回填闭环** | 标定数据 + `sensor_config.h` | ① 未标定阶段（`LIGHT_DARK_CALIBRATED=0`）：确认 `valid=false`、升温分支不触发、报告明确写「无光判定未验收」；② 完成标定后：核对回填 `LIGHT_DARK_REF_CODE`、置 1，并重跑 T-L3-02/04/05 与 T-L5 相关判定 | 配置快照 + 标定记录 + 复跑证据 | 未标定不得宣称无光判定通过；回填必须由实现能力完成修改，本能力只提供方法与数据（交接见 §6） |

### 4.7 条件上报判定（空口边界矩阵）`[联测]`（用例组 T-L5，核心）

方法：用可控温度激励（恒温箱/热风/冰袋对传感器头部）建立「前一有效温度」，再改变温度与光照条件构造下述情形；每次只变一个变量，观测 433 空中是否出现新帧（433 接收机或网关日志），并记录解出的 `temp/hum/id`。内侧判定可用钩子报告的 `report` 值替代，但**至少一次必须以真实空中帧验证**。期望方向为**升温**。

| 编号 | 场景 | 期望（IC-002 §2 / FWR-104） | 判定要点 |
|---|---|---|---|
| T-L5-01 | 升温 +1.0 ℃（30.0→31.0）且 DARK | 上报 | 帧内容=**触发样本**的温湿度；之后无新变化不再重复 |
| T-L5-02 | 升温**恰好 +0.9 ℃**（30.0→30.9）且 DARK | **不上报**（严格 >） | 记录为「0.9 含等于」实测项（§6.4）；不得据此判缺陷 |
| T-L5-03 | 升温 +0.8 ℃（30.0→30.8）且 DARK | 不上报 | 低于阈值不触发 |
| T-L5-04 | 升温 +1.0 ℃ 但 LIT | 不上报 | 无光是升温分支的必要条件 |
| T-L5-05 | 升温 +1.0 ℃ 但光照**无效**（未标定或 ADC 全失败） | 不上报（升温分支关闭） | 光照无效只关升温分支 |
| T-L5-06 | 降温 −1.0 ℃（30.0→29.0）且 DARK | 不上报 | 方向为升温，降温恒不触发 |
| T-L5-07 | 34.0→**35.0** 且 DARK | **上报**（升温分支） | 恰好 35.0 不被整体排除 |
| T-L5-08 | 34.0→**35.0** 且 LIT | 不上报 | 超温分支在 35.0 不成立，升温分支因有光关闭 |
| T-L5-09 | 无前值、35.1 ℃、明或无效 | 上报 | 超温分支独立于光照与前值 |
| T-L5-10 | 无前值、**35.0 ℃**、DARK | 不上报 | 首笔 + 恰好 35.0，两分支均不成立（FWR-108） |
| T-L5-11 | 无前值、20.0 ℃ | 不上报（不强制上报首样本） | 复位后首个周期无帧 |
| T-L5-12 | 有前值、`cur=35.1 ℃`、LIT 或光照无效 | 上报 | 超温分支独立成立 |
| T-L5-13 | 前值存在、稳态无变化 | 不上报（无周期保活） | 连续 ≥3 周期无帧；证明 3 分钟是采样周期而非上报周期 |
| T-L5-14 | 上报成功后同条件持续 | 不重复上报 | 上报即清除待上报状态 |
| T-L5-15 | 升温满足但上一周期温湿度失败 | 以**失败前**的前值判定 | 与 T-L6-01 联合执行，验证失败周期不推进前值 |

所有内部判定用例（钩子报告 `report`）必须与至少一次真实空中帧结论一致；不一致时以空中帧为准并登记缺陷。

### 4.8 失败路径、冻结样本与有界性 `[实板/联测]`（用例组 T-L6）

| 编号 | 行为 | 前置/资源 | 方法 | 证据 | 判定 |
|---|---|---|---|---|---|
| T-L6-01 | 失败不推进前值 | 钩子（优先）或行为反推 | ①建立前值 30.0 ℃；②注入一个周期温湿度故障（失败、不上报）；③恢复并把温度**升到 31.0 ℃** 且 DARK，观察是否上报 | 波形 + 空中帧/钩子 | 恢复后必须上报（说明前值仍是故障前 30.0 ℃）；若实现用了失败周期的值，本项失败 |
| T-L6-02 | 失败周期不发 0 值帧 | 同上 | 检查故障周期空中无帧、网关无 `temp=0` 记录 | 433 接收记录 + 网关日志 | 无帧、无 0 值记录 |
| T-L6-03 | 433 发送失败有界重试 | 屏蔽 433（移开/衰减/取下接收端） | 使上报条件成立，观测发射尝试次数与时长 | 电流曲线 + PB02/PB03 波形 + 另一接收机 | 尝试 ≤ `SENSOR_RF_TX_RETRY`；单次超时 ≤200 ms；用尽后本轮放弃回深睡；**无持续发射或死循环**；下一周期正常重试 |
| T-L6-04 | 失败不阻塞下一拍 | 同上 | 移除屏蔽，等待下一周期 | 波形 | 节拍不漂移、能重新上报 |
| T-L6-05 | 光照与温湿度同时失效 | 断开光敏 + 取下 GXHT40 | 观察若干周期 | 电流 + 空中 | 不产生上报；有界结束；深睡电流正常 |
| T-L6-06 | I²C 读 NACK（转换未完成）路径 | 从机模拟器延迟应答 | 在读到 NACK 时观察重读行为 | 波形 + 钩子重试计数 | 等待 1 ms 后重读，总重试 ≤ `GXHT40_READ_RETRY`；用尽归入整周期失败路径 |
| T-L6-07 | **冻结样本在真实链路中不被改写** | 传感器 + 433 接收机 + 可控温度 | 构造触发上报后使发送持续失败以产生多次重试；在重试期间改变传感器温度/光照并让新采样发生；抓取每次空中帧逐字节比对，与触发时刻样本比对 | 多次空中帧十六进制 + 触发时刻参考读数/钩子 | 所有重试帧**逐字节一致**且等于触发时刻冻结样本；不得出现「触发样本被新采样替换」；仅成功后清除，用尽放弃 |

### 4.9 端到端链路（433 → 网关 → BLE → Android）`[联测]`（用例组 T-L7）

| 编号 | 行为 | 前置/资源 | 方法 | 证据 | 判定 |
|---|---|---|---|---|---|
| T-L7-01 | 10 B 帧解出正确字段 | 网关板 + 网关日志/nRF Connect + Android | 触发一次上报，抓网关接收与解密结果，核对 `uid/temp/hum` 与本次实际值 | 传感器侧（钩子/参考仪器）+ 网关日志 + 手机读数（同一时刻） | 三处一致；`hum` 与 `temp` 不交换 |
| T-L7-02 | BLE 记录顺序与 Android 解析 | 同上 + 已装 App 真机 | 读 FFE0/FFE2，核对每设备 8 B = `id|hum_BE|temp_BE`；App 显示与之一致 | BLE 原始十六进制 + App 截图/日志 | 与 `parsePlainFrame`（`u16be@4`/`s16be@6`）一致；无温湿度互换 |
| T-L7-03 | ID 归因 | 多设备同场（若可用）或单设备重复上电 | 核对空口 4 B ID = 网关记录前 4 B = App 归因 ID；反复上电 ID 稳定 | 多方十六进制对照 | 4 字节 ID 完全一致且稳定；App 不以列表顺序代替 ID |

| T-L7-05 | 网关回归不变 | 同上 | 对照改动前后网关 BLE 特征长度、组块行为、服务/特征 UUID | 抓包/日志比对 | 未改变（本设计预期网关无功能改动）；若不一致，按接口契约对齐属网关实现能力的交接 |
| T-L7-06 | 负温端到端 | 见 T-L2-05 | 与 T-L7-01/02 联合执行 | 同上 | 手机端显示负温正确 |
| T-L7-07 | 无上报时 App 不合成数据 | 稳态无触发条件连续 ≥3 周期 | 观察 App/云端是否出现伪造样本或 0 值 | 网关日志 + App 记录 | App 不把「未收到」当 0，不按每 3 分钟合成（IC-002 §5） |
| T-L7-08 | 光照/原因不上链路 | 抓取全链字节 | 检查 433 明文 10 B 与 BLE 设备块前 8 B 均无光照状态/有效性/原因字段；网关未新增字段 | 原始字节 dump | 与 §4.2 结论一致；无新增字段 |

## 6. 前置条件、依赖与交接

1. **设备与仪器（当前阻断）**：本轮只读枚举显示无串口、无调试探针、无逻辑分析仪/示波器/电流表；`[实板]`/`[联测]`/`[功耗]`/`[标定]` 用例在本环境不可执行，必须记 BLOCKED。恢复后应先做 T-L1-09/T-L1-12（部署一致性），再做 T-L2/T-L3/T-L4。
2. **观测钩子**：`SENSOR_TEST_TRACE` 已在 `sensor_config.h` 提供但**默认关闭**。打开可得到光照 `{valid,mean,samples_ok,dark}`、`temp_x10`、`hum_x10`、`report`、`prev_temp_x10`、冻结快照、重试计数；无钩子时用 PB05/电流/空中帧 + 故障注入替代，证据强度下降须如实标注。功耗用例必须用关闭态。
3. **D-01（固件实现交接）**：`fw_core.c` 的 `sensor_decide_report` 需改为**升温方向** `int32(cur)-int32(prev) > SENSOR_REPORT_RISE_X10`、**移除 `cur==350` 整体排除**、增加 `light_valid` 入参；`SENSOR_REPORT_DROP_X10` 更名 `SENSOR_REPORT_RISE_X10`。未修正前 T-L0-05/T-L5-* 按本计划期望会失败。
4. **D-02（固件实现 + 标定交接）**：`light.c` 需返回 `{valid,mean,samples_ok,dark}` 并**删除满量程回退**、删除滞回状态；`fw_core.c` 提供 `light_is_dark(mean,valid,c_dark)`；`sensor_config.h` 以 `LIGHT_DARK_REF_CODE` + `LIGHT_DARK_CALIBRATED` 取代 `LIGHT_DARK_ENTER/EXIT/HYSTERESIS_STEP`。**`C_dark` 完全遮光实板标定属 T2 增量交付内容**：本能力只提供标定方法、记录规范与数据（T-L3-03），**回填配置头与置 `LIGHT_DARK_CALIBRATED=1` 属实现能力**。未完成前不得宣称「无光判定已验收」（T-L1-10/T-L3-08）。
5. **D-03（固件实现交接）**：`measure.c` 发送路径需读取**触发时刻冻结快照**（当前读取 `s_prev_temp_x10/s_last_hum_x10`）；未修正前 T-L0-08/T-L6-07 会失败。
6. **测试 harness 期望重写（交接）**：§3.2 中标注「必须重写/需扩展」的 harness 仍编码 rev 2.0 期望；这些文件的修改属**实现/验证执行能力**，本能力只做设计。执行时若 harness 期望未更新，其 pass 不得作为 rev 3.0 结论。
7. **0.9 ℃ 含等于（FWR-OPEN-2）**：IC-002 v3.0 已冻结为「严格大于 0.9 ℃」（T-L5-02），本设计按此期望；同时把「恰好 0.9 ℃ 的行为」作为实测记录项。若需求方改为「至少 0.9 ℃」，仅期望值改变，用例结构不变。
8. **无周期保活（FWR-OPEN-3）**：本设计期望「无周期保活」（T-L5-13）。若产品追加该需求，属新需求，需重新设计用例。
9. **Android 同步修改（readme 修改点 6）**：空口与 BLE 布局不变，本计划预期 App 无需协议改动；T-L7-02/03/07 是发现「需要改 App」的证据入口，但修改属 Android 能力（IC-002 D-03 的多设备归因风险亦属 Android）。
10. **串口参数**：传感器调试 UART 为 **9600**（`measure.h`），与常见默认 115200 不同；执行时须显式使用 9600。
11. **仪器与夹具清单**（执行前确认在位）：SWD 探针 + 编译下载工具、8 通道以上逻辑分析仪、nA/µA 电流表或 SMU、可调光源/暗箱、可控温源与参考温湿度计、433 接收端或网关板、已装 App 真机。
