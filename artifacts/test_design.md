# 嵌入式测试设计（TD-002 rev 4.0）

状态：嵌入式测试设计产物（embedded_tester.embedded_test_design）
版本：4.0（替代 rev 3.0；与固件方案 FD-002 **rev 4.0**、需求 FWR-002 rev 4.0、运行时架构 RTA-002 rev 4.0、接口契约 IC-002 v3.0 对齐）
对象：蹬被报警器**传感器固件（CW32L010Y8M6，本次主要改动）**、**网关固件（CH592 beiwov2，只读核对，不改）**，以及**传感器 → 433 MHz → 网关 → BLE → Android** 的端到端嵌入式验证。
能力边界：本文件**只做测试设计**（范围、适用性、前置/资源、方法、数据采集、判定与标定方法），**不执行测试、不烧录、不修改被测固件源码**。执行由后续嵌入式验证能力按本计划选取适用项与回归项后承接。
基线：Git `b38c0afbd36871c708651e5012ba77f66b103e0b`（接手时工作区干净）。本轮受测对象是**当前提交编出的镜像**，不是 run6 的旧镜像或旧结论。

> **本轮 rev 4.0 变更要点**（相对 rev 3.0）：
> 1. 新增 **UART1 调试通道**行为与用例组：启动横幅（固件标识/UID/复位来源/串口参数）、每采样周期一行 ≤96 B 整数轨迹、打印在判定与发送之后、等 `TC` 再关闭、唤醒后重新初始化、关闭串口只碰 UART1 与 PA05/PA06、打印不改变采样/判定/发送结果、`main.c` 的 Flash 读保护两行保持注释。
> 2. **观测方法按本轮真实资源重定范围**：已确认在线/提供的资源为传感器 + COM42 串口、CW-DAPLink 下载调试、已供电网关、已连接手机、Keil MDK；逻辑分析仪、示波器、电流表/SMU、暗箱/可控光源、参考温湿度计、可控温源、433 专用接收机**未确认提供**，因此从 rev 3.0 的「强制前置」降为本计划的**可选扩展诊断**（说明价值、适用条件与未执行状态），**不再作为任务通过的必要条件**。
> 3. 新增「观测方法能证明什么 / 不能证明什么」一节，禁止把单一手段的结论外推（尤其：串口轨迹证明软件可见状态，不证明 I²C 位级电气、空口波形、电流与绝对温湿度精度）。
> 4. UART 轨迹被设计为**主要观测手段**，并给出可判定的字段解析与自洽校验规则（含 report 由 prev/have/light/t 重算、dark 由 mean 与 `C_dark` 重算、send/retry 与 report 的跨行一致性、tick 与节拍一致性）。
> 5. 明确**精确边界只能在宿主机验证**：恰好 +0.9 ℃（差=9）、恰好 35.0 ℃、温度原始字/湿度原始字全量域、`C_dark=1..4095` 全量域等；真实目标只验证方向性、门控与端到端一致。避免把无法在实板上精确构造的边界写成实板强制项。
> 6. **全暗基准 `C_dark` 标定**改由「完全遮光 + UART 轨迹原始样本分布」完成（不再要求暗箱/可控光源）；未取得完全遮光基准时如实记录未标定，不得用满量程、旧默认 350/250 或亮态读数冒充。
> 7. 登记当前基线 `b38c0af` 的 as-built 偏差（D-01/D-02/D-03 同 rev 3.0，新增 D-04 无调试串口输出）与需要实现能力落地的交接；本计划**不下调期望**，也不修复实现。
> 8. 登记上游措辞不一致：FD-002 rev 4.0 §3.1 把 `debug_trace.{h,c}` 列入「新增（已完成，保持）」，而当前源码不存在该模块（§3.2/D-04 及功能增量正文与交接均要求新增）。以正文与任务要求为准：本计划按「待实现」对待。

- readme 修改点 1（GXHT40）、2+7（光敏分压与全暗 1/3）、3（3 分钟）、4（升温条件上报）、**8（UART1 调试串口初始化与打印）**，以及「不改硬件、空口/BLE 布局不变、不改网关代码、不改 iOS」均有可独立观测的预期行为，**可设计测试**。

- **as-built 偏差（必须如实记录，不修复）**：当前工作树（`b38c0af`）仍是旧语义——`fw_core.c` 用 `prev-cur>9` 且对 `cur==350` 直接排除、无 `light_valid` 入参；`light.c` 用 350/250 滞回且 ADC 全超时回退满量程 4095、`light_sample()` 返回 `bool`；`measure.c` 发送读取 `s_prev_temp_x10/s_last_hum_x10`（非触发时刻冻结快照）；无 `debug_trace` 模块、采样路径不初始化/不打印 UART1、`DebugUART_Close()` 仍 `SYSCTRL_AHBPeriphReset(GPIOA)` 并关 GPIOA 时钟。期望一律以 FD-002 rev 4.0 / IC-002 v3.0 / 本轮需求为准；对当前镜像执行本计划时，相关用例会**合法地失败**，直到实现能力修正。这是必需的实现交接，**不得**因此下调期望或把旧行为判为通过。
- 面向旧语义的宿主机 harness 期望（滞回、降温方向、满量程回退、发送前值、无调试通道）**不能作为新语义证据**；执行前必须确认期望已按本计划重写（§3.2、§6）。

## 2. 测试范围与适用性

### 2.1 覆盖的产品行为

| 编号 | 行为（来源） |
|---|---|
| B1 | **GXHT40 温湿度采集**：地址探测（0x44/0x45）、`0xFD` 高重复率测量、按 tMEAS 上限等待、6 字节读取（温度在前）、温度字/湿度字分别 CRC-8（poly 0x31、init 0xFF）、x10 整数换算与有效域（−400..1250 / 0..1000）、读 NACK 与 CRC 错按上限有界重试、失败不修改输出（readme 1；FD-002 §2.2/§6.1/§6.2/§10） |
| B2 | **光照采集**：PB05 输出供电 → 稳定等待 → PB04/AIN11 多次转换 → 取**成功样本**算术平均 → 随后 PB05 置低；结果显式表达 `{valid, samples_ok, mean_adc_code, code_min, code_max, dark}`（readme 2；FD-002 §2.3/§6.3） |
| B3 | **全暗 1/3 无光判据**：`dark = valid AND (uint32)3*mean >= C_dark`（整数乘法、边界相等为暗）；**每笔独立、无滞回、无历史暗态**；`C_dark=1..4095` 均有定义（readme 2/7；IC-002 §3；FD-002 §6.3） |
| B4 | **全暗基准标定与未标定门禁**：`C_dark` 必须来自完全遮光、相同供电/ADC 参考/建立时间/平均策略的有效实测；记录板件、供电、遮光方式、原始样本分布、取样次数与配置版本；未标定（`LIGHT_DARK_CALIBRATED=0`）时 `valid=false`，升温分支不触发，不得宣称无光已验收（FWR-110；FD-002 §6.3/§12） |
| B5 | **3 分钟节拍与采样顺序**：RTC 1 分钟中断累计 3 次才置一次采样请求；上电后另有一次启动采样机会；单周期只测量一次；**先采光照再测温湿度**（readme 3；FD-002 §4/§5、FWR-103） |
| B6 | **条件上报判定**：`rising = have_prev AND int32(cur)-int32(prev) > 9 AND light_valid AND dark`；`superheat = int32(cur) > 350`；`report = rising OR superheat`；恰好 +0.9 ℃、恰好 35.0 ℃（不同时满足升温分支）、无前值未超温、有光且未超温、降温均不触发；恰好 35.0 ℃ 若同时满足升温分支（如 34.0→35.0 且无光）**触发**；光照无效只关闭升温分支，超温分支**独立触发**（readme 4；IC-002 §2；FD-002 §6.4） |
| B7 | **待上报冻结样本与有界发送**：仅存在待上报样本时才组装 10 B 帧并沿用既有 Feistel 加密与 433 有界超时发送；置待上报时**冻结当次温度/湿度/ID**，重试期间（含跨周期）帧内容与快照**逐字节一致**；失败按上限有界重试，用尽放弃本轮且不伪造成功，**仅发送成功才清除**（FWR-114；FD-002 §4/§8.1/§10/§11.8） |
| B8 | **失败不伪造**：I²C/CRC 整周期失败时不上报、不推进前一有效温度、不冻结待上报样本、不构造 0 值；每次**成功**温湿度采样（含未上报或光照无效）推进前一有效温度（FWR-107/FWR-109；FD-002 §10） |
| B9 | **旧通路退役与引脚所有权**：hall/OPTCFG/params/history 模块及其初始化、GPIOB 霍尔中断分支、LPTIM OPTCFG 分支、写 Flash 参数路径移除；PB04 仅 AIN11 模拟输入、PB05 仅光照供电输出、PB06 不外驱动；UART1/PA05/PA06 仅 `debug_trace` 拥有（FWR-111；FD-002 §3.3/§11.4/§11.15） |
| B10 | **空口/BLE 布局不变与网关兼容**：433 明文 10 B `uid(4)|temp_LE(2)|hum_LE(2)|crc16_LE(2)` + 既有 Feistel；BLE 每设备 8 B `id|hum_BE|temp_BE`；不新增光照/有效/原因/时间字段；网关不二次门控（FWR-105/FWR-112；IC-002 §4/§5；FD-002 §8/§9） |
| B11 | **低功耗行为**：非采样期 MCU 深睡、GXHT40 待机、PB05 低（分压无电流）、I²C 引脚不主动拉低、**调试 UART 关闭**、433 有界（FWR-106；RTA-002 §3.3） |
| B12 | **运行时/中断边界**：单线程超级循环，无 RTOS；RTC ISR 只计数置标志；ADC 走轮询不用中断；UART1 不用中断、轮询发送后等 TC；GPIOB 霍尔中断与 LPTIM OPTCFG 分支已移除（RTA-002 §1.1–§1.3；FD-002 §11） |
| B13 | **UART1 调试通道（readme 修改点 8，本轮新增）**：上电初始化 UART1（PA06/PA05、9600 8N1、PCLK 8 MHz、轮询）并打印启动横幅（固件标识、芯片 UID 前 4 字节、复位来源、串口参数）；每个采样周期在**判定与发送之后**打印一行 ≤96 B 的整数轨迹（RTC 累计节拍、前一有效温度 x10 与存在标志、光照 valid/成功样本数/最小/最大/均值码/无光判定、温度 x10、湿度 x10、上报判定、433 发送结果、待上报重试计数）；打印后等 `TC` 再关闭串口，唤醒后重新初始化；关闭只复位/关闭 UART1 与改写 PA05/PA06，**不得**复位 GPIOA、**不得**关闭 GPIOA 时钟、**不得**改动 PA03/PA04（软 I²C）与 PA07/PA08（SWD）；**打印不得改变采样/判定/发送结果与状态快照**；`main.c` 中被用户注释的 Flash 读保护两行**保持注释**（FWR-115；FD-002 §2.4/§6.5/§11.15–§11.18） |

### 4.1 L0 宿主机纯逻辑与流程

| 编号 | 行为 | 前置/资源 | 方法 | 证据 | 判定 |
|---|---|---|---|---|---|

### 4.4 L2 UART1 调试通道（真实目标，本轮主观测层）

**前置/资源**：受测镜像（T-L1-09/12 已确认）、CW-DAPLink、USB-TTL 接传感器 J3.1/J3.2/GND、COM42 @**9600** 8N1、捕获窗口内触发复位的能力（下载后自动复位/`openocd_reset`/重新上电，必须在捕获窗口内发生，否则横幅会丢失）、捕获时长上限 300 s（需分区窗口）。

### 4.6 L4 3 分钟节拍、顺序与单周期单次（真实目标）

**取舍说明**：`serial_capture` 单次时长上限 300 s 且**原始产物不含逐字节时间戳**，因此用**分区捕获窗口**：连续执行若干定长窗口（建议 10–30 s），记录每个窗口的 `started_at/finished_at` 与是否含 S 行；窗口宽度即时间分辨率。可用 `serial_exchange` 的读超时做同样分段。节拍的**内部**证据是 `tick` 增量，**外部**证据是窗口归属，两者必须一致。

| 编号 | 行为 | 前置/资源 | 方法 | 证据 | 判定 |
|---|---|---|---|---|---|
| T-L4-01 | **采样周期 ≈3 分钟** | COM42 分区窗口 | 复位后在捕获窗口内开始；连续执行覆盖 ≥2 个采样间隔的窗口序列；统计相邻两条 S 行落在的窗口（时间分辨率=窗口宽度） | 每窗口 `started_at/finished_at` + 是否含 S 行 + S 行原文 | 相邻采样之间隔 ≈180 s（落在相邻窗口的相邻采样点，误差不超过窗口宽度量级）；**同时** `tick` 增量必须为 3（或每行均为 3，取决于实现语义，先由实现确认）；记录实测间隔与离散度，**不自造容差**（RTC 用 LSI，readme 未给精度） |
| T-L4-02 | **单周期单次测量 + 顺序** | 同上 | 统计一个采样间隔内 S 行数量；核对同期光照字段与温湿度字段来自同一周期（同一行内成对出现） | S 行序列 | 一个周期恰好一条 S 行（失败重试不算重复周期）；同一行内含光照与温湿度结果，未被拆成两行 |
| T-L4-03 | **无 1 分钟节拍残留** | 同上 | 覆盖 ≥6 分钟的窗口序列确认不存在每 1 分钟一条的结构 | 窗口序列 | 无 1 分钟节拍残留（FWR-103） |
| T-L4-04 | **上电启动采样机会** | 复位控制 | 复位后立即观察是否在无需等待 3 分钟即出现首条 S 行；核对首笔 `have=0` | S 行 + 窗口时间 | 上电后有一次立即采样（首行 `have=0`），随后转入 3 分钟节拍；首笔仅在 `t>350` 时 `report=1`（FD-002 §5.3） |
| T-L4-05 | **发射期间节拍不丢** | 联测 | 让某周期触发上报（见 T-L5），观察该周期与下一周期的窗口归属与 `tick` | 窗口序列 + S 行 | 上报（≤200 ms 上限）不影响下一拍时间基准；`tick` 不丢 |

### 4.7 L5 条件上报判定与端到端（真实目标/联测，核心）

**激励手段（已确认可获得）**：温度用**局部加温**（握在手心/夹于腋下/放入被窝/暖水袋隔布加热；不得用明火或直接接触热源烫伤器件）产生 ≥1.0 ℃ 的升温；光照用**遮光手段**产生无光；**>35.0 ℃** 用可持续高于 35 ℃ 的加温方式（细节见 §6 前置条件）。
**边界说明**：恰好 +0.9 ℃（差=9）与恰好 35.0 ℃ 的精确边界**无法**在实板稳定构造，其判定以宿主机 T-L0-05 为准；实板验证方向性与门控。
**判定手段**：轨迹 `report/send`（主）+ **手机在同一时段收到该笔读数**（联动证据）。每步只改一个变量。

| 编号 | 场景 | 期望（IC-002 §2 / FWR-104） | 判定要点 |
|---|---|---|---|
| T-L5-01 | 有前值；遮光；本次比上次升温 ≥1.0 ℃ | 上报 | 该周期 `report=1` 且 `send=1`；手机收到该笔；`t` 与手机显示温度一致（同一笔） |
| T-L5-02 | 有前值；**有光**；同样升温 ≥1.0 ℃ | 不上报 | `report=0` 且该周期无发送记录；手机无新读数（记录观察窗口） |
| T-L5-03 | 有前值；**光照无效**（未标定阶段或 `valid=0`）；升温 ≥1.0 ℃ | 不上报（升温分支关闭） | `report=0`；`light.valid=0`；无发送 |
| T-L5-04 | 有前值；遮光；**降温** ≥1.0 ℃ | 不上报 | 方向为升温，降温恒不触发 |
| T-L5-05 | 有前值；遮光；升温但**未达 1.0 ℃**（如仅 +0.2..0.5 ℃） | 不上报 | 记录差值（以 x10 整数差为准）与实际 `report`；只要差值 ≤9 即不得上报 |
| T-L5-06 | 无前值（复位后首笔）；温度 ≤35.0 ℃ | 不上报 | 首笔 `have=0`、`report=0`；无发送 |
| T-L5-07 | **温度严格超过 35.0 ℃**；有光 | **上报** | 超温分支独立于光照与前值；`report=1` 且手机收到 |
| T-L5-08 | **温度严格超过 35.0 ℃**；遮光或光照无效 | 上报 | 与 T-L5-07 结论一致（光照不影响超温分支） |
| T-L5-09 | 上报成功后同条件持续（拒绝同一温湿度/无新升温） | 不重复上报 | 连续 ≥2 周期无新触发；证明「3 分钟是采样周期而非上报周期」且成功后清除 |
| T-L5-10 | 有前值；遮光；连续多个周期（≥3）无显著变化 | 不上报 | 无周期保活；无 0 值/合成样本 |
| T-L5-11 | 上报周期内的 433 发送 | 帧内容 = 触发样本 | 轨迹 `t/h` 与手机端读数一致（±同一笔，非相邻周期值）；`send=1` |
| T-L5-12 | 轨迹 `send/retry` 与触发自洽 | 无伪造 | `report=1` 的周期 `send∈{1,2}`；`report=0` 且无跨周期待上报时 `send=0`；若 `send=2` 出现，须与真实链路条件（如遮挡/距离）对应并记录 |
| T-L5-13 | 失败周期不推进前值（实板可见部分） | 失败周期无有效读数推进、无发送 | 与本组 T-L6 联测；轨迹显示该周期温湿度无效/无发送，下一周期仍以失败前的前值判定 |
| T-L5-14 | 有前值、遮光、升温 ≥1.0 ℃ 但**上一周期温湿度失败** | 以失败前的前值判定 | 与 T-L5-13 联合：恢复后给出的 `prev` 必须等于失败前的有效样本 |

## 5. 数据采集与证据规范

| 数据 | 采集方式 | 保存要求 |
|---|---|---|
| 宿主机测试输出 | harness/`build_test.sh` stdout | 原始文本 + 退出码 + 命令 + 工具版本 + 执行时间 |
| 交叉编译输出（如执行） | `gcc/build.sh` stdout、`arm-none-eabi-size`、`nm` | 原始文本；记录 commit 与工具链版本 |
| 构建/部署 | `mdk_build`/`mdk_flash` 原始日志 | 受测 commit、产物哈希、日志含 **Verify OK / Application running** |
| **UART1 轨迹** | `serial_capture`（COM42，9600）分段窗口，或 `serial_exchange` | **原始字节流文件** + 每个窗口的 `started_at/finished_at` + 原始 S 行/横幅原文（逐行字节数） |
| 判定一致性重算 | 由 S 行字段重算 `dark`/`report` 的表格 | 重算脚本或其等价记录 + 逐行比对结果 |
| 全暗标定 | 完全遮光下的原始 S 行集合 | 原始数据 + 分布统计（min/max/均值/中位）+ 计算过程 + 板件/供电/遮光方式/取样次数/配置版本 |
| 端到端 | 手机截图/日志 + 传感器轨迹 | 同一笔上报的时间对应关系必须注明；不保存凭印象的结论 |
| 可选仪器（如后续执行） | 逻辑分析仪/示波器/电流表原始采集文件 | 原始文件 + 导出 CSV + 关键截图（含时间基准）；明确标注为扩展诊断 |
| 判定 | 每用例：期望、实测、结论、证据路径 | 失败项需含最小复现步骤与现象时间点 |

证据要求：每结论必须能由保存的证据复现。**任何 mock/宿主机结论必须显式标注层级**，不得写成实板结论；**任何串口轨迹结论必须说明它证明的是软件可见状态**。下载/编译成功不得作为功能通过证据。

1. **执行前必须确认（本轮已确认项与待确认项）**

## 7. 风险与限制

| 风险 | 影响 | 缓解 |
|---|---|---|
| 启动横幅丢失（复位未落在捕获窗口内） | 无法证明「上电初始化并打印」 | 捕获先开、窗口内复位；若仍不可得，如实记证据缺口（不得用后续周期行替代横幅结论） |

| 旧 harness 期望未更新 | 用旧 pass 冒充新语义证据 | T-L0-10 要求先核对期望来源；T-L9-05 清零旧语义 |
| `C_dark` 未标定或遮光不彻底 | 升温分支不可用或阈值错误 | T-L3-05 完全遮光采集 + 分布记录；T-L3-07 未标定门禁；有光均值必须明显低于阈值，否则登记器件/分压问题 |
| 实板无法精确构造 0.9 ℃/35.0 ℃ 边界与 ADC 全超时 | 边界与异常路径无法在实板证明 | 明确归宿主机 T-L0-04/05 与光照 harness；实板只验证方向性与门控；必要时记证据缺口 |

| 目视/时间对应误差（轨迹与手机读数对应错笔） | 端到端比对结论错误 | 记录时间窗并只取同一时段唯一一笔；必要时用 `t/h` 与手机读数双重匹配 |
