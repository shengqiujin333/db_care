## 1. 产品与用户

### 1.1 产品定义

蹬被报警器由四部分组成：

1. **传感器**：CR2032 纽扣电池（焊装）供电，采集被窝温度、湿度与安装处光照；通过 433 MHz 无线把满足条件的读数发给中继器。
2. **中继器**：接收 433 MHz 数据，按传感器 ID 缓存并聚合，通过 BLE 提供给手机 App；App 同时保留既有 MQTT 订阅路径（发布端与上行实现不在本轮范围，保持不变）。
3. **Android App（爱守护）**：读取/接收读数，按设备归因，入库、告警、展示；守护中且已注册手机号时把读数上传云平台。
4. **云平台**：EMQX broker、注册/上传服务 `abr.py`、MySQL 数据库 `bwusernamebase`。

iOS App 本轮不修改；既有 433/BLE/平台载荷布局保持兼容。

### 1.2 用户与使用场景

| 角色 | 关注点 | 本轮必须可观察的行为 |
|---|---|---|
| 被照护者（睡眠中） | 蹬被后环境变化被发现 | 传感器按 3 分钟节拍采集；满足条件才上报，不依赖手机持续在线 |

| 安装/运维人员 | 能装、能配、能标定、能排障 | 有可执行的操作部署手册；UART1 调试口可观测；全暗标定有明确步骤与记录；服务器/证书/端口可核验 |
| 验证人员 | 能独立复现和判定 | 每条需求有可观察判据、原始证据要求与责任边界 |

## 2. 功能需求

优先级：**P0** = 本轮交付必须满足；**P1** = 必须满足但依赖现场/外部条件；**P2** = 兼容性约束。

### PR-001 GXHT40 温湿度采集（P0）

**需求**
- 传感器使用 GXHT40，I²C 7 位地址 `0x44` 或 `0x45`（运行期探测）。
- 周期测量使用高重复率命令 `0xFD`；读取 6 字节：`T_MSB,T_LSB,T_CRC,RH_MSB,RH_LSB,RH_CRC`，温度字与湿度字分别做 CRC-8（poly `0x31`，init `0xFF`，不反转，xorout `0`）。
- 温度输出 `int16`、单位 0.1℃、有符号；湿度输出 `uint16`、单位 0.1%RH。
- 有效域：温度 `-40.0..125.0℃`（`-400..1250`），湿度 `0..100.0%RH`（`0..1000`）。
- CRC 任一失败、字节数不足或温度超出有效域：整笔样本无效，不更新“上次有效温度/湿度”，不构造 0 值，不上报。
- 读 NACK、CRC 错、总线错误允许有界重试；重试上限必须有配置常量，不得无限等待。

**来源**：`readme.txt` 点 1；`gxht40.pdf`（地址/命令/CRC/换算/量程）；`sensor_hardware/` 网表与 BOM（U9=GXHT40）。

**可验收行为**
1. 真实目标上至少连续 3 个采样周期输出有效温湿度，数值落在有效域且在稳定环境中不跳变异常。
2. 人为制造 CRC 错/断线时，该周期无效、上一有效值保持不变、不产生 RF 发送。
3. 地址 `0x44` 与 `0x45` 两种器件均能被探测；不得只支持其中一种。
4. 采集失败后下一周期能重新探测并恢复（见 PR-013）。

### PR-002 光照采集与“无光”判定（P0）

**需求**
- 光敏分压电路：`PB05` 在采样时输出高电平供电，经 R3（5 MΩ）到 `PB04`（AIN11），光敏电阻到 GND；采样结束 `PB05` 回低。非采样期不得持续供电。
- 每次光照采样：供电后等待稳定（当前设计 100 ms），做多次 ADC 转换（当前设计最多 8 次成功值），取算术平均；部分成功可用成功样本均值，并记录成功数；全部失败则该次光照无效。
- 光照结果至少包含 `{valid, samples_ok, mean_adc_code, min, max, dark}`；不得用“满量程”或默认值合成暗态。
- 无光基准 `C_dark` = 在**完全遮光**、与量产相同的供电/稳定等待/取样次数下，同板实测的有效平均 ADC 码（1..4095）。
- 判据：`dark = valid && (3 × mean_adc_code >= C_dark)`；整数运算，边界相等算暗；每笔独立判断，不使用滞回或历史暗态。
- `valid = (samples_ok > 0) && C_dark 已标定`。未标定时 `valid=false, dark=false`，升温上报分支关闭。
- 不得用“当前有光环境的读数”“旧默认 350/250”“满量程”“推算值”冒充 `C_dark`。

**来源**：`readme.txt` 点 2、7；`sensor_hardware/pstxnet.dat`（PB04=LIGHT_ADC、PB05=LIGTHT_POWER、PB06=NC）；`MAIN_BOARD.BOM`；既有 `light.c` 仅作实现核对。

**可验收行为**
1. 完全遮光下记录 `C_dark` 与原始样本分布（min/max/mean）；标定记录含板件标识、供电、遮光方式、取样次数、配置版本。
2. 有光环境下 `mean_adc_code` 明显低于 `ceil(C_dark/3)`，判定 `dark=false`。
3. 完全遮光下 `mean_adc_code` 接近 `C_dark`，判定 `dark=true`；在 `mean = ceil(C_dark/3)` 边界判定为暗。
4. ADC 全部超时：`valid=false, dark=false`，无伪造码值。
5. 未标定配置下：`valid=false`，升温分支永不触发；产品不得宣称“无光判定已验收”。

### PR-003 3 分钟采样节拍（P0）

**需求**
- 采样周期为 3 分钟：RTC 1 分钟节拍累计 3 次触发一次完整采样（温湿度 + 光照）。
- 每个周期只测量一次；采样结果驱动的重试/发送不得额外触发测量。
- 上电允许立即执行一次采样机会（`sample_flag=1`），之后进入 3 分钟节拍。
- 采样周期不是上报周期；不得因“到 3 分钟”而无条件上报。
- 非采样期 MCU 深睡；RTC 维持节拍。

**来源**：`readme.txt` 点 3；既有 `main.c` RTC 节拍实现仅作核对。

**可验收行为**
1. 连续 ≥5 个周期的 UART1 `S` 行显示节拍按 3 个 1 分钟 tick 递增。
2. 相邻周期时间差中位数为 180 s（暂定允许 ±10%，LSI 精度未在资料中给出，见 OQ-03）。
3. 周期之间无额外温湿度/光照采样，无额外 RF 发送。

### PR-004 条件上报判据（P0，核心）

**规范判定式**（全部使用 0.1℃ 整数，`int32` 计算差值）：

```text
report = sample_valid
         AND (
              ( have_prev AND (int32)cur_temp_x10 - (int32)prev_temp_x10 > 9
                AND light.valid AND light.dark )
              OR ( (int32)cur_temp_x10 > 350 )
         )
```

其中 `sample_valid` 仅指**温湿度采样有效**（双 CRC 通过且温度在有效域），不含光照；光照有效性只通过 `light.valid && light.dark` 作用于升温分支，超温分支不受其限制。

**语义**
- “本次温度比上次温度大于 0.9℃”按字面解释为**升温方向**：`cur - prev > 0.9℃`。0.1℃ 量化下等价于升温 **≥ 1.0℃**；恰好 +0.9℃ 不触发。
- `prev` 是**上一次有效采集温度**，不是上一次上报温度。每次温湿度采样成功都推进 `prev`，无论是否上报、光照是否有效；采样失败不推进。
- 上电/复位后 `have_prev=false`：升温分支不成立；超温分支独立成立。
- 恰好 `35.0℃` 不满足“超过 35℃”；但**仍要评估升温分支**（例如 34.0→35.0 且无光应上报）。
- 光照无效（含未标定、ADC 失败）时升温分支关闭；超温分支不受光照和前值限制。
- 湿度随温度一起上报，**不参与**触发判定。
- 不设周期保活、心跳、首样本强制上报；不得补造零值。
- 发送成功仅指本地 433 发送完成，不等于网关/手机确认；链路无 ACK，不承诺端到端“恰好一次”。

**规范测试向量**

| # | prev (℃) | cur (℃) | 光照 | have_prev | 期望上报 | 说明 |
|---:|---:|---:|---|---|---|---|
| 1 | 30.0 | 30.8 | 有效暗 | 是 | 否 | Δ=0.8 |
| 2 | 30.0 | 30.9 | 有效暗 | 是 | 否 | Δ=0.9，不“大于” |
| 3 | 30.0 | 31.0 | 有效暗 | 是 | 是 | Δ=1.0 |
| 4 | 30.0 | 31.0 | 有效亮 | 是 | 否 | 需同时无光 |
| 5 | 30.0 | 31.0 | 无效 | 是 | 否 | 无效不能证明无光 |
| 6 | 31.0 | 30.0 | 有效暗 | 是 | 否 | 降温不是本轮条件 |
| 7 | 34.0 | 35.0 | 有效暗 | 是 | 是 | 恰好 35.0 仍可走升温分支 |
| 8 | 34.0 | 35.0 | 有效亮 | 是 | 否 | 升温分支要求无光 |
| 9 | — | 35.1 | 有效亮/无效 | 否 | 是 | 超温独立 |
| 10 | — | 35.0 | 有效暗 | 否 | 否 | 恰好 35.0 且无前值 |

**来源**：`readme.txt` 点 4；`readme.txt` 的 Git 历史（提交 `4220a78` 将“小于 0.9℃”改为“大于 0.9℃”，现行文本如此）；`artifacts/interface_contract.md` v3.0 §2 的同类冻结（仅作一致性核对）。

**可验收行为**
1. 上表 14 个向量在目标固件/宿主机纯逻辑中逐一得到期望结果。
2. 真实目标上：暗环境升温 ≥1.0℃ 触发一次上报；同条件有光不触发；降温不触发。
3. 重启后首个样本不因“无前值”而强制上报。
4. 恰好 35.0℃ 不被误判为超温；35.1℃ 独立上报。
5. 一次触发只产生一次发送（发送失败按有界重试处理，不重复计数为多次触发）。

### PR-005 433 MHz 空口兼容（P0）

**需求**
- 明文帧 10 字节：`sensor_id(4, 原字节) | temperature_x10(int16, 小端) | humidity_x10(uint16, 小端) | CRC16(小端)`。
- CRC16：CCITT-FALSE，poly `0x1021`，init `0xFFFF`，不反转，xorout `0`；覆盖前 8 字节。
- 继续使用既有 8 轮 Feistel 加密和既有配对密钥；不新增光照、原因、时间或版本字段。
- 单次发送超时 200 ms、最多 3 次尝试（有界）；失败不伪造成功。
- 待上报样本在重试期间保持温湿度与 ID 一致；未发送成功前，新触发不得把待上报样本悄然替换成另一笔（允许保持原样本直到成功或重试用尽）。
- 明文/密文布局不变，网关无需改动。

**来源**：`readme.txt` 点 6“不改硬件/网关”；`artifacts/interface_contract.md` §4；既有 `encrytogate.c`、网关 `feistel_al.c`。

**可验收行为**
1. 传感器真实发送 → 网关解密 → CRC 通过；字段与参考向量一致。
2. 篡改任一字节后网关 CRC 失败并丢弃，不更新缓存。
3. 帧长、字段偏移、字节序、符号与既有网关逐字节兼容。

### PR-006 中继器（网关）保持现状（P1，兼容约束）

### PR-007 Android 数据解码与归因（P0）

**需求**
- 支持 BLE 直读路径（FFE0/FFE2，AES/ECB/NoPadding，既有密钥）与既有 MQTT 路径。
- BLE 明文：头块 16 B = `gateway_id(6) | N(1) | pad(9)`；设备块 16 B，前 8 B = `id(4) | hum u16be@4 | temp s16be@6`；生产帧长 `16 × (1+N)`。
- 密文非 16 B 对齐、解密失败、帧不足、`N=0`、设备块不足：显式拒绝，不产生读数、不入库、不上传、不告警。
- 单位只除一次 10；负温保留符号；ID 原字节序、8 位大写十六进制无分隔。
- 未知 ID 不得错配为另一台已绑定设备。
- MQTT 载荷无 ID：必须在同一网关绑定上下文按发送侧设备顺序对应本地 ID 集合；数量不等、空序列、非法时间、非有限数值时拒绝整批。数量相同但顺序错误无法检测，需在手册/验收中记录该限制。
- App 不得从协议推断光照、上报原因或物理采样时刻；BLE/MQTT 接收时间只表示“App 收到时间”。
- App 不得合成缺失样本、不得把“未收到”当成 0、不得用固定 3 分钟节奏补点。

**来源**：`readme.txt` 点 6；`artifacts/interface_contract.md` §4/§5；既有 `GatewayFrameCodec.kt`、`MqtttService.kt`。

**可验收行为**
1. 参考向量：ID=`01 02 03 04`、T=`-5.0℃`、RH=`60.0%` → RF 前 8 B=`01 02 03 04 CE FF 58 02`；BLE 设备前 8 B=`01 02 03 04 02 58 FF CE`。
2. 非法帧（短帧、未对齐、N=0、解密失败）全部拒绝，数据库/上传/告警无新增。
3. 多设备 BLE 帧逐设备归因正确；MQTT 数量不一致时整批拒绝。
4. 负温、0℃、35.0/35.1℃、湿度 0/100% 边界解析正确。

### PR-008 Android 产品行为同步（P1）

**需求**
- BLE 轮询节拍与传感器 3 分钟采样对齐（当前为 180 s），保留手动“立即读取”。
- 不再以“30 分钟无数据”显示“离线”；改为“最近上报 X 分钟/小时/天前”与“按条件上报，可能长时间无上报”提示；连接状态仍由既有 broker 状态表达。
- 设备详情只读说明必须与 PR-004 一致：**采样周期 3 分钟；本次温度比上次高超过 0.9℃ 且无光，或温度超过 35.0℃，才上报；可能长时间无数据**。不得写成“下降超过 0.9℃”。
- 图表可查询范围放宽到 24 小时；`>35.0℃` 做高温强调，`=35.0℃` 不强调。
- 早起报告说明“按条件上报、条数非等间隔”；某设备当日无上报时显示“昨日无上报”，不得把零样本写成设备异常。
- App 不重算传感器门控、不显示光照状态/照度、不推断上报原因。
- **既有用户报警功能保持原语义**（与传感器上报条件是两件事）：
  - 温度/湿度下降报警：以时间戳时间窗 5/10/15 分钟取基准，温度和湿度都低于基准超过用户阈值；
  - 温湿度超限报警：严格超过用户设置上限/低于下限；
  - 紧急报警：温度 `>65.0℃`，文案“紧急报警，温度超过65度，谨防火灾”，不受 900 s 去抖限制；
  - 其他报警受 900 s 节流；文案与优先级保持既有行为。
- 守护中且已注册手机号才入库/上传；未守护不产生云数据。

### PR-010 UART1 调试串口（P0）

**需求**
- 传感器使用 UART1：`PA06=TXD`、`PA05=RXD`，9600 8N1；上电初始化并打印启动横幅（固件标识、UID 前 4 字节、复位来源、串口参数）。
- 上电诊断行：`VDD`（供电轨）、`IOTEST`（引脚拉低/回读/角色）、`IOSIG`（事务位签名）、`BUS`（空闲电平 + 有界地址扫描；无 ACK 显示 `none`）。
- 每个采样周期在判定与发送之后输出一行 `S` 轨迹，长度 ≤96 B，仅整数/大写十六进制；字段至少覆盖：节拍、前一有效温度与存在标志、光照 valid/成功数/极值/均值/无光、温度 x10、湿度 x10、采样有效、上报判定、发送结果、重试次数。
- 温湿度失败周期在 `S` 后输出 `G` 诊断行：结果码、0x44/0x45 是否 ACK、读重试次数、整帧重测次数、最近一次 6 字节（未成功占位）。
- 调试输出只观测，不改变采样/判定/发送；打印后等发送完成再关闭 UART，深睡期间无字节；不得复位 GPIOA、不得关闭 GPIOA 时钟、不得影响 PA03/PA04（软 I²C）与 PA07/PA08（SWD）。
- 生产/交付固件默认开启（readme 明确要求可调试），关闭开关不得改变业务结果。
- 当前项目调试串口为 `COM43`（9600 8N1），见 `runtime/environment.yaml`；不得使用旧记录的 COM42 作为本轮证据入口。

**来源**：`readme.txt` 点 8；`runtime/environment.yaml` 的 `sensor.debug_serial`；既有 `sensor_config.h`、`debug_trace.c/h`。

**可验收行为**
1. COM43 9600 8N1 捕获到完整 `BOOT → VDD → IOTEST → IOSIG → BUS` 上电行。
2. 每个周期恰一行 `S`，成功/失败周期字段与实际一致；失败周期恰一行 `G`。
3. 每行 ≤96 B；关闭 UART 时采样/判定/发送结果与开启时逐项一致。
4. 深睡期间串口无输出；唤醒后重新初始化可继续打印。

### PR-013 异常、恢复与不伪造（P0）

**需求**
- 采集失败：有界重试；失败周期不上报、不更新前一有效温度/湿度、不构造 0 值；调试行可见失败原因。
- 失败后下一周期必须重新探测 `0x44/0x45`，并先做有界总线恢复（如 9 个 SCL 脉冲 + STOP）；不得因缓存地址永久失联；恢复/重试均有上限。
- 光照全部转换失败：`valid=false`，不得合成暗态；`dark=false`。
- RF 发送失败：有界重试；用尽则放弃本轮，不伪造成功；下一周期按新判定自然重试。
- 待上报样本在重试期间保持温湿度/ID 一致（PR-005）。
- 任何异常不得导致 App 侧补点、归因错误或云端重复数据。

**来源**：`artifacts/interface_contract.md` §2/§3；`readme.txt` 点 4（“才上传”）；现有实现（`gxht40.c`、`sf_i2c.c`、`measure.c`）仅作核对。

**可验收行为**
1. 断线/CRC 错/读超时故障注入：失败周期不产生上报与假数据，诊断行与故障类型对应。
2. 恢复接线后下一周期重新探测并恢复有效采样。
3. 总线被拉低时执行有界恢复，SCL 脉冲数/STOP 可观测，不无限等待。
4. RF 失败重试次数有界，发送结果字段如实标记。
